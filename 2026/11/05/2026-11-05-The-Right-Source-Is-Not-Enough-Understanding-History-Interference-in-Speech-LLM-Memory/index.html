The Right Source Is Not Enough: Understanding History Interference in Speech-LLM Memory

本文最后更新于 2026年11月5日 中午

论文信息

  • 标题：The Right Source Is Not Enough: Understanding History Interference in Speech-LLM Memory
  • 作者：HongJin Song, Weiqiao Shan, Runwu Shi, Yifei Wu, Yujin Wang, Jiale Luo, Jiasheng Kuang, Xinyu Yang, Zhaoqi Cui, Chuizheng Kong, Ziyu Wu, Guowu Tan, Qiuyu Fang, Chunxiang Jin
  • 机构：Beijing Institute of Technology；Northeastern University, China；Institute of Science Tokyo；Ant Group；Wuhan University；Sichuan University
  • 版本：arXiv v1，2026-11-03；源码采用 ICLR 2027 样式，但当前应视为预印本
  • 论文：arXiv:2611.05124

一句话概括：Speech-LLM 即使已经识别出当前问题对应的正确历史音频源，其他历史音频中的具体答案值仍可能通过直接读取或中间状态传播进入答案计算；可靠的多轮语音记忆因此不仅需要“记住并检索”，还需要控制被记住的信息如何影响决策。

这篇论文最重要的区分是：找到正确来源，不等于只使用正确来源。 在 MOSS-Audio 与 MiMo-Audio 上，作者发现无关历史不是泛泛地让问题变难，而会把错误定向推向历史中出现过的具体值。

进一步的因果干预显示，两种回答格式存在不同路径：开放式生成的大多数历史值错误依赖模型继续访问无关音频；多项选择错误则可在直接访问被切断后继续存在，因为早期干扰已经写入问题—候选状态。论文的贡献是机制诊断，不是一个可直接部署的修复算法。

1. 问题：模型记住了什么，和最终用了什么，是两件事

论文图 1：模型可以正确保留多个历史事件，却在回答当前问题时让错误事件中的值进入决策。图中路径是概念示意。

多轮 Speech-LLM 通常把此前音频保留在上下文中，以便用户追问旧事件。已有工作因此重点测试两个能力：

  1. 历史音频是否仍被表征；
  2. 当前问题能否检索到相关音频。

但论文提出第三个问题：即使相关来源仍然可访问、来源角色也被模型识别，其他来源中的值是否仍会参与答案竞争？

例如历史中同时出现“图书馆 8 点开门”和“航班 10 点起飞”。用户问航班时间时，模型回答 8 点。这不是完全忘记航班，而是图书馆时间成为了错误证据。

作者将每段音频 turn 视为一个 source：回答当前问题所需的是 target source，其余为 irrelevant source。重要的是，来源是否相关取决于问题；同一段历史音频在另一个问题下可能正是必要证据。

2. 实验框架：自然语音验证现象，合成语音拆开变量

研究使用两个冻结权重的开源 Speech-LLM：

  • MOSS-Audio-8B-Instruct；
  • MiMo-Audio-7B-Instruct。

2.1 自然语音数据

作者从 LibriSpeech 构造 1,000 个三来源历史，共包含 3,000 段互不重复的主录音与 3,000 个来源特定问题。其中 450 个历史来自 test-clean，550 个来自 test-other；同一历史内的三段录音来自不同说话人和章节。

每个问题都有成对条件：

  • Neutral：额外来源不包含候选答案值；
  • Competing：额外来源支持某个错误候选值。

目标音频、问题、候选、来源顺序与 turn 数保持不变；中性替换还匹配词数和时长。

2.2 受控合成语音

机制实验使用时间、颜色、地点、数量四类答案，建立三套彼此独立的材料：

数据集 Dev / Test 用途
Relation-content 128 / 512 历史关系、自然错误、模块控制
Reading-structure 128 / 512 来源阻断、状态桥接、回答格式对比
Coherent role reversal 128 / 512 全层 role-value 因子扫描

每个 state-transfer episode 派生四个历史变体，因此测试有 2,048 个 condition，但不是 2,048 个独立 episode。统计置信区间按完整 episode 重采样，保留其内部配对结构。

3. 指标：把“正确值”和“历史错误值”直接比较

多项选择任务只比较 A–D 四个单 token 标签的下一 token logit。定义 target 相对 historical value 的 margin：

\[m = \ell(y)-\ell(h),\]

其中 $y$ 是正确值对应标签，$h$ 是无关历史值对应标签。$m$ 增大表示决策更偏向当前目标。

开放式回答则让模型生成短答案，再把实际输出归为 target value、history value 或 other。论文明确没有把自由生成的 sequence score 与选择题 option logit 混为一谈。

4. 行为结果：无关历史会把错误定向推向具体值

在 3,000 个自然语音问题上：

模型 Neutral Competing 变化 95% CI
MOSS-Audio 84.23% 78.73% -5.50 pp [-6.73, -4.30]
MiMo-Audio 48.23% 39.67% -8.57 pp [-9.80, -7.37]

这里的 Neutral 是“中性历史”，不是只输入目标音频的 baseline。为了排除模型本来就没听懂目标音频的情况，作者又筛选出两个模型在 target-only 下都答对的 1,365 个问题；加入 competing history 后，MOSS 与 MiMo 仍分别下降 2.79 和 10.06 个百分点。

更关键的是固定九 turn 的 load 实验。作者不增加上下文长度，只把中性 turn 替换成支持某个错误候选的语音：

  • 每增加一个支持该错误值的 turn，其相对正确答案的 score 增加 0.260（MOSS）和 0.089（MiMo）；
  • 支持另一个错误候选的 turn 仅贡献 0.008 和 -0.001；
  • 两种支持方向的差异置信区间分别为 [0.195, 0.305] 与 [0.068, 0.111]。

因此，性能下降不能仅解释为“历史更长”或“位置更远”。干扰携带具体语义方向。

论文图 3：同一段 near-history 在被问及时是有用记忆，在当前问题中却可能成为有害证据。每个柱子聚合 512 个 test episode。

5. 来源角色并没有消失

一个自然解释是：模型根本没弄清问题问的是哪段音频。作者通过 state transfer 检验这一点。

保持音频、来源顺序与候选不变，只切换问题所询问的事件；在第 17 层后，把 donor 的 question-candidate hidden states 转移给 receiver。结果在两个模型、两个转移方向上，预测有 98.6%–99.8% 跟随 donor 的 queried event。只转移孤立 candidate position 时，变化约为 1%–3%。

为了避免 whole-state transfer 顺带复制答案，作者进一步只转移由开发集拟合的 rank-4 role projection，而且 donor 与 receiver 的答案值不同。在第 24 层：

  • earlier → later role shift 使 later-minus-earlier margin 增加 0.99（MOSS）和 0.63（MiMo）；
  • reverse shift 则变化 -0.80 与 -0.49。

这说明“当前问题需要哪个来源”的信息确实存在，而且可以因果性改变答案。历史干扰不能只归咎于来源识别完全失败。

6. 三类因果干预

论文图 2：作者只干预 decoder state；音频经过 audio encoder，而文本问题不经过。所有干预都是已知来源边界的诊断性反事实。

6.1 切断对无关来源的直接访问

严格 late-block 条件让第 0–17 层正常处理完整历史；第 18–35 层中，所有位于无关来源之后的位置都不能再注意该来源，包括后续音频、问题、候选及 source wrapper token。开放式生成时，新生成 token 在所有层都不能访问该来源。

这一区分很重要：late block 阻止未来继续读取，但不能擦除前 18 层已经写入其他位置的影响。

6.2 转移 question-candidate states

作者建立两次匹配运行：

  • $F$：完整 early access；
  • $E$：第 0–17 层阻断 question position 对无关来源的访问。

第 17 层后，把 $E$ 的 question-candidate states 放进 $F$，或反向把 $F$ 放进 $E$；两个 receiver 后半程都使用完全相同的 late block。这样便能测试早期历史影响是否被中间状态携带。

6.3 分离 source role 与 answer value

在每层，作者从“音频和值完全相同、只改变询问事件”的 state difference 拟合 rank-4 role basis $U_R$；再从“问题不变、只改变历史值”的差分 $D_V$ 中去除 role projection：

\[D_{V\perp R}=(I-U_RU_R^\top)D_V,\]

随后拟合 rank-4 value basis $U_V$。差分先中心化，再进行 randomized SVD；每层独立拟合，开发集与测试集分开。

干预只在单层、最后 32 个 prompt position 上加入 projected difference，后续网络继续正常计算。“value”指答案语义，不是 attention head 的 Value tensor。

7. 两条干扰路径：开放生成依赖继续读取，选择题可由状态携带

条件 MOSS 开放式 MiMo 开放式 MOSS 选择题 MiMo 选择题
Full history $F$ 151 22 175 94
Strict late block $F+L$ 2 3 124 49
$F+L\leftarrow E$ — — 6 1
$E+L\leftarrow F$ — — 125 49

这些是同一批 2,048 个 test condition 上的 history-aligned error count，不是独立 episode 数。

开放式回答中，late block 几乎消除了错误：MOSS 151→2，MiMo 22→3。这说明在该设置下，模型通常需要继续读取无关音频才能生成历史值。

多项选择中则有大量错误存活：MOSS 175→124，MiMo 94→49。将 early-blocked states 注入后，错误进一步降至 6 和 1；反向恢复 full-access states，又回到 125 和 49。

由于两个 receiver 的 late mask 完全相同，差异不能归因于后半程可访问位置不同。结论是：早期对历史的读取已经改变 question-candidate states，之后即使不能再看原音频，这些状态仍能推动错误候选。

论文还做了 MOSS 单 token 颜色控制：late block 清除了全部 32 个开放式历史值错误，但 51 个选择题错误中仍有 37 个保留，说明差异不只是开放式自回归需要反复读上下文。

8. Role 与 Value 在网络深度上的敏感区间不同

论文图 4：灰色区域仅用于标示 12–17 层，不代表作者独立证明了一个排他的“记忆模块”。曲线是单层干预后的下游效应。

作者在全部 36 个 decoder layer 上进行因子扫描。定义 role effect 为 $\Delta_R$，在已有 role edit 后增加 value edit 的条件效应为：

\[\Delta_{V\mid R}=\Delta_{R+V}-\Delta_R.\]

结果显示：

  • value 条件效应从约第 9–12 层开始明显，在中间层较强；第 16 层为 1.51（MOSS）和 0.95（MiMo）；
  • role effect 在更深层增强，MOSS 第 23 层达到 2.14，MiMo 第 22 层达到 1.15；
  • 改变 role 后，value edit 仍有显著附加效应。

这不意味着 value 首次在第 9 层出现、role 首次在第 22 层出现。每个单层 edit 都会影响后续所有计算，因此曲线测量的是干预敏感度，不是首次表征位置。峰值也是全层扫描中的 test peak，并非独立 held-out layer selection。

更有意义的解释是：来源角色可以改变决策方向，却没有把其他来源的值完全关在门外。

9. 自然错误修复：联合干预最好，但仍是 oracle 诊断

论文图 5：role enhancement、counterfactual value shift 与联合干预对自然发生错误的恢复。

作者固定 near-history 中自然发生的历史值错误，并在第 20 层干预：

  • MOSS：165 个 condition、122 个 episode，全部复现；
  • MiMo：初选 52 个 condition，其中 47 个 condition、37 个 episode 复现；5 个未复现错误被排除。

episode-averaged 恢复结果为：

干预 MOSS MiMo
Role enhancement 43.0% [34.8, 51.6] 62.2% [45.9, 77.0]
Counterfactual value shift 68.4% [60.7, 76.2] 67.6% [54.1, 81.1]
Both 79.1% [72.1, 85.7] 83.8% [73.0, 93.2]

value shift 不是删除历史，而是沿开发集拟合的 $U_V$，向匹配的 alternative-history state 移动一半距离。role shift 也依赖同一 episode 的历史问题状态。这些干预需要 oracle source boundary 与 counterfactual state，只能证明因果参与，不能直接部署。

附录图：在同一测试总体内，value effect 相对 role effect 越强，历史值错误越常见；这是描述性关联，不是独立验证的错误预测器。

在第 20 层，按 $D=\Delta_V-\Delta_R$ 分五组，历史值错误率从最低组到最高组：

  • MOSS：3.3% → 47.0%；
  • MiMo：4.8% → 14.4%。

但这个指标本身需要对同一 example 做反事实干预，所以不能被描述成在线 error detector。

10. 不能简单归因于 Attention 或 MLP

附录图：不同模型与层上，attention/MLP transfer 的恢复与保留历史问答能力并不一致。

作者把 target-only donor 的 attention output 或 MLP output 注入包含两来源的 receiver。结果不能支持“错误都来自 attention”或“错误都来自 MLP”的统一结论。

一个关键反例是：MOSS 第 24 层 attention-output replacement 可强烈恢复当前问题，却让询问历史事件时的准确率接近 0。它可能只是移除了历史证据，而不是学会了选择性使用历史。

因此，修正当前答案还不够。一个好的方法必须同时满足：

  • 当前问题不受无关历史值干扰；
  • 当用户真正追问该历史时，它仍能被正确使用。

11. 与站内“上下文抗噪”文章的关系

站内此前的《上下文也会骗人？Speech-LLM 的抗噪表征学习与动态置信度门控机制》关注历史转录错误、上下文偏置与推理时门控；本文讨论的是更窄、也更基础的机制问题：历史内容可以完全正确，却因为不相关而成为错误证据。

维度 上下文抗噪/门控路线 本文 role-value 分析
干扰来源 错误、噪声或过度偏置的上下文 正确但与当前问题无关的历史音频
核心问题 是否应信任或注入上下文 上下文已保留后，哪些值进入答案计算
分析对象 训练策略或推理门控 冻结 Speech-LLM 的内部因果路径
结论 需要控制上下文依赖 检索到正确 source 仍不足以排除错误 value
当前产物 面向鲁棒系统设计 oracle 机制诊断，尚非部署方案

跨论文理解上，两者可以衔接：未来的门控不仅要决定“是否读取历史”，还应在 question-conditioned state 形成时限制不相关 value 的写入，否则晚一些再裁剪 KV cache 可能已经来不及。

12. 论文的边界与成熟度审计

这篇论文对自身证据边界写得较清楚，但阅读时仍需保留以下限定：

  1. 预印本状态：源码使用 ICLR 2027 final-style 命令，但 arXiv v1 不能据此视为已经录用。
  2. 只有两个模型：共同现象不等于所有 Speech-LLM 都有相同层峰或路径占比。
  3. 受控材料有限：四类答案与合成事件便于因果识别，但不能估计真实开放对话中的失败率。
  4. 没有自动修复器：intervention 使用已知来源边界、开发集方向与 matched counterfactual，不能直接在未知线上数据运行。
  5. 峰值不是 held-out 选择：层网格在测试前确定，但报告的是 scan peak；置信区间为 pointwise，不是峰位置的 simultaneous interval。
  6. 复现资产未随源码提供：论文说明完整复现还需要实验代码、音频材料与 per-example output；当前 arXiv source package 主要提供论文源码和图。
  7. 权重版本不完全统一：附录记录模型 configuration hash，却没有统一的 upstream weight revision identifier。
  8. 不解释训练根因：研究定位了推理时的因果路径，没有证明这些路径由哪类训练数据或目标造成。

源码中没有发现待填 TODO、占位引用或自相矛盾的主结果数字；相反，作者多次强调 condition 与独立 episode 的区别、错误复现筛选、开放式与选择题指标不可直接等同，以及干预不是部署方案。

13. 工程启示

论文没有提供现成算法，但它改变了多轮语音记忆系统的设计检查表：

  1. 评测不能只问“记没记住”：同一历史事实应同时测试被问及时能正确使用、不被问时不会干扰。
  2. 来源检索准确率不是终点：还要测其他来源的 value 是否改变 candidate margin。
  3. 只在解码后段屏蔽历史可能太晚：早期读取可能已经把影响写进 question-candidate states。
  4. 开放生成与选择题要分开测：格式会改变信息传播路径，不能用一个 benchmark 替代另一个。
  5. 修复必须保留有用记忆：只让当前答案变对、却破坏历史追问能力，不算可靠 selective memory。
  6. 需要在状态形成时做条件化控制：未来可学习 question-conditioned source gate、value routing 或具有保真约束的状态净化，而不是只做静态 cache pruning。

总结

这篇论文把 Speech-LLM 的多轮记忆问题从“存储—检索”推进到“证据使用”：

  • 历史音频中的具体值会定向诱导错误；
  • 模型同时保留了可用的 source-role 信息；
  • 开放式生成主要依赖继续读取无关来源；
  • 选择题干扰则能经 question-candidate states 持续传播；
  • role 与 value 在不同深度呈现不同干预敏感度；
  • 两者共同导致自然错误，联合 oracle 干预恢复最多；
  • 但任何修复都必须同时保留历史被正确追问时的可用性。

因此，“找到正确来源”只是可靠语音记忆的必要条件。真正困难的是让模型在当前问题下，只允许相关来源中的值进入答案形成，同时保留其他记忆供未来问题调用。
