一句话概括：Hy ASR 3.0 把语音编码、音频条件热词检索和多种文本上下文接入 Hy3 自回归解码器，再以迭代伪标注、三领域专家强化学习与 on-policy 蒸馏整合能力，重点改善中文方言、上下文相关关键词和复杂场景下的转录。

报告给出的公开中文、英文、纯粤语汇总错误率分别为 4.64%、5.22%、5.06%，相对各自最强的非 Hy 对比系统，论文报告约 2.7%、3.0%、11.0% 的相对错误率下降；内部句内上下文与对话上下文测试的目标关键词召回率分别为 61.88%、83.94%。这些结果的看点，不只是干净语音上的错误率，而是模型能否利用一句话里的解释、上一轮对话或外部词表，把“读音接近”进一步落实为“写对那个词”。

但这是一份完整系统的能力报告，而不是已经充分验证各组件因果贡献的可复现训练配方：模型规模、关键架构规格、训练超参数、奖励细节、部署性能与逐阶段消融均未披露。公开横向分数是作者在本研究中报告的测试结果，不是从各厂商官方榜单搬来的成绩；多个公开子集仍非最优，口音英语甚至较 Preview 回退。下面将系统设计、实测结果与证据边界分开讨论。

1. 这篇报告真正要解决什么

把语音转成“语法通顺的文字”和忠实地写出说话人想表达的那个词，并不总是一回事。Hy ASR 3.0 围绕三类实际困难组织系统：

  1. 声学上相似、语义上不同的词。同音人名、罕见职官名、游戏模式名，不能只依靠局部发音判断。
  2. 上下文的形式不统一。业务系统可能只提供热词表，也可能提供上一轮问答或一段摘要；音频自身还可能含有“不是这个字，是那个字”的解释。
  3. 语言与声学分布偏移。方言、长音频、儿童与老人语音、低音量和噪声，需要同一个系统兼顾，而不是只优化一种标准录音条件。

因此，论文的主要价值在于展示如何把这些目标放进统一的 Speech LLM 系统及后训练流程，而不是提出一种完全不同的 ASR 解码范式。

图 1：原文能力总览，每项与该指标下最强的非 Hy 对比系统比较。注意两处口径：左上角的 Dialect 4.80% 包含四个粤语子集和 KeSpeech，不是纯粤语的 5.06%；右下角原图写作“Whispered speech”，但正文和表 4 定义的是“低音量语音与噪声语音的合并测试”。本文以后者为准，不把 7.49% 解读成单独的耳语识别成绩。

覆盖范围也需要先说清楚：摘要称支持普通话、英语和 13 个中国方言组，其中包含粤语；引言则说，在普通话、英语、粤语之外支持 12 个其他方言组。两种表述是一致的，并不是“13 加 12”，也不是两份互相矛盾的能力清单。

2. 架构：先以音频筛选热词，再让文本上下文参与转录

2.1 主干仍是 Encoder–Adapter–LLM

Hy ASR 3.0 由三个主模块与一条检索支路组成：

  • Audio encoder：把输入语音变成声学表示序列。
  • Audio adapter：把编码器表示映射到 LLM 能接收的嵌入空间。
  • Audio-conditioned hotword retrieval：同时读取音频表示和候选热词表，选出与当前音频相关的词。
  • Hy3 LLM decoder：基于文本上下文、音频嵌入及已经生成的 token，自回归地产生转录文本。

图 2：音频表示一方面经过 adapter 接入 Hy3，另一方面参与热词检索。上下文包括 Summary、Dialogue QA 和 Retrieved Hotwords。下方给出 Encoder SSL、Pre-training、SFT、RL 的流程概览。图是模块关系示意；下文的“文本前缀位于音频嵌入之前”依据原文第 2 节的明确描述，不能由图中方框左右位置推导出完整序列模板或注意力掩码。

为便于说明，可把正文的数据流抽象成：

\[\mathbf{H}=E(\mathbf{a}),\qquad \mathbf{Z}=A(\mathbf{H}),\qquad \mathcal{B}^{*}=R(\mathbf{H},\mathcal{B}).\]

其中，$\mathbf{a}$ 是输入音频，$E$ 是音频编码器，$A$ 是 adapter，$\mathcal{B}$ 是候选热词表，$R$ 是音频条件检索机制，$\mathcal{B}^{}$ 是选出的相关热词。检索结果与可用的摘要、问答历史共同组成文本上下文，经过 tokenizer 和文本嵌入处理，作为*音频嵌入之前的文本前缀。

把这个前缀记为 $\mathbf{C}$，则转录过程可概括为：

\[p_{\theta}(\mathbf{y}\mid\mathbf{a},\mathbf{C}) = \prod_{t=1}^{|\mathbf{y}|} p_{\theta}(y_t\mid\mathbf{C},\mathbf{Z},\mathbf{y}_{<t}).\]

以上两式是对正文的记号化整理，不是论文另外给出的实现公式；原文没有公开 $\mathbf{H}$、$\mathbf{Z}$ 的具体维度，也没有给出几种上下文的完整提示模板与固定排列规则。

2.2 外部上下文与句内上下文不是同一个输入通道

论文区分了两种情况：

上下文来源 模型如何获得 典型作用
外部热词表 音频条件检索后，把选中的词放入文本前缀 人名、业务术语、专有实体的候选拼写
外部 Summary / Dialogue QA 可用摘要或先前问答作为文本前缀 提供领域、话题与会话语义
同一句音频内部的信息 通过音频表示与转录序列建模，不额外提供一个“句内上下文文本” 利用说话人自己的语义铺垫、否定对照或逐字解释消歧

这里尤其容易误读：句内上下文评测不是先把正确转录交给模型作为 prompt，也不是一个外部文本纠错实验。其线索本来就在待识别的音频里。

另一方面，“使用句内后文帮助识别前面的人名”并不等于论文已经证明在线流式场景也能做到相同效果。是否能访问整段音频、如何分块、何时固定历史输出，以及后文到来后能否修订先前文字，v1 均未说明。

2.3 检索接口明确，但实现远未完整披露

这条检索支路的重要性在于：候选热词不是完全脱离声学证据直接灌入 prompt，而是先接受当前音频条件的筛选。不过，论文没有交代：

  • 热词与音频分别如何编码、如何打分；
  • 是整句检索还是局部片段检索，是否有显式时间对齐；
  • 候选规模、Top-K、阈值、索引结构与训练损失；
  • 检索召回率、非热词误触发率，以及长列表带来的开销。

所以，可以把它定位为“音频条件的候选筛选 + 文本前缀偏置”，但不能进一步认定它使用了 CIF、CTC 尖峰、双塔局部匹配或位置门控，也不能宣称它已经解决百万级热词检索和过度偏置。

3. 训练：从迭代声学表征到多专家能力整合

论文将训练概括为音频编码器预训练、大规模 ASR 预训练和后训练；后训练再包括 SFT 与 RL。需要注意，编码器训练本身有两个阶段，接入 LLM 后的 ASR 预训练又有两个阶段，不是同一组阶段的重复描述。

3.1 编码器：Best-RQ 启动，HuBERT 迭代，RVQ 形成多级目标

编码器采用迭代式 HuBERT 风格自监督流程：

  1. 用 Best-RQ 训练 bootstrap encoder。
  2. 选取其部分中间层表示并量化，构造离散监督目标。
  3. 用这些目标训练一个中间版本的 HuBERT 模型。
  4. 对中间 HuBERT 的表示做 残差向量量化（RVQ），形成多级目标。
  5. 最终编码器从被 mask 的语音输入中预测这些多级目标。

这个过程的关键是监督目标随着表征质量一起迭代：不是一次性固定最初的量化标签，而是先获得较好的中间表示，再构造更丰富的预测目标。这里的 RVQ 用于自监督训练目标构造；报告并没有说最终送入 Hy3 的音频一定是这些离散 RVQ 码，也不能据此把系统称为“离散 codec token ASR”。

编码器训练数据被描述为数千万小时，以普通话和英语为主，同时包括粤语和其他中国方言。训练分为：

  • 在广泛语音混合上做大规模预训练；
  • 在重平衡后的数据上继续预训练，提高方言占比，降低噪声录音与短句的权重，同时强化 masking，并使用 utterance mixing 增强抗干扰语音能力。

“降低噪声录音权重”与后续“加强困难声学场景”发生在不同训练环节，不应合并成一条模糊的数据策略。前者是编码器继续预训练的数据描述，后者是 ASR 继续预训练的定向补强。

报告没有给出编码器层数、参数量、mask 比例、量化码本规模、RVQ 级数或每一级损失权重，因而可以还原训练思路，却还不能复现同一个编码器。

3.2 ASR 两阶段预训练：先做可靠的大规模伪标注，再调整任务分布

第一阶段：大规模 ASR 预训练。

数据来自数千万小时的网络语音。作者用多个 ASR 系统独立生成候选转录，通过 ROVER（Recognizer Output Voting Error Reduction） 融合，再进行多级质量过滤。随后做领域感知的数据平衡和数据压缩，后者在本文语境中指减少冗余、优先保留信息量较高的样本，不是音频帧率压缩或推理 token 压缩。

作者声称，这套数据策略使模型在仅使用原始训练数据 50% 的情况下取得更好性能。但报告没有列出对应的受控实验表、原始与筛选后的准确规模、分域配比或具体性能差值。因此，50% 是需要保留条件的作者陈述，不是可以独立复核的“数据减半仍提升多少”的实验结论。

第二阶段：定向继续预训练。

提高以下数据的占比：

  • 方言语音；
  • 上下文偏置数据；
  • 困难声学条件下的语音。

作者还称，这使预训练分布更接近后续 SFT，允许把 SFT 数据缩减到原来的 十分之一，同时维持性能。这里同样缺少匹配的对照结果、绝对数据规模与训练成本，不能直接改写为“SFT 加速 10 倍”，也不能把最终的方言或上下文收益因果归给这一阶段。

3.3 SFT：上一轮最好的模型，参与下一轮数据生产

SFT 不只是消费一份固定标注集，而是迭代改进数据生产链：

  1. 持续改进自动转录流水线中的标注组件；
  2. 用上一轮表现最好的 SFT checkpoint 作为教师，生成下一轮伪转录；
  3. 补入方言和其他困难场景的定向数据；
  4. 在提升这些能力的同时，尽量保持通用 ASR 表现。

这是一种迭代自训练/伪标注机制。合理动机是利用更强的当前模型提高下一轮监督质量，但论文没有报告迭代次数、每轮样本量、教师筛选准则、伪标签错误率变化或人工纠错比例；不能把“迭代”自动当作持续净收益的证据。

3.4 三领域专家 RL：先分别优化，再合并行为

作者从 SFT checkpoint 出发，分别训练三个独立专家：

专家 优化重点
通用 ASR 专家 一般领域的识别表现
方言 ASR 专家 方言相关的识别行为
上下文偏置 ASR 专家 依赖外部或语义上下文的关键词识别

奖励按领域设计，除整体识别准确率外，还考虑关键词识别和句级流畅性。作者的动机是避免通用识别、方言表达和上下文关键词这些目标在同一策略里直接混合时互相干扰。

不过，“分别优化可以缓解干扰”目前是设计解释：报告没有给出与单模型联合 RL 的等数据、等计算量对照，也没有披露奖励公式、各项权重、RL 算法或约束项。不能把它补写成 PPO、GRPO 等某一种算法，更不能声称已实验证明三专家优于联合 RL。

3.5 MOPD：教师监督学生自己会走到的状态

三个专家随后通过 Multi-teacher On-policy Distillation（MOPD） 整合到一个学生模型。对每条样本，学生先生成自己的识别假设，再将样本及这条假设路由给相应领域的专家，由专家提供 token 级分布监督。

论文给出的目标函数为：

\[\mathcal{L}_{\mathrm{MOPD}} = \mathbb{E}\left[ \frac{1}{T}\sum_{t=1}^{T} D_{\mathrm{KL}}\left( \pi_{\theta}(\cdot\mid\mathbf{s}_t) \Vert \pi_{\phi_d}(\cdot\mid\mathbf{s}_t) \right) \right].\]

其中：

  • $\pi_{\theta}$ 是学生策略；
  • $\pi_{\phi_d}$ 是领域 $d$ 对应的专家；
  • $\hat{\mathbf{y}}$ 是学生自行生成的转录，$T=|\hat{\mathbf{y}}|$；
  • $\mathbf{s}_t=(\mathbf{x},\hat{\mathbf{y}}_{<t})$；
  • $\mathbf{x}$ 包含声学输入和可选的偏置上下文；
  • 期望同时覆盖领域路由样本与学生生成的假设。

它与“让教师离线生成一份正确转录，然后普通 SFT”有两个区别。

第一，训练状态来自学生自己的轨迹。教师面对的是学生已经生成的前缀，而不仅是参考答案前缀。其动机与论文引用的 on-policy distillation 一致：在学生实际可能遇到的状态上提供纠偏信号。

第二，KL 的方向是学生到专家。公式明确为 $D_{\mathrm{KL}}(\pi_{\theta}\Vert\pi_{\phi_d})$，不能写反。多教师也不意味着对每个 token 同时平均三个专家；正文描述的是按领域选择相应专家。

这是一种训练阶段的能力整合，不等于推理时三模型投票，也不能仅凭“专家”二字把最终系统称为 MoE。报告目标是得到统一 ASR 模型，但没有给出蒸馏前后各专家、学生的逐域结果，无法量化整合时保留了多少能力、损失了多少能力。

3.6 Model-Behavior RL：最后对真实难例做行为补强

MOPD 之后还有一轮 Model-Behavior RL，针对实际使用中发现的困难案例，特别是需要周边语境才能写对的关键词，强化上下文利用和句级连贯性。

它和前面的上下文专家并非同一段流程：前者是独立领域专家的训练，后者是在能力整合之后继续调整统一模型行为。但 v1 没有提供难例挖掘规则、样本量、reward 实现及这一阶段前后的独立结果。因此，后面那些漂亮的句内消歧案例，最多与设计目标一致，不能直接算作 Model-Behavior RL 的单独效果证明。

4. 实验：汇总领先成立，但必须保留测试范围

4.1 先统一阅读规则

下列表格均转录自 Hy ASR 3.0 v1 本文报告的结果，不是我们重新执行的评测，也不是从厂商官方页面摘出的官方成绩。原文引用各系统技术报告和服务文档，是为了标识模型家族或服务；作者明确说明，横向数值来自本研究。

为控制表格宽度，使用以下简称：

  • Qwen：Qwen3 ASR Flash；Fun：FunASR Flash；Doubao：Doubao ASR 2.0。
  • Seed：Seed 2.0 Lite；Step：StepAudio 3 ASR Max。
  • Preview：Hy ASR 3.0 Preview；Hy：Hy ASR 3.0。

公开与内部主语言表沿用论文的 CER/WER 标注，英语正文明确称 WER；鲁棒性表明确为 CER。上下文表是目标关键词召回率，方言人评则是人工判定通过的转录比例。后三者都不能转换成普通的词错误率。

相对错误率下降按原文定义计算：

\[\mathrm{RERR}=\frac{E_{\mathrm{comp}}-E_{\mathrm{Hy}}}{E_{\mathrm{comp}}},\]

其中 $E_{\mathrm{comp}}$ 是该指标最强的非 Hy 对比系统。召回率与人评比例的差异则用百分点（pp），而不是 RERR。

四个例子的技术含义各不相同：

  • “佥事”：同句中的官职层级与梁冠制度提供历史语义线索，避免写成“千石”等同音近音词。
  • “绿洲启元”：游戏模式、M416 与武器属性共同提供领域背景，目标是专有名称，而不是更常见的“绿洲起源”。
  • “白鹿……不是天上飞的白鹭”：需要同时保留肯定对象和被排除对象，不能把全句同音词统一替换。
  • “邱黎璃，是黎明的黎，琉璃的璃”：名字里相邻的同音字必须分别绑定到后面的解释，不能因为后文解释写对了，就认为名字本身也被正确转录。

这些案例比单纯展示低 CER 更容易说明“语境相关关键词”的困难，但它们是挑选出的定性例子。表 3 是跨系统比较，不是同一模型使用/不使用上下文的 on/off 消融。没有移除句内提示、打乱对话历史或禁用检索后的对照，不能从中估计“上下文模块贡献了多少”，也不能排除通用模型能力、数据构造或其他训练差异的影响。

此外，报告虽然支持热词、摘要和问答三种外部形式，却只给出了句内上下文与 Dialogue QA 的这两组汇总。没有单列热词-only、摘要-only、候选数扩展、错误上下文，以及非目标词是否受损等实验。关键词召回率提高并不自动证明全句保真度和抗过度偏置都得到改善。

4.6 方言：最终证据来自人评，而不是 LLM judge 分数

许多方言缺乏统一书写规范，同一段口语可能存在多个合理写法。论文因此对没有成熟书写惯例的方言采用翻译式的书面表示思路。在开发过程中，作者用 LLM judge 评估语义错误与转录风格一致性；但最终报告的方言成绩来自人工评测，不是 LLM judge 的打分结果。

人评覆盖 13 类、91 个次区域变体，只与 FunASR Flash、Doubao ASR 2.0 比较。三项指标的含义是：

宽松识别率 语义正确，允许不改变意思的措辞差异 不是逐字忠实度
格式合规率 标点、逆文本归一化（ITN）、流畅性等无格式问题 不是内容识别准确率

5. 放回已有技术脉络：与 Qwen3-ASR 和上下文偏置路线比较

5.1 与 Qwen3-ASR：共同主干，不同的披露重点

此前的 Qwen3-ASR Technical Report 解读 已讨论过音频编码器接 LLM 的 ASR 路线。这里还需要区分两个对象：Hy 表中的 Qwen3 ASR Flash 服务，不是旧文讨论的开源 Qwen3-ASR-0.6B/1.7B checkpoint。不能把 Flash 在这份报告里的分数，直接贴到开源模型名下。

下表的 Qwen3 架构与训练信息依据 Qwen3-ASR 原论文第 2 节 复核，而非复用旧文中未重新核实的评价性结论。

5.2 与上下文偏置综述：它是系统级整合，不是已经验证的局部检索新机制

在此前的 上下文偏置、Speech-RAG 与语音大模型领域自适应综述 的分类中，Hy 可以放在“检索筛选候选，再通过文本上下文影响 Speech LLM”的位置，同时把输入形式扩展到摘要与对话历史。

这里比较的是接口与证据类型，不是复用综述中的跨论文榜单数值。Hy 没有报告足够信息来说明它是否采用了综述所讨论的局部声学定位机制，也没有提供匹配协议的 B-WER、非热词 CER 或检索召回率。它的 61.88%/83.94% 是两个内部测试集的目标关键词召回率，不能拿来与其他论文的实体检索 Top-1 或偏置词错误率直接比较。

它给出的有价值方向是：上下文 ASR 不必停留在“热词拼写提示”，还可以利用对话语义与音频内的明确解释。但“支持更多上下文形式”与“已经证明这些形式分别有效、且不会损伤非目标词”仍是两件事。

这里有三条尤其重要的解释边界。

第一，Preview 不是组件消融。它与最终模型之间可能同时改变数据、训练和工程实现；论文没有把变化拆开，因此不能把某个汇总差值分配给 continued pretraining、Expert RL、MOPD 或 Model-Behavior RL。

第二，跨系统比较不是同预算比较。不知道 Hy 的参数规模、训练计算量，也不知道各商业 API 的精确版本和调用配置，就无法得出“某种训练策略在相同资源下更有效”的结论。公开中文 4.64% 对 4.77%、英文 5.22% 对 5.38% 是报告中的点估计差异；没有置信区间，不能进一步声称统计显著。

第三，源码与图表口径也需要核查，而不只是摘取摘要。本次阅读中应明确保留的事项包括：

  • 摘要的“13 个方言组含粤语”与正文的“粤语之外 12 类”一致，不是计数冲突；
  • “纯粤语 5.06%”和“粤语 + KeSpeech 4.80%”是不同集合；
  • 总览图的“Whispered speech”与正文/表 4 的合并低音量、噪声口径不一致，以后者作为可解释的结果范围；
  • Seed 中文汇总 5.42% 无法由表内显示的子集值按简单均值复现，不能隐藏这一聚合疑点；
  • SpeechIO 的源码参考条目明确写了 evaluation snapshot unspecified，正文没有补足 Locked/Unlocked 的具体快照协议。官方仓库引用不等于这些行就是可直接复核的官方榜单记录。

这些限制不等于否认已报告的系统表现，而是决定了读者可以得出多强的结论。现阶段可以说：在作者所报告的系统和测试设置内，Hy 有较强的汇总识别、上下文关键词和部分内部鲁棒性表现。还不能说：某个新训练环节已经被单独证明有效，所有子集都领先，或者系统已具备可验证的低成本流式部署能力。

7. 总结

Hy ASR 3.0 最值得关注的是三件事：

  1. 把上下文从单一热词表扩展到多种语义线索。音频条件检索、摘要和问答历史是外部入口，句内解释则直接通过音频与转录建模，两者不能混为同一个检索模块。
  2. 把能力专门化与能力整合分开。三领域专家 RL 后使用学生自身轨迹上的 MOPD，再做难例行为优化，构成一个清晰的后训练组织思路；但各环节的独立收益尚未被消融验证。
  3. 报告了有竞争力的完整系统结果，也留下清晰短板。公开汇总领先不掩盖口音英语回退、多个子集非最优，以及方言宽松识别率比 FunASR 低 1.0 pp；内部集上的优势也不应跨协议外推。

因此，这篇报告适合用来理解一个面向业务的 Speech LLM 如何组织语音、上下文与多目标后训练。若要进一步判断可复现性、训练投入回报或部署性价比，仍需要模型规格、完整评测配置、组件消融和工程实测，而不是继续叠加更多没有控制变量的榜单。
