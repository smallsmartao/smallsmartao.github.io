从拒绝采样、自投机到 CTC 与声学锚定：Speech 投机解码与推理加速深度综述

本文最后更新于 2026年8月18日 下午

在大语言模型（LLM）与语音大模型（Speech-LLM / Encoder-Decoder ASR / TTS）的自回归逐步解码中，每一步前向计算都必须将庞大的模型权重从高带宽显存（HBM）搬运到计算单元，使得推理过程严重受限于显存带宽（Memory-Bound）。

投机解码（Speculative Decoding, SD）通过“极轻量草稿机制（Drafter）生成 $K$ 个候选 Token $\to$ 大容量目标模型（Target Verifier）单次前向执行并行验证”的范式，在贪婪解码（Greedy）与温度采样下实现严格的数学无损加速。

然而，将纯文本投机解码迁移至语音模态（Speech-to-Text 与 Text-to-Speech）绝非简单的模型替换，而是面临着一整套声学与时序特有的挑战：

  1. 声学强条件约束（Audio-Conditioned）：ASR 任务输出分布高度确定，文本领域的树状搜索（Tree Attention）在语音中是否仍有收益？
  2. 小 Target 模型开销失衡：在 0.5B~1B 的轻量级语音模型（如 TTS / 端侧 ASR）中，自回归 Drafter 为什么会导致严重的“负加速”？
  3. 时域对齐漂移（Alignment Drift）：Drafter 虽然能访问完整音频，但随着生成步数增加，为何会丢失与音频帧的精确定位？
  4. 模态特化表征赋能：语音前端天然存在的 CTC 非自回归（NAR）表征与声学编码器，如何做到“零成本”草稿直出？

本文基于 arXiv 原论文深度精读 与 工业生产级部署（SpeechSpec / SGLang / vLLM）实战经验，系统解构 6 篇核心论文与落地架构。

1. 投机解码的数学基石：Leviathan et al. (ICML 2023)

1.1 核心观察与瓶颈突破

在标准的自回归生成中，生成 $K$ 个 Token 需要大模型串行执行 $K$ 次前向计算。由于 LLM 解码的主要开销在于将大模型的全量参数从显存加载到计算核心，因此大模型单次前向同时打分 $K$ 个 Token 的计算耗时，与打分 1 个 Token 的耗时几乎相当。

Leviathan et al. 提出了利用一个计算开销极低的小模型 $M_q$（Draft Model）快速生成 $K$ 个候选 Token，再交由大模型 $M_p$（Target Model）执行单次并行打分校验的框架。

1.2 严格无损拒绝采样（Rejection Sampling）数学推导

设目标大模型预测分布为 $p(x) = p(x_t \mid x_{<t})$，草稿模型预测分布为 $q(x) = q(x_t \mid x_{<t})$。在每轮投机迭代中：

  1. 草稿模型 $M_q$ 串行自回归生成 $K$ 个候选 Token：$(\tilde{x}_1, \tilde{x}_2, \dots, \tilde{x}_K)$；
  2. 目标模型 $M_p$ 一次性并行打分，得到 $p(\tilde{x}_1), \dots, p(\tilde{x}_K)$。

对于第 $i \in {1, \dots, K}$ 个 Token 进行逐步检验：

  • 接受判定：从均匀分布 $r \sim U[0, 1]$ 采样，若满足：则接受 $\tilde{x}_i$，并继续校验第 $i+1$ 个候选 Token。
  • 拒绝与残差重采样：若在第 $n$ 个位置首次出现 $r > \frac{p(\tilde{x}_n)}{q(\tilde{x}_n)}$，则拒绝该 Token 及后续所有 $\tilde{x}_{n+1 \dots K}$，并直接从修正残差分布 $p’(x)$ 中采样一个新 Token 作为第 $n$ 个位置的输出：

2. 自投机与树状掩码注意力：Medusa & EAGLE

2.1 抛弃独立小模型的自投机（Self-Speculative）

独立小模型在实际部署中存在显存争抢、额外参数常驻以及双模型通信开销。自投机方案直接利用 Target 模型自身的隐层表征生成草稿：

  • Medusa (2024)：在 Target 顶层隐状态并联 $K$ 个单层 MLP 预测头，单步前向直接预测未来多步候选分布；
  • EAGLE / EAGLE-3 (2024-2026)：指出直接预测 Top-1 Token 存在严重特征不确定性，改为在 Target 倒数第二层特征（Hidden States）上挂载轻量 Transformer 头进行隐状态自回归。

2.2 树状因果注意力掩码（Tree Attention Mask）

如上图所示，Medusa 与 EAGLE 将多步候选组合构造成前缀树（Token Tree）。Target 模型通过构造特殊的 2D 因果注意力掩码，使得每个候选节点只能看到其树状祖先节点的 KV Cache。Target 仅需单次前向即可同时打分树上的所有分支路径，一次性挑选出命中长度最长的有效前缀。

3. 语音 ASR 强条件特化：SpecASR (arXiv:2507.18181)

3.1 核心问题：ASR 是音频强条件引导任务

北京大学团队在 SpecASR 中指出，文本领域的投机解码迁移到 ASR 往往只有 1.5x~2.0x 的平庸提速。这是因为 ASR 的解码过程受到前端语音特征的极强约束（Audio-Conditioned），大模型与小模型在清晰语音段的预测几乎 100% 一致，而在噪声或口音段则极易同时发生不确定性震荡。

3.2 SpecASR 三大核心算法机制

  1. 自适应单序列预测（Adaptive Single-sequence Prediction, ASP）：
    • 突破传统 4~6 步的固定短草稿限制，将最大 Draft 长度扩展到 $K=24$；
    • 在 Draft 自回归生成时，实时检测每个 Token 输出的归一化 Logits 与信息熵。一旦检测到某个 Token 置信度低于阈值（如 0.4），判定进入声学模糊区间，立即主动截断草稿，交由 Target 模型验证，杜绝在错误路径上浪费生成算力。
  2. 草稿序列循环复用（Draft Sequence Recycling, DSR）：
    • 在传统投机解码中，一旦中间第 $n$ 个 Token 校验失败，后续 $K-n$ 个 Token 全部被丢弃；
    • SpecASR 发现：在 ASR 任务中，被拒绝的后续 Token 在声学邻域窗口内仍然具有极高的转写正确率。DSR 将这些被丢弃的片段存入循环缓存池，在后续生成步中进行局部拼接复用，减少了 74.1% 的无效 Draft 计算。
  3. 两阶段稀疏 Token 树（Two-Pass Sparse Token Tree, TSP）：
    • 第一阶段生成贪婪主干序列（Main Trunk），识别出低置信度节点；
    • 第二阶段仅在低置信度节点依据 Top-2 候选分叉生成极窄的侧枝，构建稀疏拓扑树。

在 LibriSpeech 与多种大模型（Llama-7B / Vicuna-13B）评测中，SpecASR 取得了 3.04x ~ 3.79x 的加速，比通用投机解码额外提速 1.25x~1.84x，且 WER 绝对无损。

4. CTC 极速非自回归草稿：Self-Speculative ASR (arXiv:2603.11243)

4.1 核心思想：利用声学编码器做零成本非自回归 Drafter

IBM Research 提出的方案将 Speech-aware LLM 特有的前端 Conformer 编码器顶层 CTC 预测头作为天然的非自回归 Drafter。由于 CTC 可以一次性全并行吐出整句文本假说（耗时 $< 5\text{ms}$），使得 Drafting 阶段的耗时开销几乎完全降为 0。

4.2 三步自适应状态机数学机制

  1. Step 1: CTC 帧熵门控与极速直出
    • 提取 CTC 输出每一帧的后验概率分布 $p_{\text{CTC}}(v \mid t)$，计算帧信息熵：
    • 若全句所有发音帧的熵均低于阈值 $\tau_{\text{CTC}}$（声学特征极度清晰），直接将 CTC 贪婪去重后的文本 $\hat{y}$ 作为最终识别结果，完全绕过 LLM 的任何前向计算。
  2. Step 2: LLM 单步并行似然验证
    • 若存在高熵模糊帧，将 CTC 生成的整句 Token 序列 $\hat{y}$ 作为 Draft 传入 LLM Decoder；
    • 利用 LLM 因果掩码在单次前向（Single Forward Pass）中并行打分所有位置的条件对数似然：
    • 若全部满足，则以单步代价完整接受该 CTC 句子。
  3. Step 3: AR 前缀回退接管
    • 若在索引 $j$ 处首次出现似然低于 $\tau_{\text{SLM}}$，LLM 直接以已验证的前缀 $\hat{y}_{<j}$ 作为 Prompt 上下文，恢复标准自回归解码。

4.3 实验指标与反直觉发现

在 Granite-Speech (1B LLM + 440M Conformer) 架构上，该方案将系统的 Inverse Real-Time Factor (1/RTF) 提升了 4.4 倍。更重要的是，在 High Accuracy 模式下，LLM 校验后的 WER 反而比纯自回归解码更低（达到 5.58% WER），证明了 CTC 与自回归 LLM 之间具有天然的互补纠错效应（System Combination）。

5. 声学对齐漂移机理与校正：AnchorDraft (arXiv:2608.12703)

5.1 痛点发现：Access is NOT Localization

在单模型自投机 ASR（Single-Model Speculative ASR）中，Boson AI 与麦吉尔大学的研究者揭示了一个普遍存在的性能断崖现象：Drafter 生成第 1 个 Token 的接受率很高，但随着 Draft 自回归步数拉长，后续 Token 的接受率发生雪崩式下滑。

论文通过深入测量发现：

  • 尽管 Drafter 在每一步都能读取整段音频的 KV Cache，但它在连续自由展开时迅速丢失了当前生成词与音频时间帧之间的定位能力（Alignment Drift）；
  • 目标大模型（Target）在验证时的 Cross-Attention 峰值与真实音频帧误差中位数仅为 2 帧；
  • 轻量 Drafter 在自由展开数步后，注意力对齐误差中位数迅速扩散至 21 帧（在 100 帧音频中相当于错位了 20% 的时间！），导致后续候选 Token 完全与当前发音错位。

5.2 解决方案：AnchorDraft 高斯引导注意力锚定训练

为了在零额外推理开销（Zero Runtime Overhead）的前提下消除漂移，AnchorDraft 在训练阶段引入了高斯引导注意力损失：

  1. 利用强制对齐工具（MMS-FA）获取训练集中每个 Token $t$ 对应的真实音频中心帧索引 $c_t$；
  2. 构建以 $c_t$ 为中心的归一化目标高斯分布：

AnchorDraft 强迫草稿模块的内部注意力紧密跟随发音时间推进，将深层步长的草稿接受率提高了近一倍，且在完全不改变推理计算图的情况下获得了扎实的端到端加速。

6. 声学离散 Token 粗粒度验证：PCG (arXiv:2511.13732)

在自回归语音合成（TTS，如生成 RVQ / EnCodec 声学 Token）中，传统文本投机解码的精确匹配（Exact Match）过于严苛：在离散声学 Token 空间中，许多不同的 Codebook 索引在感知和发音上属于完全等价或高度相近的声学表征。

Apple 团队提出的 Principled Coarse-Graining (PCG) 通过以下机制革新了 TTS 投机验证：

  1. 声学相似度分组（Acoustic Similarity Groups, ASG）：在 Target 模型 Embedding 空间中，根据余弦相似度将距离极近的 Token 聚类为允许相互重叠的声学相似组；
  2. 重叠感知粗粒度拒绝采样：将每个 Token 的概率质量平摊到其所属的重叠组中，在 Group 级别构建边缘分布并执行拒绝采样；
  3. 收益：在严格数学证明音质（Intelligibility）与音色（Speaker Similarity）无损的前提下，将 TTS 的 Token 接受率提升了 40% 以上，显著拉升了端到端生成吞吐。

7. 工业生产级落地实战指南 (基于 Qwen-Audio 与 CosyVoice)

结合开源工业实践（SpeechSpec 项目在 SGLang / vLLM 上的调优经验），在实际业务生产系统中落地语音投机解码需重点把握以下工程细节：

7.1 ASR 工业落地的三大铁律

  1. 必须禁用 Tree Attention（树搜索）：
    • 生产级测试表明：在 Qwen2-Audio 与 Qwen3-Omni 上，由于 ASR 任务的分支度极低，Top-1 延续序列的命中率已极高。开启 Top-$k$ 树搜索不仅接受长度增长微弱，反而导致 Verifier 单步打分的 KV 计算量成倍暴增，端到端吞吐甚至慢于纯自回归 Baseline。
  2. 模型规模决定 Draft 步长与架构选型：
    • 7B 级别（如 Qwen2-Audio-7B）：Target 前向开销适中，Draft 步长可适当放宽（EAGLE-3 设置 Steps=5，接受长度 4.27，获得 1.73x 加速）；
    • 30B+ MoE 级别（如 Qwen3-Omni-30B-A3B）：Target 激活计算高效，必须严格限制 Draft 步长（Steps=3 最优；若设为 7 步，Drafter 累积延迟会导致加速比从 1.60x 恶化至 1.13x）。在大 MoE 上，单步全并行的 DFlash 全面超越 EAGLE-3。
  3. On-Policy 训练是唯一标准：
    • 严禁使用开源数据集的真实文本标注作为 Draft 的训练标签（Off-Policy）；必须让 Target Verifier 自身在部署采样配置下生成伪标签（On-Policy Regen），否则 Draft 无法拟合 Verifier 的特征分布，吞吐直接损失 25% 以上。

7.2 TTS 工业落地的两大关键突破

  1. 小 Target 模型（0.5B）必须使用并行 Draft（DSpark）：
    • CosyVoice2 等 TTS 系统的 LLM 通常仅为 0.5B 左右，Verifier 计算极轻。若采用 EAGLE-3 等串行自回归 Drafter，Draft 开销与 Verifier 处于同一量级，速度直接降为 0.5x（严重负优化）。
    • 解法：必须采用带 Markov 头的 DSpark 3 层并行架构，在保持 Drafter 极低耗时的同时维持深层接受率在 65%~77%，实现 2.1x ~ 3.1x 加速。
  2. Repetition Penalty 采样冲突与解决：
    • CosyVoice 解码必须开启 repetition_penalty = 1.1 防止音频崩溃。若仅 Target 施加惩罚而 Draft 未施加，Draft 生成的候选会频繁被 Target 拒绝；
    • 解法：在 Serving 内核中对 Draft 的 Logits 施加与 Target 完全一致的 Repetition Penalty 变换函数，使接受长度从 2.49 跃升至 2.98。

8. 总结与落地选型决策全景图

从 Leviathan 纯文本严格拒绝采样出发，投机解码在语音领域的演进经历了“通用自投机 $\to$ 模态感知动态草稿（SpecASR） $\to$ 声学对齐锚定（AnchorDraft） $\to$ 声学 CTC 非自回归极致直出 $\to$ 生产级 Serving 对齐”的完整跃迁。充分利用语音模态的前端声学表征与时域对齐特性，是释放 Speech-LLM 极限推理吞吐的核心钥匙。
