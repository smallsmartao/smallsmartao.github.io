从拒绝采样到 CTC 非自回归引导：Speech 投机解码与推理加速的演进综述

本文最后更新于 2026年8月18日 下午

在大语言模型（LLM）与语音大模型（Speech-LLM / Encoder-Decoder ASR）中，自回归逐 Token 解码（Autoregressive Decoding）每一步都需要从高带宽显存（HBM）中搬运完整权重，使得推理过程严重受限于内存带宽（Memory-Bound）。

投机解码（Speculative Decoding）的核心思想是：利用一个计算开销极低的草稿机制（Drafter）一次性生成包含 $K$ 个候选 Token 的草稿序列（或草稿树），再交由大容量目标模型（Target Model）执行单次前向计算（Single Forward Pass）完成并行验证。

本文围绕“草稿如何生成（Drafting 机制）、目标模型如何验证（Verification 准则）以及针对语音模态特性的针对性改造”这一技术主线，深度解构投机解码从纯文本通用理论到 Speech-LLM / ASR 领域的关键论文演进。

SpecASR (arXiv:2507.18181) 动态声学感知 Drafter（自适应 $K$ 步草稿） 目标大 ASR 模型前向对数概率比对校验 1. 自适应草稿长度：依声学熵动态调控 $K$；2. 草稿循环复用：拒绝时复用未命中但匹配的邻域草稿；3. 两阶段稀疏 Token 树 相比标准 AR 提速 3.04x~3.79x，比传统 SD 提速 1.25x~1.84x
Self-Speculative ASR with CTC (arXiv:2603.11243) 利用声学编码器顶部的 CTC 分支作为非自回归（NAR）Drafter 三步自适应校验：低熵直出 $ o$ 单步 LLM 似然验证 $ o$ 失败回退自回归 Draft 耗时趋近于 0；利用 CTC 帧熵进行置信度门控，跳过简单段的 LLM 验证 RTF 提升 4.4x，WER 相对 AR 仅劣化极小且在部分测试集反向提升
SpeechKV (2025) 配合任意 Drafter（如小模型或多头） 结合 KV-Cache 动态剪枝 进行 Target 投机验证 揭示语音 Cross-Attention 时间局部聚集与静音稀疏性，验证时动态丢弃 60% 冗余声学 KV Cache 显存带宽占用降低 60%，高并发投机吞吐翻倍

1. Leviathan et al. (ICML 2023) —— 投机解码的数学基石

1.1 草稿生成与验证机制

  • 草稿生成（Drafting）：使用一个参数量极小的独立辅助模型 $M_q$（计算延迟远低于 Target 模型 $M_p$），自回归串行前向 $K$ 步，生成候选 Token 序列 $( ilde{x}_1, ilde{x}_2, \dots, ilde{x}_K)$，对应草稿概率为 $q(x)$。
  • 验证机制（Verification via Rejection Sampling）：
    Target 模型 $M_p$ 仅执行一次并行前向计算，得到这 $K$ 个位置在目标模型下的真实输出概率 $p(x)$。对于第 $i$ 个草稿 Token $ ilde{x}_i$：
    • 接受（Accept）：保留该 Token，继续检验下一个；
    • 拒绝（Reject）：一旦第 $n$ 个 Token 被拒绝，后续 $ ilde{x}_{n+1 \dots K}$ 全部丢弃，并从修正残差分布中直接重新采样一个 Token：

1.2 关键理论特性

  • 严格数学无损（Lossless Guarantee）：该算法在数学上证明了最终采样得到的 Token 序列分布与纯粹使用 Target Model 单独逐步采样的概率分布完全严格一致，且每轮迭代期望生成的 Token 数量恒大于 1。

2. Whisper Speculative Decoding (OpenAI / HuggingFace, 2023)

2.1 音频与文本如何参与投机？

  • 特征共享机制：语音输入（80 维 Log-Mel 频谱）仅在前端通过一次计算提取特征。Target 模型（如 Whisper-Large-v3，1.5B）与 Draft 模型（如 Whisper-Tiny，39M）共享完全相同的声学 Encoder 输出特征或 Mel 频谱。
  • 草稿生成：Whisper-Tiny 仅运行其轻量级的 4 层 Decoder，以极快速度自回归吐出 $K=4$ 个候选项。
  • 并行校验：Whisper-Large 将这 4 个 Token 与声学特征进行单步 Cross-Attention 前向，在 Greedy 贪婪解码模式下，只要 Draft Token 与 Large 预测的 Argmax 命中即接受。

2.2 核心收益与瓶颈

  • 收益：在保留 Whisper-Large 顶尖识别率的同时，平均每步接受约 3.2 个 Token，实现端到端 2.0x 提速。
  • 痛点：显存中需同时常驻两个独立的完整模型，且 Tiny 模型的自回归生成依然是串行访存，受限于 GPU 显存带宽争抢。

3. Medusa 与 EAGLE：无小模型的自投机架构 (2024-2026)

3.1 彻底抛弃独立 Draft 模型

为消除常驻小模型的额外显存开销与带宽瓶颈，Medusa 和 EAGLE 提出了自投机（Self-Speculative Decoding）：

  • Medusa（多头预测）：在 Target LLM 顶层并联 $K$ 个单层 MLP 预测头（Medusa Heads），在生成当前 Token 时，单步前向直接预测未来第 $t+1, t+2, \dots, t+K$ 步的多个候选分布，并排列组合构成候选树（Tree Structure）。
  • EAGLE / P-EAGLE（隐状态特征自投机）：针对 Token 级别预测不确定性高的问题，EAGLE 改在 Target 的倒数第二层隐藏状态（Hidden States）上进行特征级自投机。P-EAGLE 进一步将草稿生成改为单步前向并行化预测，完全消除了 Drafter 内部的自回归串行等待。

3.2 树状注意力验证（Tree Attention Verification）

Target 模型利用预先构建的 2D 树状因果掩码（Tree Masked Attention），在单次前向中同时计算候选树中所有分支路径的注意力，一次性找出最长命中路径并提交。

4. SpecASR (arXiv:2507.18181, 2025)

4.1 语音模态特有问题与设计突破

传统文本投机解码在 ASR 任务中常因噪声或生僻词导致 Draft 接受率大幅震荡。SpecASR 基于“ASR 是强音频条件引导（Audio-Conditioned）”的核心观察，提出了三项专为语音设计的机制：

  1. 自适应草稿长度（Adaptive Draft Length）：
    • 监控声学特征在当前时间步的声学信息熵/置信度。声学清晰、低熵区域拉长草稿步长（如 $K=6$）；声学模糊、高熵区域缩短步长（如 $K=2$），避免无效草稿引入额外校验开销。
  2. 草稿循环复用策略（Draft Sequence Recycling）：
    • 当草稿在中间某一位置被拒绝时，传统方案会丢弃后续所有 Token；SpecASR 发现被拒绝的后续 Token 在声学邻域窗口内仍有极大概率与真实发音对齐，因此将其存入候选池循环复用，避免重新生成。
  3. 两阶段稀疏 Token 树（Two-Pass Sparse Token Tree）：
    • 平衡 Draft 阶段与 Target 验证阶段的计算延迟，剪除低概率声学分支。

4.2 实验收益

在标准 ASR 评测集上，SpecASR 相比标准自回归基线提速 3.04x ~ 3.79x，在保持 WER 绝对无损的前提下大幅超越通用投机解码（1.25x~1.84x 额外加速）。

5. Self-Speculative ASR with CTC Drafts (arXiv:2603.11243, 2026)

5.1 CTC 引导的非自回归超轻量草稿

该工作将 Speech 任务特有的声学 CTC 预测器与 LLM 自回归解码深度融合：

5.2 三步自适应解码流程

  1. 第一步（CTC 熵门控）：计算 CTC 输出概率分布的帧熵，若低于设定阈值，直接将 CTC 贪婪解码结果作为最终识别文本，完全跳过 LLM 前向；
  2. 第二步（LLM 单步并行似然校验）：若帧熵高于阈值，将 CTC 生成的整句 Token 序列作为 Draft，送入 LLM 执行单次 Forward，采用放宽的对数似然阈值进行并行校验；
  3. 第三步（回退自回归接管）：若校验失败，LLM 仅需从最长已接受的前缀处恢复标准自回归解码。

5.3 核心指标

在 1B LLM + 440M CTC 编码器架构下，该方案在维持 WER 基本不变（相对劣化仅 12%，部分测试集甚至超越纯 AR）的同时，将 Inverse Real-Time Factor (1/RTF) 提升了 4.4 倍。

6. AnchorDraft (arXiv:2608.12703, 2026)

6.1 发现声学对齐漂移（Alignment Drift）

在单模型自投机 ASR（Single-Model Speculative ASR）中，虽然 Drafter 可以访问完整音频，但随着 Draft 自回归步数拉长，Drafter 的预测质量会急剧下降。

论文通过诊断发现，草稿质量下降的核心不是语言建模能力不足，而是 Drafter 丢失了当前生成的 Token 与音频时间帧之间的对齐位置（Audio Position Tracking）：

  • 目标模型（Target）在验证时的注意力峰值与真实音频帧误差中位数仅 2 帧；
  • 单模型 Drafter 在连续生成数步后，注意力对齐误差中位数迅速扩散至 21 帧，导致后续生成的候选 Token 完全与当前语音错位。

6.2 解决方案：AnchorDraft 对齐锚定训练

  • 提出 AnchorDraft 机制：在训练阶段设计辅助对齐损失，强迫 Drafter 的隐层特征显式跟踪音频交叉注意力的峰值帧位置（Anchor）；
  • 收益：在完全不改变推理阶段计算图的前提下，大幅拉齐了 Drafter 与 Target 的声学对齐精度，使长步长草稿的接受率翻倍，显著提升了端到端推理速度。

总结：Speech 投机解码的技术演进脉络

纵观投机解码在语音大模型上的演进路径，主要呈现三大核心转变：

  1. 草稿机制：从外挂串行小模型 $ o$ 隐状态并行自投机 $ o$ 模态特有 CTC/NAR 极速生成
    • 逐渐摆脱了“小模型自回归”带来的显存带宽浪费，转而利用语音前端天然具备的非自回归（NAR / CTC）能力，使 Draft 耗时逼近于零。
  2. 验证粒度：从严格 Exact Match $ o$ 树状掩码并行校验 $ o$ 声学置信度/似然松弛判定
    • 针对语音存在同音词、口语泛化等模态特点，引入了自适应步长与声学相关性校验。
  3. 多模态协同：显式解决声学对齐与 KV 缓存瓶颈
    • 通过 AnchorDraft 约束草稿阶段的时间对齐漂移，结合 SpeechKV 动态稀疏剪枝，彻底释放了长语音在高并发服务下的吞吐潜力。
