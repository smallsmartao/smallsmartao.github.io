从离散 Token 到原始频谱：Speech–LLM 接口的八篇论文演进综述

本文最后更新于 2026年8月18日 上午

1. 为什么要把“接口”单独拿出来研究

把语音接入大语言模型，表面上像是一个简单的维度匹配问题：语音编码器输出一串向量，再用 projector 映射到 LLM 的 hidden size 即可。八篇论文合在一起看，却会发现接口至少决定五件事：什么信息进入 LLM、声学不确定性是否保留、文本预训练知识是否能被调用、系统是否可以生成语音，以及模块能否替换或复用。

本文覆盖 AudioPaLM、SALMONN、LauraGPT、SLAM-ASR、LegoSLM、Phonemes vs. Projectors、Mel-LLM 与 JSTIP。它们不是简单的时间线迭代，也不是后一篇“淘汰”前一篇，而是在不同约束下回答同一组问题：

  1. 表示问题：用离散语义/codec token、连续 encoder feature、CTC posterior、phoneme，还是原始 log-Mel？
  2. 连接问题：扩展 LLM 词表、训练 Q-Former/MLP、借用 embedding table，还是彻底去掉专用 speech encoder？
  3. 目标问题：只做 ASR，还是同时做翻译、理解、音频描述、增强与语音生成？
  4. 训练问题：冻结 LLM、全参数微调、LoRA，还是改变 speech/text 在训练序列中的相邻关系？
  5. 系统问题：追求统一生成、低成本适配、低资源泛化、模块热插拔，还是训练/推理效率？

本文把论文明确报告的设置和数字称为论文事实；跨论文的共同规律称为综述判断。后者只用于组织证据，不冒充任何单篇论文的结论。尤其要避免把不同数据集上的 WER 直接排名，也不把论文所称的 zero-shot、encoder-free 或 only-projector-trained 扩大解释。

综述判断一：接口不是单一层，而是“表示压缩—坐标对齐—训练暴露—输出解码”的组合。 AudioPaLM 主要改变表示与词表；SALMONN/SLAM-ASR 主要改变坐标对齐；LegoSLM 与 phoneme 路线给坐标加入结构；Mel-LLM放宽前端压缩；JSTIP则指出，即便表征已经送进 LLM，训练序列仍可能阻断文本先验。

综述判断二：离散与连续不是非黑即白。 LegoSLM 的输入是连续向量，却受 token embedding convex combination 约束；phoneme 方法是离散序列，却以 K=8 路径采样传播不确定性；LauraGPT 同时采用连续输入与离散输出。真正需要比较的是：接口保留哪些信息、加入何种结构先验、在多少配对数据下可学。

第一阶段：统一离散词表——AudioPaLM

4. AudioPaLM：把音频变成 LLM 可以自回归预测的整数

4.1 问题、接口与系统边界

AudioPaLM 的目标不是只提高 ASR，而是让 decoder-only LLM 同时“听”和“说”。文本由 SentencePiece 表示；语音经量化器得到 25 Hz 离散 token。若文本词表大小为 $t$、音频词表大小为 $a$、embedding 维度为 $m$，原文本 embedding 为

checkpoint surgery 后扩成

前 $t$ 个 ID 保持文本含义，新增 ID 对应音频 token；Transformer 主体不变，输入输出 embedding 共享。顶层模型由 PaLM-2 8B 初始化，新增音频 embedding 置零，并对整个模型微调。论文明确指出，冻结大部分旧参数的方案经验上不可行。

音频 tokenizer 有三种：多语 w2v-BERT embedding+k-means、USM-v1 中间层量化、以及带辅助 ASR loss 并为多语优化的 USM-v2。w2v-BERT 与 USM-v1 均为 25 Hz、1024 词表；论文没有在相应小节给出 USM-v2 精确词表大小。25 Hz 下，一个文本 token 约对应 6—8 个音频 token，这说明统一词表并不等于统一序列效率。

输出语音时，AudioPaLM 先生成语义 token，再由 AudioLM 或 SoundStorm 生成 SoundStream codec token，最后卷积解码为波形。SoundStorm 非自回归并行迭代，论文称相对 AudioLM 快两个数量级；顶层 S2ST 结果采用 SoundStorm。模型以 3 秒 voice prompt 保留说话人和声学条件，不足 3 秒时重复补足。

4.2 任务表达、目标与训练数据

模型把 source audio、transcript、translated transcript、translated audio 组合成 ASR、AST、S2ST、TTS、MT 五类任务。任务由普通文本 tag 指定，如 [ASR French]、[S2ST English French]。combined task 会在一次自回归轨迹中依次生成中间结果，例如先源转写、再译文、再目标语音，而不是调用多个独立模型。

默认优化使用 Adafactor、恒定学习率 $5\times10^{-5}$、dropout 0.1，只在输出位置计算 loss。PaLM-2 对照改为 dropout 0.2，学习率从 $10^{-4}$ warm-up 后指数衰减至 $10^{-5}$。论文没有提供统一 batch size、总 step 与硬件数量，不能补写。

训练 mixture 由 SeqIO 组织。AST mixture 含 CVSS/CoVoST2、VoxPopuli、CommonVoice 11、Conversational EsEn、YouTube ASR 以及 WMT/TED MT；S2ST mixture 进一步加入 TTS 合成数据、PaLM-2 翻译后再合成的目标语音和联合任务。论文 Table 1 的小时数是经过 mixture balancing 后模型实际看见的音频：例如 AudioPaLM S2ST 看见 CVSS/CoVoST2 1.4k h、VoxPopuli S2ST 5.4k h、WMT/TED TTS 26.2k h、PaLM MT TTS 10.9k h，而非原始语料的天然规模。

4.3 结果：翻译和生成强，ASR 并非全面最优

顶层结果中，AudioPaLM-2 8B AST 在 CoVoST2 上为 37.8 BLEU；AudioPaLM 8B S2ST 为 36.2 AST BLEU / 32.5 CVSS ASR-BLEU / 16.0 VoxPopuli WER。同表中 MAESTRO 的 VoxPopuli WER 为 8.1，说明论文证据支持的是“语音翻译强、识别有竞争力”，而不是所有语音任务均最优。AudioPaLM-2 的级联 ASR+翻译为 39.0 BLEU，又说明端到端统一性与单项最优不是同一目标。

FLEURS zero-shot AST 中，AudioPaLM-2 在 29 个已见 AST 语言上为 28.6 BLEU，在“只见过该语言 ASR、没见过 AST”的语言上为 20.7；AudioPaLM 对应为 22.4 和 10.0。这里的 zero-shot 是未见该语言对的 AST，不是从未见过该语言。

语音质量实验共覆盖 21 语言×10 输入。较早的 AudioPaLM+AudioLM 系统主观 MOS 4.44、音色 SMOS 4.00、客观音色相似 0.40、声学一致性 0.81，均高于表中 Translatotron 2；但这不是顶层 SoundStorm 版本，必须区分。

4.4 消融给出的接口证据

AudioPaLM 的九组设计实验比单个最好数字更有解释力：

  • AST-only 16.0 BLEU，加入 ASR 后 18.5，显示共享监督有益。
  • 1B/8B 从零训练仅 6.5/6.9 BLEU、WER 66.0/63.3；PaLM 8B 初始化达到 18.4 BLEU、40.2 WER，直接证明文本 checkpoint 的价值。
  • w2v-BERT、USM-v1、USM-v2 依次为 15.2/50.1、18.5/40.2、26.9/22.3（BLEU/WER），tokenizer 是决定性瓶颈。
  • combined task 把 USM-v2 AST 从 26.9 提到 30.5 BLEU，却把 WER 从 22.3 变成 25.3，说明显式中间文本有任务间代价。
  • 加入 S2ST 后，AST 30.5→27.8、WER 25.3→27.1，同时获得 24.2 S2ST ASR-BLEU；统一能力存在容量/mixture trade-off。
  • AudioLM→SoundStorm 使 CVSS S2ST 31.2→32.5。
  • PaLM-2 从 128M→1B→8B 时，BLEU 18.3→31.6→37.8，VoxPopuli WER 16.4→11.7→9.8，规模仍然重要。

4.5 限制

论文明确指出性能受离散 tokenizer 质量制约，且全模型微调无法结构性保证保留原文本能力。目标语音中有大量合成数据，输出还依赖 SoundStorm/codec 链路；PaLM、USM 等关键资产的开放性有限。生成式 benchmark 与指标也不成熟。AudioPaLM由此建立了统一离散接口的上限，同时清楚暴露了量化、长序列与训练成本问题。

5.2 三阶段训练与数据

第一阶段以 LibriSpeech 960 h、GigaSpeech 1000 h 做 ASR，以 WavCaps 2800 h 加 AudioCaps、Clotho 做 AAC，建立跨模态对齐。第二阶段 instruction tuning 覆盖 12 类任务、约 4400 h/2.3M samples：ASR、英中 AST、AAC、phoneme recognition、emotion、music caption、overlapped speech recognition、speaker verification、gender、speech/audio/music QA。SQA/AQA/MQA 的问题由 ChatGPT 依据 caption 或 label 生成。

第三阶段 activation tuning 极小：先降低 LoRA scale，让模型根据 12 段音频生成 12 个故事，再对每个故事做一次 teacher forcing，共 12 steps，同时更新 Q-Former 与 LoRA。其目的不是再学一种普通任务，而是纠正 instruction tuning 后对短、确定、强对齐输出的偏置。

6. LauraGPT：连续输入、离散输出的非对称接口

6.1 为什么输入与输出不必对称

LauraGPT认为输入理解和输出生成的需求不同。输入音频经 log-Mel 与 32 层 Conformer，LFR 后每 60 ms 一帧连续表示；输出音频则由 codec 第一层 RVQ 离散 token 表示。统一样本写成 [input embeddings, task ID, output tokens]，只在 target 上计算

backbone 是 Qwen-1.8B，总模型约 2B；audio encoder 与 Qwen 均从预训练 checkpoint 初始化，除独立 codec vocoder 外联合优化。

codec 类似 EnCodec：五个 stride convolution blocks [8,5,4,2,2]，32 个 RVQ quantizer，每个 codebook 1024，单组 25 Hz。自回归 LLM 只预测第一 quantizer，避免把 32 组全部展开成极长序列。一步 codec vocoder 不逐层分类其余 index，而是一次回归 32 层 codec embedding 之和：

预测 embedding 送入冻结 codec decoder。TTS 时 predictor 还看文本与 prompt audio；增强时看 noisy speech feature。这一设计把离散 token 丢掉的细节交给条件 vocoder 恢复。

6.2 七任务、三阶段训练

七个 basic tasks 为 ASR、SLU、speech-to-text translation、SER、AAC、speech enhancement、TTS。重采样后分别约 24.2M、1.2M、2.2M、0.3M、1.3M、5.3M、5.0M samples。翻译还加入约 2000 h 机器翻译语音文本和 ParaCrawl v9 14M 双语句对；增强数据由干净语音混合 FSD50K 噪声（SNR 2—15）并卷积 RIR，约 6000 h。

三阶段均为 supervised multitask：先全任务、峰值学习率 $5\times10^{-4}$；再聚焦 TTS/SE/AAC/SER/SLU，$2\times10^{-4}$；最后再全任务，$10^{-4}$；每阶段 warm-up 10K。vocoder predictor 用 TTS+SE，Adam、峰值 0.001、warm-up 25K，codec decoder 冻结。

复杂 S2ST 实际是模型内部任务级编排：先以 <S2TT> 生成译文，再以 <TTS> 合成目标语音；个性化版本还串联 ASR 文本、译文和原始语音 token。它不同于 AudioPaLM 的单次联合 S2ST 轨迹，仍可能累积级联误差。

6.3 结果与关键消融

任务结果具有明显的“统一但非全面最优”特征：AISHELL-1/2 CER 为 1.8/3.2，优于 comparable MMSpeech 1.9/3.9；LibriSpeech clean/other WER 4.4/7.7，落后 Whisper-Large-v2 2.5/4.9。CoVoST2 En→Zh 38.5 BLEU，强于表中 25.4 baseline；AAC SPIDEr 0.15 低于 ensemble 0.21；SE 为 PESQ 2.97、STOI 88.0、WER 15.94；LibriTTS TTS 为 WER 8.62、SECS 0.91、MOSNet 3.26。论文明确警告 SOTA 行不可公平比较，且结果是 single runs。

连续输入的证据很强：把输入也改为前 4 组 quantizer flatten 的 100 Hz Discrete IO 后，AISHELL-1 CER 1.8→7.1，LibriSpeech other WER 7.7→24.0，CoVoST2 BLEU 38.5→5.0，SE WER 15.94→53.97。因此该论文支持“理解侧不宜过早粗粒度离散化”，但不能直接推广到所有 tokenizer。

一步 vocoder 相对 multi-step 在 SE 上 PESQ 2.55→2.97、WER 19.32→15.94。多任务相对单任务使 SLU-F1 51.0→73.5、AAC SPIDEr 0.11→0.15；SER WA 0.508→0.507 略降，但 UA 0.221→0.312。Conformer 中 BN→LN 使循环输出比例 86.0%→4.6%、PESQ 1.27→2.97，仍未完全消除循环。无预训练初始化时，LibriSpeech other WER 17.6、CoVoST2 BLEU 12.2；预训练后为 7.7、38.5，文本/声学初始化都是关键。

6.4 限制

LauraGPT 需要除 vocoder 外全参数多任务微调；未系统测富资源任务的单/多任务差异，也未深入评估文本 LLM catastrophic forgetting。生成强依赖 audio tokenizer，不同 tokenizer 未系统比较；自然语言 instruction following、in-context learning 与覆盖 speech/non-speech/music 的开放式能力仍是愿景。它的贡献不是“全任务 SOTA”，而是给出连续输入、离散输出与一步细节补全的完整工程折中。

9.4 限制与谱系意义

10. Mel-LLM：LLM 能否直接读取 log-Mel？

10.1 “Encoder-free”的准确含义

Mel-LLM基于 Phi-4-MultiModal，移除专用 Transformer/Conformer speech encoder blocks，让 LLM 更直接接触 80 维 log-Mel。但它仍保留 12.6M 参数的 NeMoConv 做 temporal downsampling，以及 12.6M projection；所以 encoder-free 应理解为没有主 speech encoder blocks，而不是波形直接进入 LLM或零前端。

log-Mel先用训练集统计量做 MVN，可选卷积压到 $T/r$。概念式为

方法文字称 single linear layer，但主配置表实际为 2-layer MLP 1024→3072→3072，应以后者为实验事实。Phi-4-MM有 32 层、hidden 3072；原 LLM layers、norm、embedding、LM head 冻结，rank-320、$\alpha=640$ 的 LoRA 可训练，约 503M 参数。主配置 8×下采样、12.5 Hz，训练速度为 encoder baseline 的 1.57×；这是训练速度，不是推理延迟。

10.2 数据与优化

OpenASR mixture 约 31M utterances、64k h，全部为公开英文语音，含 LibriSpeech 960h、GigaSpeech 10k h、MLS English 44k h、SPGISpeech 5k h，以及 Common Voice、VoxPopuli、TED-LIUM、AMI、Earnings-22、FLEURS。扩展理解 mixture 为 55.3M weighted examples，涵盖 speech QA、音频/音乐指令、speaker、emotion 与 AudioSet/FSD50K/AudioCaps/Clotho 类数据；遵循既有 train/eval split，但并非完全未见任务 family。

训练使用 16×H100、ZeRO-1、AdamW、峰值 $10^{-4}$、linear warmup-decay、9000 warm-up steps、effective batch 512，数据迭代三次。生产规模实验使用约 10×匿名内部数据，只迭代一次，但未给绝对小时。TTS 用 Libriheavy 50k h、5 epochs，默认输入 projection 与 Mel head dropout 0.5，KL/stop/flux 权重 0.05/1.0/0.5。

10.3 ASR、速度与规模结果

旧版 8-set OpenASR 平均 WER 中，Whisper-Large-V3 7.44，Phi-4-MM 原系统 6.14，带预训练 encoder 完整微调 5.61，random-encoder baseline 6.97；Mel-LLM 使用 Phi 初始化 LoRA 为 7.12，random LoRA 为 7.44。故它与随机 encoder 基线相近并具速度优势，但明显落后完整预训练 encoder 的 5.61。

10.4 声学线索与语义锚定的交换

相比 Phi-4-MM，Mel-LLM 在 IEMOCAP 40.69→66.16、gender 92.57→97.73、WavLLM speaker 76.64→87.98、MMAU-mini 50.70→54.10；加 ASR init 后 IEMOCAP 72.36、speaker 92.10、GTZAN 53.55。更直接的频谱访问有利于情感、说话人、性别和音乐等声学/副语言线索。

相反，MMLU-speech 从 Phi-4-MM 53.12 降到 Mel 41.30、Mel+ASR 36.47，而 text MMLU 只从 61.00 降到 58.68/56.73。论文将其概括为 acoustic access 与 semantic anchoring 的权衡。由于系统数据与适配并非完全一致，不能把全部差值只归因于移除 encoder，但“原始声学更丰富不等于语音推理更强”是关键警示。

TTS 更能说明成熟度：latent diffusion baseline WER/UTMOS 4.2/3.41；Mel-LLM no-norm 为 11.03/3.10，MVN 为 14.75/3.25；random init 虽收敛却无可听输出。连续 Mel 生成只是 proof-of-concept，不是高质量统一生成方案。

10.5 限制

Mel-LLM仅测英文；大公开数据设置仍落后 pretrained encoder；知识密集 spoken QA 是明显瓶颈；10×实验缺少同规模 encoder 对照；理解 mixture 与测试任务 family 相关；训练/推理显存、实际 latency 与长音频稳定性未系统报告。它最重要的价值，是把“speech encoder 是否不可或缺”从架构教条变成可缩放验证的问题，并暴露 semantic anchor 这一新瓶颈。

ASR-only 的 conversation/dictation TER 23.63/11.06，medical/banking EER 7.97/11.57，MMLU T2T/S2T 43.01/35.68，SQA T2T/S2T 9.41/0.05。只加 interleave 后，TER 22.65/10.81，EER 7.32/11.29，MMLU 51.26/51.77，SQA 45.37/41.92。Medical EER 相对改善 8.16%，且 speech/text behavior 接近。

ASR+PubMed 但无交错时，MMLU T2T 提到 64.10，S2T 仅 43.77；加入交错后 T2T 64.16、S2T 58.98，medical EER 7.49→6.87。这与“文本知识已在模型中，但普通 ASR 条件下不可充分访问”的假设一致，仍不是底层机制的因果证明。

TTS-transcription 不交错为 medical EER 7.85，加交错为 6.81，与直接 TTS-pairs 的 6.86 接近。这只说明本文医疗设置中有机会减少 TTS 依赖；最佳 JSTIP 仍组合 ASR、Interleave、TTS-Interleave、PubMed、TTS-transcription，达到 6.60，相对 ASR-only 改善 17.2%。

粒度消融中，Word-IL EER 7.64、MMLU gap −6.89；Segment-IL silence 7.79/−4.45，silence+punctuation 7.69/−0.77；Mixed-IL silence+punctuation 达 7.32/+0.61。因此在单一粒度里 Word-IL 的实体收益更大，段级更缩小模态 gap，混合配方兼得；这是功能归纳，不是因果分解。

外部参考中 JSTIP medical EER 6.60，优于 Whisper Large-V3 6.94、Qwen3-ASR-1.7B 6.67，低于 Qwen3-Omni-30BA3B 5.84、Voxtral-Small-24B 6.04；banking 10.75 也不占优。模型规模、数据、prompt、decoding 不同，只能作 external reference。

11.5 限制

数据、评测与 backbone 大量内部化；word alignment error 会直接污染 span，替代 aligner 未测；只用 deterministic alternation；仅英文；实体测试小且时长记录可疑；没有训练成本、统计方差和完整复现配方。SQA/MMLU只支持 knowledge-access 解释，不是 interleave→entity gain 的严格中介证明。

JSTIP对整个谱系的修正是：speech-language interface 不止是 projector 的函数形式，还包括模型在训练时看到了哪些跨模态条件分布。 一个几何上已对齐的 embedding 接口，仍可能在行为上保持 speech/text 两套割裂的生成模式。

13. 逐篇实验协议、指标口径与复现边界

这一节不再重复架构主线，而是把八篇论文容易在二次转述中丢失的实验条件集中列出。它们决定数字究竟回答什么问题，也决定不同系统能否横向比较。

13.1 AudioPaLM：数据 mixture、指标和九组设计变量

AudioPaLM 的数据表不能直接解读成“收集了多少小时”。表中数字是经过 SeqIO mixture balancing、有限训练步之后模型实际看见的小时数。AudioPaLM AST 与 AudioPaLM-2 AST 分别看见 CoVoST2/CVSS 0.9k/0.9k、VoxPopuli ASR 1.6k/1.6k、VoxPopuli S2ST 6.7k/3.9k、CommonVoice 3.4k/2.0k、Conversational EsEn 2k/2k、YouTube ASR 13k/7.6k。S2ST 配方则看见 CoVoST2/CVSS 1.4k、VoxPopuli ASR 1.6k、VoxPopuli S2ST 5.4k、CommonVoice 0.9k、Conversational 2k、WMT/TED TTS 26.2k、PaLM MT TTS 10.9k。后两类目标语音是合成数据，比较直接语音监督时不能忽略。

不同任务的指标也不相同。CoVoST2/FLEURS AST 用 SacreBLEU corpusBLEU；VoxPopuli ASR 用忽略大小写和标点的 JiWER WER；CoVoST2 对日语、中文报告 CER；CVSS S2ST 先用固定 ASR 转写生成语音，再算 ASR-BLEU。语音质量还分无参考客观 MOS、主观 MOS、speaker embedding cosine、主观 SMOS和录音识别 embedding 的 acoustic consistency。这些指标分别反映可懂度、自然度、音色和声学条件，不应合并成一个“音质更好”。主观实验对 210 个输入、三个系统共 630 个输出进行评价，每个输出每项研究收集 10 个评分，即每项 6300 ratings；输入还预筛 objective MOS 不低于 3.0。

扩数据实验呈现清楚的域迁移现象。只用 CoVoST2/CVSS 时，VoxPopuli WER 可高于 160，加入 public speech 后显著下降；继续加入 YouTube、WMT/TED 与 PaLM MT TTS，AST/S2ST逐步提高，但不同 ASR 测试并非单调同步。PaLM 与 PaLM-2 对比也不是所有指标同向：PaLM-2 在翻译上稳定提高，部分 CoVoST2 ASR WER却变差。因此，底座升级主要证明更强文本翻译先验进入 AST，不证明声学识别无条件变好。

复现时还要记录两个系统边界：第一，acoustic model 在 Multilingual LibriSpeech 上训练，三秒 prompt 同时表示为语义 token 与 SoundStream token；第二，扩大数据早期消融使用 AudioLM Stage 2/3，而最终顶层 S2ST使用 SoundStorm。若只写“AudioPaLM生成语音”，会把语义模型与外部声码生成器的贡献混在一起。

13.2 SALMONN：十五项任务并非同一种泛化

SALMONN 的十五项测试按三层组织。Level 1 是训练中出现的任务；Level 2 是未直接训练的 speech-grounded NLP，包括英德/英日翻译、keyword extraction、spoken-query QA和 slot filling；Level 3 是作者设计的 Story 与 speech-audio co-reasoning。因训练中已有 ASR、AST、问答、描述等监督，Level 2/3 更适合称“未按相同任务格式监督的组合与指令泛化”，不能笼统称开放世界零样本推理。

激活前后的完整任务变化揭示取舍。英中 BLEU4 34.4→33.1；AAC METEOR/SPIDEr 25.6/47.6→24.0/40.3；PR PER保持4.2；emotion accuracy 0.63→0.69；music caption BLEU4/RougeL 3.5/22.1→5.5/21.8；speaker verification 0.93→0.94；英德翻译 19.7→18.6，英日 22.0→22.7；keyword accuracy 0.30→0.32；slot filling accuracy/遵循率 0.33/0.77→0.41/0.99。activation tuning 对开放输出帮助显著，却不是所有已训练任务的 Pareto improvement。

遵循率的实现本身带有任务规则。SQQA与slot filling中，如果输出与音频问题的 WER 小于30%，模型会被判为仍在做 ASR、没有遵循新指令；Story 最多生成200 tokens，少于50 words 判未遵循，diversity 只是不同词数而非故事质量；SAC由GPT-3.5根据问题、背景caption和输出判断遵循与正确性。SQQA与keyword语音由商业TTS合成，SAC又是内部数据。因而0.50 SAC accuracy不能与人工公开大样本的通用推理准确率等同。

模型的 window Q-Former 还体现了时长复杂度折中。全局 Q-Former 若固定压成少量 token，长音频中的局部时间信息容易拥挤；逐窗输出随时长增长，更适合 ASR，但也增加 LLM context。30秒得到88 token的数字依赖 $L=17,N=1$ 和50Hz输入，不是所有 SALMONN 配置的通用压缩率。双编码器各自冻结，意味着33M可训练参数只是适配阶段成本，不能把 Whisper和BEATs先前训练成本从系统能力来源中删除。

13.3 LauraGPT：七任务的输入输出形态并不相同

LauraGPT 所谓统一，是统一为自回归任务表达，不是所有任务共享完全相同的模态路径。ASR、SLU、S2TT、SER与AAC以音频连续表示作为输入、文本token作为输出；TTS以文本为输入、第一层codec token为输出；SE则由 noisy continuous feature 产生目标audio token，再由有条件vocoder补齐细节。task ID决定输出词表区域和解码目标，输入与task-token位置不计损失。

其可比结果还应按任务逐项阅读。SLURP intent accuracy/SLU-F1 为87.9/73.5，对照为85.3/74.6，说明一个指标提高、另一个略低；BSTC中英翻译17.8，对照级联18.2，而CoVoST2英中38.5显著高于对照25.4；MELD的WA/UA/WF1为0.507/0.312/0.492，对照0.535/0.268/0.480，也不是单向领先。增强的PESQ 2.97略高于CMGAN 2.95，但WER 15.94和STOI 88.0弱于12.29和91.0。统一模型在不同指标上具有不同优势，不能用“多数任务超过baseline”替代逐项事实。

codec 的32层RVQ只在独立codec训练中全部存在；主LM只预测第一层。一步vocoder回归32层embedding总和，而不是恢复每一个离散index。这减小自回归长度，却使细节恢复依赖条件predictor。Discrete IO对照把前4个quantizer flatten到100Hz，它同时改变表示连续性、信息量、序列长度和训练难度，所以结果强烈支持当前实现中的连续输入，却不能严格隔离“离散”这一个变量。

初始化与归一化消融提供了工程警告。把Conformer batch norm改为layer norm后，循环比例仍有4.6%，意味着生成退化只被缓解。没有预训练初始化时AISHELL-1/2 CER 4.3/6.0、LibriSpeech clean/other 8.3/17.6、BSTC/CoVoST2 BLEU 8.4/12.2；初始化后相应为1.8/3.2、4.4/7.7、17.8/38.5。增强PESQ只从2.88到2.97，作者因而推测文本预训练对文本输出任务帮助更明显；这是由任务差异支持的推测，不是把收益精确分解给Qwen或audio encoder的因果实验。

13.4 SLAM-ASR：所谓“只训 projector”必须限定训练阶段

最终HuBERT X-Large已在LibriSpeech-960上做过ASR fine-tuning，随后才在Speech–LLM连接阶段冻结。因此，“最终连接只训练约一个MLP”是事实，“整个系统没有训练speech encoder”则是错误。候选encoder预训练量也不同：HuBERT/WavLM Base来自LibriSpeech 960h，HuBERT Large约60k h LibriLight，WavLM Large约94k h，Qwen-Audio与Whisper又有不同数据来源。encoder比较揭示模块选择，但不是等预训练预算实验。

基础组合表仍有值得保留的尺度规律。Whisper-tiny配TinyLLaMA raw/chat为12.72/21.64与9.55/21.01；Whisper-small配LLaMA-2 raw/chat为6.41/10.88与4.51/8.94；Whisper-large配LLaMA-2 raw/chat为3.01/7.15与2.72/6.79。encoder增大总体改善，chat模型多数更好，但收益会随组合变化。最终Vicuna projector约21.50M参数；TinyLLaMA组合为17.31M、Phi-2为18.35M，projector大小随输入/LLM维度改变，并非固定参数预算。

与传统系统的表格还包含ContextNet 2.1/4.6、Conformer 2.1/4.3、Branchformer 2.4/5.5、Zipformer 2.0/4.4；加入in-domain LM的最好数字约1.9/3.9。SLAM-ASR为1.9/3.8，同时未使用这些specialist中的SpecAugment、speed perturbation、EMA和in-domain LM重打分。这是其方法简洁性的有力证据，但传统系统与LLM系统的预训练、推理内存和延迟并未等控。

训练曲线的冻结消融也不能简单解释为“微调永远有害”。在该设置中，可训练encoder使原有表征在projector尚未对齐时持续漂移，优化更难；若采用分阶段解冻、不同学习率或正则，结果可能不同，论文没有覆盖。正式PDF没有可见Limitations章节；源码中被注释掉的大推理成本和多语未来工作只能作为作者草稿旁证，不能当作正式论文陈述。

13.5 LegoSLM：接口模块性的必要条件

LegoSLM的主设定要求CTC输出包含与Gemma相同的256K token再加blank。这个巨大CTC词表让 $Eo_t$ 可以直接进入Gemma坐标，却也把词表设计成本放到encoder端。16,384词表实验没有直接乘Gemma embedding，而是增加随机初始化table并随LLM训练，所以它证明的是“可通过小型额外映射容纳词表不一致”，不是无需训练的任意词表兼容。

AEC baseline把 $n=1,5,10$ 的候选用 <sep> 拼接；在MLS/LBS上分别为8.9/8.0、8.0/6.5、7.8/5.7。增加N-best持续改善，说明语言模型确实可利用候选不确定性，但硬候选只保留有限路径。Lego把每帧完整分布压成一个期望向量，计算紧凑，却也可能让不同多峰分布映射成相近期望；论文没有专门测这种posterior collision。TopS结果说明前100项已足够当前任务，但不代表所有语言或噪声场景都只需100项。

AST中的接口含义也值得区分：encoder posterior对应源语言token embedding，而Gemma生成目标语言文本。Oracle text input为36.5/30.1/31.8 BLEU，LegoSLM*为25.8/21.1/21.1，仍有明显speech-interface差距。en→de切换encoder并为各配置选最佳温度时，Lego为20.9/22.4/18.7，AEC-10为20.9/22.3/18.4，二者接近；SP只有2.8—4.0。模块替换优势很强，但AST最好点依赖温度选择。

训练前后的可解释性诊断中，LegoSLM* log perplexity 4.8→0.1、next-token accuracy 25.2→97.7%；SP训练前perplexity 116.2、accuracy 0；AEC-10训练前1.0/87.4。这个排序恰好对应接口结构强弱：硬文本最接近LLM，token-simplex期望居中，自由连续projector最陌生。训练后Lego能超过AEC的最终WER，则说明保留软声学信息的价值。该诊断是在当前tokenizer与数据上的相关证据，不是通用的接口距离度量定理。

13.6 Phonemes vs. Projectors：公平比较仍有剩余变量

LibriSpeech使用CMUdict转IPA，并训练Phonetisaurus补全词典；Tatar通过Phonetisaurus与预训练LanguageNet G2P生成词内IPA。全部转写先小写并去除与发音无关的标点。mono-phone删除相邻phone之间空格，形成连续phoneme string；BPE-phone保留词边界，再学习merge。因两者tokenization和边界信息不同，BPE收益不能只归结为“更大音素单元”。

projector的Pr-Stage1与Pr-Stage2均能继续降低WER。Whistle-small从7.43/14.72到5.94/12.66，mono-phone fine-tuned Whistle从5.38/10.81到4.11/9.18；WavLM-base从4.10/9.18到3.08/7.66，mono-phone fine-tuned WavLM从4.11/8.35到3.03/7.02，BPE-phone fine-tuned WavLM从3.57/7.69到2.85/6.79。这表明LLM LoRA不是可有可无的后处理，phoneme supervision也主要改善困难集。

最强E8的1.97/3.78与外部系统只是非严格横比。论文列出的Q-Former+Vicuna-13B为2.28/5.20、SALM 2.30/4.80、SLAM-ASR类2.10/4.26，而更强HuBERT-LoRA+adapter+Vicuna-LoRA可到1.78/3.62。作者明确说backbone、规模与recipe不匹配，因此E8用于contextualization，不构成SOTA声明。

低资源Tatar虽共享同一个冻结encoder，接口训练过程仍不同：projector学习连续映射，phoneme侧借用Whistle-large原有phoneme预训练与显式IPA文本。结果准确回答“在已含目标语言的多语phoneme encoder上，20h目标ASR用哪种桥更好”，但不回答完全未见语言、无G2P资源、code-switch或副语言任务。未来提出去掉pronunciation lexicon、端到端联合优化和统一discrete/continuous bridge，恰好说明当前方法仍依赖外部语言资源。

13.7 Mel-LLM：质量、速度和semantic anchor必须三者同时报告

OpenASR八个旧测试集的逐项结果显示不同域差距不均匀。Mel-LLM Phi-init在AMI/Earnings22/GigaSpeech/LibriSpeech-clean/other/SPGISpeech/TED/VoxPopuli上为12.91/12.99/10.95/1.70/4.83/2.28/3.55/7.76；完整预训练encoder微调为11.16/9.57/9.45/1.32/2.95/1.70/2.70/6.03。encoder-free在LibriSpeech-other和Earnings22上的损失尤其明显，平均值会掩盖域差异。OpenASR后来移除了TED-LIUM，但论文数字生成于移除前，复现必须使用同一旧版八集口径。

理解评测的指标实现也不完全统一。ESC-50、IEMOCAP、gender、GTZAN、speaker、MMAU和MMLU用标准化label/choice匹配，invalid算错；age提取首个数值或区间中点，非数值输出invalid且被排除。因此age MAE与分类accuracy不能按同一invalid政策比较。Gemma基线在IEMOCAP、age、MMAU、MMLU-speech上的invalid比例分别为71.07%、96.81%、29.00%、14.89%，低分部分来自格式失败。

Mel+ASR init并非在所有任务都提高：ESC-50 67.85→67.00、age MAE 8.39→7.56、IEMOCAP 66.16→72.36、GTZAN 46.85→53.55、MMLU-speech 41.30→36.47。ASR初始化强化某些声学分类与语音模式，却进一步损害知识型spoken task，显示semantic anchoring不是简单增加ASR监督即可解决。

TTS消融同样不能只看UTMOS。no normalization为WER 11.03/UTMOS 3.10，MVN为14.75/3.25：感知质量提高，可懂度下降；dropout 0.1变体恶化到85.51/1.38；fix-KL与sigma-VAE为12.65/3.22和18.07/3.29。连续Mel AR对初始化、归一化和潜变量约束敏感。论文未来提出native speech-text joint training、text distillation、teacher-encoder supervision与更强latent generation head，说明直接频谱入口仍需语言锚定与专门生成建模。

13.8 JSTIP：主结果中的每一类数据回答不同问题

JSTIP的主表把ASR、Interleave和Text三类开关分开。ASR-only是底线；ASR+PubMed检验直接混文本；ASR+TTS-pairs检验增加合成音频配对；ASR+TTS-transcription检验只加入对应领域文本；各自再加Interleave，才回答交错条件分布是否额外有效。不能把所有“+Interleave”行当作同一个模型，也不能从Best配方中分离出单一组件的独立贡献。

完整主表还显示通用TER没有为实体指标牺牲。ASR+PubMed从23.32/10.81加交错到22.35/10.74；ASR+TTS-pairs从22.71/10.73到22.22/10.54；ASR+TTS-transcription从23.69/11.27到22.30/10.49。交错通常同时改善conversation/dictation TER、entity EER和S2T知识指标，但不同数据配方幅度不同。

MMLU采用五样本提示，在A/B/C/D四个next-token选择上评估，随机为25%；模态gap定义为S2T减T2T，越接近零只表示同一模型的speech/text行为更一致，不意味着绝对知识更强。Mixed-IL使51.77略高于51.26，+0.61很小且无方差，最稳妥表述是“接近持平”，不是语音推理反超文本。SQA由LLaMA-QA、TriviaQA、WebQA的UltraEval-Audio子集平均而来，受prompt、decoding和answer normalization影响，只是支持性诊断。

word alignment来自HMM hybrid系统。失败utterance被删除，却没有按confidence筛选，因而错边界会把不匹配的speech/text片段放在相邻位置。silence+punctuation让短段更集中并改善结果，但图中没有标注可读取的均值或中位数。随机交替、按word type选择模态、不同aligner和置信度加权都留作未来工作。

把JSTIP与Mel-LLM并列时尤其需要约束语气：前者保留强Conformer，后者移除主encoder；两篇没有联合实验。可以提出“interleaving也许缓解raw-Mel semantic anchoring”的未来假设，却不能把两篇独立证据拼成已经验证的组合系统。

14. 八篇论文共同给出的四条技术结论

14.1 越早压缩，越需要确认任务所需信息没有被扔掉

AudioPaLM 的 tokenizer 消融、LauraGPT 的 Discrete IO 退化、Mel-LLM 的副语言任务提升，共同支持这一综述判断：ASR 所需的词汇信息、情感/说话人所需的声学细节、TTS 所需的波形细节并不相同。统一接口若在入口处做单一路径粗量化，会把后续模型容量无法恢复的信息提前删除。反过来，保留 100 Hz Mel 虽质量更好，却使训练速度只有 encoder baseline 的 0.33×；信息保留不是免费的。

14.2 结构先验可以降低跨模态坐标的样本复杂度

SLAM-ASR证明强模块在匹配域内只需小 MLP；LegoSLM的热替换与 Tatar phoneme 结果则说明，自由 projector 在域迁移或低资源条件下可能缺少锚点。CTC token posterior、IPA、word boundary、BPE-phone 都是在接口中注入“这段声音大概对应哪些语言单元”的结构。它们并未证明结构化离散接口普遍优于连续接口；更准确的结论是：连续接口也可从结构化监督受益。

14.3 文本 LLM 的知识有三个层级：存在、对齐、可调用

AudioPaLM 的 scratch 对比证明文本初始化提供能力；SLAM-ASR说明冻结 chat LLM 可以充当强语言模型；SALMONN暴露 instruction tuning 后的 task-overfitting；JSTIP进一步区分“text-only 指标提高”和“speech-conditioned 指标提高”。所以“接上 LLM”不能自动推出知识迁移：接口需要让声学表示落入可解释空间，训练目标还要让 text prior 在 speech context 中被反复调用。

14.4 理解与生成往往需要不同接口

AudioPaLM用统一离散 token并外接 SoundStorm；LauraGPT采用连续入、离散出和一步 vocoder；Mel-LLM尝试连续 Mel 输入与连续 Mel 输出，却显示 TTS 仍远弱于 latent diffusion。现有证据更支持非对称模块化：理解侧尽量保留任务相关声学信息，生成侧用 codec/diffusion/专门 head建模高保真细节。完全统一的单一 token 流有优雅性，但未必是性能或效率最优点。

15. 从论文证据到系统选型：一份约束驱动的决策框架

如果目标是单语、高资源、离线ASR精度，且已经有经过同域微调的强speech encoder，SLAM-ASR式小MLP是最直接的起点：训练接口便宜，系统行为易验证。但部署预算必须包含大LLM推理成本，且不能假设换一个encoder仍然工作。若预期频繁升级声学模型，LegoSLM的共享CTC词表与posterior expectation更合适；工程上要接受CTC头、词表对齐、blank处理和温度验证集调参。

如果目标是低资源语言ASR，且可以获得可靠词典或G2P，phoneme接口应成为强基线。Tatar结果说明显式发音中介可能大幅降低20小时配对数据对自由projector的压力。不过，选型前应审计目标语言是否已出现在phoneme encoder预训练中、G2P错误率、文字体系与code-switch情况。若未来还需情感、说话人或音乐理解，不能只保留phoneme流，应并行保留连续声学通道。

如果目标是开放式语音与音频理解，SALMONN提供双encoder与window Q-Former的经济方案：Whisper负责语音，BEATs补非语音事件，冻结LLM降低训练参数量。上线评估不能只看ASR/AAC，还应专门构造长输出、反事实指令和未训练格式，以检测task-overfitting。activation tuning可作为恢复手段，但必须回归已训练任务，确认AAC、分离等能力没有不可接受的下降。

如果目标是同一系统内完成识别、翻译、增强和TTS，LauraGPT式连续输入、离散输出比强行对称更务实。输入encoder保留理解信息，输出codec降低生成建模难度，一步vocoder补高频细节。需要分别计算主LM、codec tokenizer、vocoder的训练与推理成本，并用可懂度、感知质量、说话人相似和循环率多指标验收。AudioPaLM式统一离散词表更适合研究跨文本/语音统一自回归与直接S2ST，但其tokenizer、长序列和全参数微调成本更高。

如果目标是极简前端、吞吐和广义声学线索，Mel-LLM提示可以去掉主Conformer块。选取token rate时不能只看平均WER：100Hz质量较好却慢，12.5Hz有初始化匹配和速度优势，6.25Hz压缩过强。还应把MMLU-speech、spoken QA与副语言任务放在同一验收表中，防止只提升声学分类却损伤semantic anchoring。

如果系统已经有不错的speech representation，却出现“文本问答很强、换成语音就不会”的现象，JSTIP式交错训练对应的是行为修复而非架构替换。实施前需要可靠word/segment alignment、padding友好的片段批处理、跨样本attention隔离和speech位置loss masking。评估应同时报告T2T、S2T与两者gap；只有T2T上涨不能证明文本知识已进入语音条件分支。

这套框架的核心不是为八篇论文排总榜，而是先写清系统约束：是否生成语音、是否低资源、是否要热换encoder、是否保留副语言线索、是否允许全参数训练、是否拥有对齐与词典。约束不同，最佳接口会改变。任何选型都至少需要四类对照：同数据的表示接口、同backbone的训练目标、同系统边界的速度/显存，以及跨域或低资源压力测试。

16. 开放问题

  1. 能否统一“共享语义坐标”与“原始声学细节”？ 一个候选方向是保留 Mel/encoder continuous stream，同时加入 CTC posterior、phoneme 或 teacher-encoder auxiliary target；目前八篇论文尚无同 backbone 的完整对照。
  2. 如何自动调节 acoustic model 与 language model 的权重？ LegoSLM 的全局温度需 dev grid search。更实用的接口应按 utterance、token 或不确定性自适应，而不是固定 $\tau$。
  3. 如何同时保留文本能力与跨模态指令遵循？ SALMONN的 activation tuning 与 JSTIP的 interleaving分别从参数激活和数据序列解决，但都存在任务退化、对齐依赖或内部数据限制。
  4. 无专用 encoder 的 scaling law 是什么？ Mel-LLM显示 10×数据缩小相对固定 reference 的差距，却缺同规模 encoder baseline。需要公开、等算力、等数据曲线才能判断 encoder究竟是不可替代模块，还是数据效率工具。
  5. 离散接口如何覆盖副语言与非语音信息？ phoneme 对低资源 ASR有效，但不能承载完整 speaker、emotion、music cue；CTC posterior 同样偏文字。多通道接口或分层 token 可能比单一序列更合理。
  6. 生成评测如何跨系统边界公平比较？ ASR-BLEU、MOS、UTMOS、speaker similarity分别测不同侧面；AudioPaLM、LauraGPT、Mel-LLM的 vocoder/codec/head边界也不同。统一模型的“模型参数”若不包含外部生成器，会低估系统成本。
  7. 模块化是否可被严格验证？ LegoSLM只在 USM family，SLAM-ASR在单域匹配模块，phoneme论文只在英语/Tatar。需要跨 encoder family、词表、采样率、语言、噪声和长音频的 plug-and-play benchmark。
  8. 训练行为接口能否与表示接口联合优化？ JSTIP与Mel-LLM来自相近研究背景，却没有组合实验。用 interleaving缓解 raw-Mel 的 semantic anchoring 是合理研究假设，但当前不能写成已验证方案。
  9. 复现与统计问题。 多篇论文没有多 seed、置信区间、完整 optimizer/decoding或硬件成本；内部数据结果也难复核。接口差距若只有 0.04 WER，统计显著性比排行榜名次更重要。
  10. 隐私、安全与幻觉。 CTC posterior 不自动提供不可逆隐私；高温后验可使 LegoSLM严重 hallucinate；audio instruction模型还可能误识别说话人、情感或事件。需要重建攻击、校准、拒答与不确定性评估。

17. 结论：从“接得上”走向“接得对”

这八篇论文勾勒的演进，并不是从离散 token 单向走到原始频谱后就结束。AudioPaLM展示了统一 token vocabulary 的生成能力；SALMONN和SLAM-ASR证明连续 adapter可以用很少可训练参数释放强 encoder与LLM；LauraGPT用连续入、离散出承认理解和生成的不对称；LegoSLM与Phonemes vs. Projectors把语言结构和不确定性重新放回接口；Mel-LLM挑战专用 encoder的必要性；JSTIP则把问题推进到训练条件分布：表示已经对齐，行为仍可能不对齐。

因此，Speech–LLM接口设计的核心不应只是“选 projector 还是 token”。更完整的问题是：

在给定数据、算力和任务边界下，应该保留多少声学信息，以何种共享坐标表达不确定性，用什么训练序列激活文本先验，再把输出细节交给哪一种生成器？

现阶段没有一条路线在统一性、精度、低资源、模块化、速度、开放式理解与高保真生成上同时占优。最可信的工程方向是承认这些目标的冲突，设计分层、非对称、结构化且行为可对齐的接口；最重要的研究纪律，则是把论文事实、受控比较与跨论文推断清楚分开。

从评测方法看，后续工作也不应继续只报一个平均WER。一个可审计的Speech–LLM接口至少要同时说明：声学前端是否在目标域微调，LLM是否全量更新，外部codec或声码器是否计入系统，文本能力在语音训练后是否保留，低资源与跨域时接口是否稳定，以及生成失败、幻觉和格式错误如何计分。只有在这些边界一致时，微小的指标差异才具有工程含义；否则，更好的数字可能只是数据、初始化、解码器或评测口径不同。八篇论文最重要的共同价值，正是把过去隐藏在“接一个投影层”背后的选择逐项暴露出来，使接口成为可以提出假设、做受控消融并明确报告代价的独立研究对象。
