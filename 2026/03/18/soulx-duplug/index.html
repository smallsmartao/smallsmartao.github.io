SoulX-Duplug: 实时全双工语音对话的即插即用状态预测模块

本文最后更新于 2026年4月8日 下午

论文链接：https://arxiv.org/abs/2603.14877
Github：https://github.com/Soul-AILab/SoulX-Duplug
作者：Ruiqi Yan, Wenxi Chen 等（上海交通大学 X-LANCE Lab、Soul AI Lab）

一、引言

语音对话系统是人工智能领域的重要研究方向。传统的语音对话模型（SDM）以半双工方式运行——用户说话时系统必须等待，用户说完后系统才开始回复。这种”你说一句我说一句”的交互方式虽然简单，但缺乏人类对话的自然感。

全双工语音对话系统（FD-SDS） 能够同时听和说，支持：

  • 打断处理：用户可以直接打断AI的回复
  • 停顿处理：检测用户是否说完
  • 动态轮次转换：像真人一样自然地交接对话主权

这对于构建更自然、更智能的语音助手至关重要。

现有方法的问题

当前全双工系统主要分为两类：

类型 代表工作 问题
端到端模型 Freeze-Omni, MinMo 轮次策略与语言建模紧耦合，数据稀缺，部署成本高
模块化系统 FireRedChat, Easy Turn VAD缺乏语义理解，ASR和轮次检测存在延迟

SoulX-Duplug 提出了第三种方案：一个即插即用的流式状态预测模块，可以在不修改原有对话模型的情况下，为半双工系统赋予全双工能力。

二、核心贡献

  1. SoulX-Duplug：首个 ASR 辅助的流式状态预测模块，统一了 VAD、ASR 和轮次检测
  2. SoulX-Duplug-Eval：双语（中英）评估基准，促进标准化评估
  3. 低延迟：流式轮次检测平均延迟仅 240ms

三、方法详解

3.1 系统架构

SoulX-Duplug 的核心思想是：将双工交互控制建模为流式状态预测问题。

SoulX-Duplug 的架构如下所示：

核心创新：

  • 音频 Token 和文本 Token 交织输入，确保预测状态时可以利用文本信息
  • 训练时：VAD、ASR、状态预测端到端优化
  • 推理时：轻量级 ASR 模型通过教师强制提供文本指导

3.2 状态 Token 设计

SoulX-Duplug 定义了 5 种状态 Token 来建模双工交互：

状态 Token 含义 场景
<eos> 无语义内容 静音或噪音
<speech> 有语义语音 用户正在说话
<backchannel> 确认行为 AI的简短回应（如”嗯”、”好”）
<take_turn> 用户说完，AI可以接话 用户表达完完整意思
<hold> 用户停顿但未说完 用户在思考，AI应等待

3.3 语音输入建模

  • 语音编码器：使用 GLM-4-Voice tokenizer，以 12.5 Hz 提取音频 Token
  • 块大小：12 个音频帧（160ms 目标窗口 + 960ms 左上下文 + 40ms 右上下文）
  • 总感受野：1160ms，每步提取 15 个 Token

3.4 文本引导的状态预测

这是 SoulX 的核心创新点：

传统方式的问题：

  • VAD 只看声学特征，不理解语义
  • “我…我…”和”我要买这个”可能被同样处理

SoulX-Duplug 的方案：

  • 联合流式 ASR + 状态预测
  • 预测状态 Token 时已经看到了对应的文本
  • 本质上是一个语义 VAD

四、实验结果

4.1 与现有方法对比

模型 流式 ASR 端到端优化 语言
Easy Turn ✗ ✓ ✓ 中文
FireRedChat ✗ ✓ ✗ 中英
Phoenix-VAD ✓ ✗ ✓ 中英
FlexDuo ✓ ✗ ✓ 中英
SoulX-Duplug ✓ ✓ ✓ 中英

SoulX-Duplug 是首个同时满足这四个条件的模块！

4.2 延迟性能

  • 平均延迟：240ms（接近理论下限）
  • 在 Full-Duplex-Bench 上达到最佳轮次管理性能

4.3 状态预测准确性

在 Easy Turn 测试集上，SoulX-Duplug 通过引入文本监督，显著提升了状态预测的准确性。

七、总结

SoulX-Duplug 为全双工语音对话提供了一个新的思路：

  1. 即插即用：不需要修改原有的对话模型
  2. 语义感知：通过 ASR 文本引导，实现语义级别的轮次检测
  3. 低延迟：240ms 的流式响应
  4. 双语支持：中英双语评估基准

这个工作展示了如何将复杂的对话管理模块化、解耦化，为未来构建更自然的人机语音交互系统提供了重要参考。
