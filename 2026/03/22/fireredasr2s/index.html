FireRedASR2S: Industrial-Grade All-in-One ASR System Technical Report

本文最后更新于 2026年3月22日 下午

FireRedASR2S: A State-of-the-Art Industrial-Grade All-in-One Automatic Speech Recognition System

  • 论文链接：https://arxiv.org/abs/2603.10420
  • PDF：https://arxiv.org/pdf/2603.10420.pdf
  • Github：https://github.com/FireRedTeam/FireRedASR2S
  • 作者团队：Super Intelligence Team, Xiaohongshu Inc. (小红书)

1. 核心动机：为什么要用系统（System）而不是单模型（Model）

在学术打榜中，大家都在拼 End-to-End ASR 模型的 CER（字符错误率）。但在真实工业落地（如播客转写、会议记录、短视频字幕）中，光有一个高精度的 ASR 模型是远远不够的。

现实中的长音频通常包含大量的静音、背景音乐、环境噪声、多语种（中英夹杂）以及各地方言。这就逼着工程师去拼凑一条流水线：去开源社区拉一个 VAD（用来切分语音），再找一个 LID（用来判断语种），接上 ASR 识别，最后再配一个 Punctuation（标点恢复）模型。

FireRedASR2S 解决的正是这个工程痛点。 “2S”中的 S 代表 System。它直接开源了一套工业级、端到端的语音识别系统，把 VAD、LID、ASR、Punc 四大模块全部打通：

  • 输入：原始复杂波形（Waveform）
  • 输出：带标点、带时间戳（Token/Word级）、带语种标签、带 ASR 置信度的结构化文本。

并且，由于接口解耦，这四个模块既可以串联运行，也可以独立拆分部署。

2. 模块拆解：四个核心组件

2.1 FireRedASR2：提供 LLM 与 AED 双引擎

FireRedASR2 并没有在模型结构上搞花活，而是老老实实做了一件工业界最该做的事：用海量高质量数据大力出奇迹。训练数据从第一代的 70,000 小时直接扩大到了 200,000 小时，极大地增强了对中文方言、口音、中英 Code-Switch 以及唱歌场景的覆盖。

提供了两个变体来平衡算力与精度：

  1. FireRedASR2-LLM (8B+ 参数)：
    采用 Encoder-Adapter-LLM 架构。借助 LLM 强大的语言推理能力，用来打榜和冲击识别精度上限。
  2. FireRedASR2-AED (1B+ 参数)：
    采用经典的 Conformer Encoder + Transformer Decoder。
    亮点设计：为了支持工业界强需求的时间戳，团队在训练好的模型上外挂了一个后置的 CTC 分支 (Post-hoc CTC)。也就是冻结 Encoder 和 Decoder，单训一个轻量 CTC 头做对齐。这样既保住了 AED 本身的识别精度，又拿到了稳定的 Token/Word 级别时间戳。

2.2 FireRedVAD：放弃 ASR 强制对齐，改用人工标注

VAD（语音活动检测）经常被认为是流水线的“脏活累活”。很多开源 VAD 直接拿 ASR 的强制对齐（Forced-alignment）生成的伪标签来训练。这会导致在复杂声学环境（比如人声+BGM 混缩）下极易翻车。

FireRedVAD 采用了 DFSMN（Deep Feedforward Sequential Memory Network）架构。

  • 极度轻量：参数量只有约 0.6M（单精度下约 2.2MB），极其适合边缘端或云端海量并发。
  • 标注干净：使用了数千小时人工标注的声学事件数据，而非伪标签。
  • 支持多模态：除了标准的二分类 VAD（语音 vs 非语音），还支持流式（Streaming）以及多标签分类（mVAD：同时检测 speech, singing, music）。

2.3 FireRedLID：100+语言与20+方言的层级预测

语种识别模块（LID）直接复用了 FireRedASR2-AED 的 Conformer Encoder 权重进行初始化。

亮点设计：层级预测（Hierarchical Label Space）
如果不做层级，模型面临的是一个由“语种+方言”混合成的上百类的扁平标签空间，极易混淆。
FireRedLID 将最大解码长度限制为 2 个 Token：

  • 第一个 Token 预测主语种（例如：zh, en, ja）。
  • 如果第一个 Token 是 zh，则预测第二个 Token（例如：mandarin, yue, wu, min）。
    这种设计符合人类语言分类树，大幅提升了细粒度方言识别的稳定性。

2.4 FireRedPunc：给 ASR 套上“好看的皮囊”

没有标点的 ASR 文本对下游应用（如阅读、机器翻译）是灾难性的。
FireRedPunc 采用 BERT 风格的编码器（初始化自 LERT），作为纯文本后处理模块。
它的预测空间非常紧凑（5类）：空格/无标点、逗号、句号、问号、感叹号。使用了 185 亿中文字符和 22 亿英文词汇的多领域数据进行训练。

3. 核心实验与评测

论文在多个公开评测集上对各个独立模块进行了拆解评测。

3.1 ASR 评测 (CER %)

在 24 个公开测试集（涵盖普通话、方言、唱歌等）上，FireRedASR2-LLM 的宏平均 CER（越低越好）表现优异。

Test Set (Macro Avg) FRASR2-LLM FRASR2-AED Doubao-ASR (API) Qwen3-ASR Fun-ASR (API)
Avg-All-24 9.67 9.80 12.98 10.12 10.92
Avg-Mandarin-4 2.89 3.05 3.69 3.76 4.16
Avg-Dialect-19 11.55 11.67 15.39 11.85 12.76
Singing (opencpop) 1.12 1.17 4.36 2.57 3.05

注：对比的 Doubao 与 Fun-ASR 均为调用 API 的系统级结果。

3.2 VAD 评测 (FLEURS-VAD-102)

基于 102 种语言的帧级别评测，0.6M 的 FireRedVAD 打出了极具统治力的数据。

Model AUC-ROC (%) F1 (%) FAR (%) MR (%)
FireRedVAD 99.60 97.57 2.69 3.62
Silero-VAD 97.99 95.95 9.41 3.95
TEN-VAD 97.81 95.19 15.47 2.95
FunASR-VAD - 90.91 44.03 0.42

FireRedVAD 在漏报率 (MR) 和误报率 (FAR) 之间取得了极佳的平衡，避免了为了降低漏报而疯狂切分无用片段的情况。

3.3 LID 与 Punc

  • LID：在 FLEURS (82 种语言) 上拿到 97.18% 的句子级准确率（Whisper 为 79.41%）。在中文方言集上拿到 88.47%。
  • Punc：在中文多领域测试集上 F1 达到 82.96%，英文达到 74.83%（对比 FunASR-Punc 英文 F1 仅 49.91%）。

4. 总结与启发

  1. 工程价值 > 结构创新：20 万小时的数据清洗和系统级的流水线打通，比单纯提一个新 Attention 变体在工业界的价值大得多。
  2. “打补丁”的高级艺术：在 AED 模型上外挂后置 CTC 分支拿时间戳；LID 采用两步生成的层级方案。这些都是从血泪教训中总结出的最稳妥设计。
  3. 开源生态的新标杆：将完整的（且可以拆解的）四件套系统开源，统一了输入输出接口，这对想要快速搭建业务转写流的开发者来说，可以说是一份极其友好的开箱即用大礼包。
