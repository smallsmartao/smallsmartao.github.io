FireRedASR2S: A State-of-the-Art Industrial-Grade All-in-One Automatic Speech Recognition System

本文最后更新于 2026年3月22日 下午

FireRedASR2S: A State-of-the-Art Industrial-Grade All-in-One Automatic Speech Recognition System

  • 论文链接：https://arxiv.org/abs/2603.10420
  • PDF：https://arxiv.org/pdf/2603.10420
  • 代码仓库：https://github.com/FireRedTeam/FireRedASR2S
  • 作者：Kaituo Xu, Yan Jia, Kai Huang, Junjie Chen, Wenpeng Li, Kun Liu, Feng-Long Xie, Xu Tang, Yao Hu（Xiaohongshu Super Intelligence Team）

这篇论文到底在解决什么问题

很多线上 ASR 系统并不是“一个模型跑到底”，而是一个流水线：

  1. 先做 VAD（切掉静音和非语音）
  2. 再做 LID（识别语言/方言）
  3. 然后做 ASR（语音转文字）
  4. 最后做 Punctuation（补标点）

现实问题是：这些模块经常来自不同工具链，接口不统一、评测口径不一致，而且上游错误会层层传递。论文的目标很明确：做一个可开源、可部署、性能强的一体化系统，把这 4 个模块统一起来。

FireRedASR2S 的 “2S” 就是 second-generation FireRedASR + System 的意思。

系统总览：统一流水线 + 模块可独立部署

论文里的默认流水线是：

Waveform → FireRedVAD → FireRedLID → FireRedASR2 → FireRedPunc

最终输出不是单纯一行文本，而是结构化结果，包括：

  • 转写文本
  • 句级时间戳
  • ASR 置信度
  • 语言标签（及可选置信度）
  • VAD 分段结果

这点对工业场景非常关键：同一份输出可以直接接字幕、搜索、质检和下游 NLP。

FireRedASR2：两条模型线（LLM 线 + AED 线）

论文给了两个 ASR 变体：

1）FireRedASR2-LLM（8B+）

  • 架构：Encoder-Adapter-LLM
  • 目标：吃到更高识别上限
  • 特点：借助大语言模型解码能力，整体精度高

2）FireRedASR2-AED（1B+）

  • 架构：Conformer Encoder + Transformer Decoder
  • 目标：在精度和部署成本之间找平衡
  • 特点：支持 token/word 级时间戳输出

关键改进点（相对上一代 FireRedASR）

论文强调最核心的增益并非“花哨新结构”，而是数据规模与覆盖面扩展：

  • 监督训练数据从 70k 小时 扩展到约 200k 小时
  • 覆盖普通话、英文、中文方言、口音、code-switch、唱歌及非语音场景

另外 AED 分支新增了一个实用设计：

  • 在主模型训练完成后，额外挂一个 post-hoc CTC 分支
  • 冻结 encoder/decoder，仅训练 CTC 头做强制对齐
  • 用于更稳定地给出时间戳

这属于很“工程化”的设计：不破坏主识别性能，同时补齐时间对齐能力。

FireRedVAD：轻量但指标很强

FireRedVAD 用的是 DFSMN，参数量约 0.6M，同时提供三种模式：

  • 非流式 VAD
  • 流式 VAD
  • 多标签 mVAD（speech / singing / music）

论文强调一个训练数据差异：

  • 不是靠 ASR 强制对齐伪标签做 VAD 监督
  • 而是使用 人工标注声学事件数据（数千小时）

这会直接影响复杂场景鲁棒性，特别是“语音 + 音乐 + 演唱 + 背景噪声”混合时的切分稳定性。

FireRedLID：层级预测语言与方言

FireRedLID 是 Encoder-Decoder 结构，核心思路是“分层预测”：

  1. 先预测 language token（如 zh/en/ja）
  2. 如果是中文，再预测 dialect token（如 mandarin/yue/wu/min 等）

这比把“语言+方言”打平成一个超大标签空间更稳，也更符合实际标签结构。

覆盖能力：

  • 100+ 语言
  • 20+ 中文方言/口音

FireRedPunc：给 ASR 文本恢复可读性

FireRedPunc 采用 BERT-style 编码器（LERT 初始化），目标是在 ASR 文本上做标点恢复。

  • 任务标签：no-punc、逗号、句号、问号、感叹号
  • 训练数据规模：
    • 中文约 18.57B 字符
    • 英文约 2.20B 词

论文里把这个模块定位得很实在：不是炫技，而是“让文本可读、可直接进入下游业务”。

论文里的设计取舍（我认为最值得关注的三点）

A. 模块化不等于“拼凑”

论文的重点不是只给四个独立模型，而是把数据口径、接口、输出结构都统一了。工程上这比单点 SOTA 更重要。

B. 把主要收益押在数据规模与覆盖，而不是频繁换结构

ASR 主干变化有限，但训练数据从 70k → 200k 小时，并覆盖更多方言与场景。结果上看，这条路线有效且可复用。

C. 低参数 VAD 的工业价值很高

0.6M 级别模型做到 99.60 AUC 和 97.57 F1，意味着在高并发和边缘部署上都有明显优势。

局限与边界（基于论文披露）

  • 部分对比基线来自商业 API，存在“服务端随时间更新”导致的可复现差异。
  • 标点测试集是内部多域集，尽管论文声明后续会发布，但当前外部复现门槛仍高于公开基准。
  • 系统是模块化 pipeline，仍可能出现上游误差传递，只是通过统一接口和更强单模块能力降低了影响。

总结

FireRedASR2S 这篇报告的价值不在“提出一个全新理论框架”，而在于把工业 ASR 真正要用的四件套（VAD/LID/ASR/Punc）做成了统一、可开源、可落地且指标够强的一套系统。

如果你的目标是“上线稳定转写服务”，而不是只跑单一学术榜单，这种系统级工作比单模型提升更有现实意义。
