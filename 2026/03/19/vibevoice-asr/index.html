VibeVoice-ASR Technical Report

本文最后更新于 2026年3月20日 上午

VibeVoice-ASR 技术解读

  • 论文：https://arxiv.org/abs/2601.18184
  • 作者：Microsoft Research

一、背景与痛点

长语音（会议/播客/讲座）仍难：传统做法把音频切成 <30s，再用分离/ASR/对齐多级流水线，导致 上下文割裂、对齐误差累积、难以端到端优化。VibeVoice-ASR 的目标是把长达 60 分钟的音频一次性处理，直接输出结构化 Rich Transcription（Who/When/What）。

二、核心贡献

  • 单次 60 分钟解码：不切段，直接长上下文生成，缓解语义割裂。
  • Rich Transcription：在同一序列里交织说话人标签、时间戳和文本，ASR+分离+对齐一次完成。
  • 多语种与混说：50+ 语言，自动语言识别，原生处理中英混说。
  • Prompt 上下文注入：可在输入前拼接提示（术语/背景），改善专有名词和多音字。
  • 双 Tokenizer + LLM 主干：复用 VibeVoice 的声学/语义双 tokenizer，输出交给解码器式 LLM（如 Qwen2.5）自回归生成。
  • 长序列训练策略：LLM 输入长度由 8k 逐步 curriculum 到 65k tokens，覆盖长语音场景。

三、方法细节

  • 输入侧：最长 60 分钟音频，经声学/语义双 tokenizer 生成连续音频嵌入；可选文本 prompt（术语/背景）直接前置。
  • 主干：decoder-only LLM（Qwen2.5 系）接收多模态序列，单通道自回归生成。
  • Rich Transcription：输出序列交织 Who/When/What，推理一次性给出文本+说话人+时间戳。
  • 说话人/时间对齐：训练标签由 vblinkp（WeSpeaker）声纹 + HDBSCAN 聚类获得，时间戳由 ASR 对齐并按标点切分，保证生成序列粒度与输入对齐。

四、训练与数据

  • 预训练：大量伪标长语音，覆盖会议/播客等长场景，建模长上下文与跨说话人依赖。
  • 上下文合成数据管线：GPT-5 生成含实体/技术词/跨语对话脚本 + 对应上下文提示；VibeVoice 引擎合成多说话人中英及 code-switch 音频；闭环 ASR 过滤高 WER 样本，得到 ~6k 小时合成数据。
  • 长语音转写修复：>50 分钟录音的分段转写交给 GPT-5 重写拼合，缓解切块割裂；补齐长录音中的非语音间隔占位。
  • SFT：高质量对话/会议（MLC-SLM、Fisher 等）+ Muse 音乐数据，校准说话人/对齐；输入长度 curriculum 从 8k → 65k。
  • 说话人标注流程：vblinkp 声纹（1.5s 窗 / 0.75s hop）+ HDBSCAN 聚类 + 0.67 余弦阈值合并，得到干净标签。
