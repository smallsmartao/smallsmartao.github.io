FireRedASR2S: Industrial‑Grade All‑in‑One ASR

本文最后更新于 2026年3月20日 上午

FireRedASR2S 系统解读

  • 论文：https://arxiv.org/abs/2603.10420
  • 代码：https://github.com/FireRedTeam/FireRedASR2S
  • 作者：Super Intelligence Team, Xiaohongshu

一、背景与动机

实际落地 ASR 需要 VAD/LID/标点的全链路，而常见做法是拼装多套工具，接口不一致且误差传递严重。FireRedASR2S 试图提供一套 开源的工业级统一流水线：从音频到带标点、时间戳、语言标签的可落地文本。

二、核心贡献

  • 一体化四模块：FireRedASR2（ASR）+ FireRedVAD + FireRedLID + FireRedPunc，统一接口、可拆分部署。
  • 双 ASR 形态：FireRedASR2-LLM（8B+，高精度）与 FireRedASR2-AED（1B+，高效）。
  • 大规模训练：~200k 小时多域、多语言、多方言标注数据，提升方言覆盖。
  • 超轻 VAD：0.6M DFSMN，支持 streaming / non-streaming / multi-label。
  • 广覆盖 LID：100+ 语言、20+ 方言，层次化两 token 解码。
  • 标点：BERT/LERT 初始化，支持中英多域。

三、系统概览

  • 顺序：VAD → LID → ASR → 标点 → 输出结构化转写（含时间戳/置信度/语言标签）。
  • 模块化：每个组件可独立服务，也可默认串联输出。

四、方法细节

  • ASR 主体：在 FireRedASR 基础上小改，提供 LLM（8B+）/AED（1B+）双版；覆盖中文、方言、英文、code-switch 与唱歌，输出时间戳、置信度、语言标签。核心提升来自 20 万小时多域监督数据 而非架构大改。
  • VAD：0.6M 参数 DFSMN，支持 streaming / non-streaming / multi-label（语音/音乐/静音）；使用人工标注声学事件，避免伪标噪声。
  • LID：Encoder-Decoder，两 token 层次化预测语言 + 方言/口音，编码器初始化自 ASR-AED，解码器量化标签。
  • Punc：BERT/LERT 初始化，中英多域，补标点并与 ASR 输出时间戳对齐。

五、训练与数据

  • 语音规模约 200k 小时，涵盖新闻/对话/方言/唱歌/中英混说，显式扩充口音分布。
  • VAD 数据：数千小时人工标注声学事件，包含 streaming、non-streaming、multi-label 三类监督。
  • 迁移：LID 编码器复用 ASR-AED，Punc 基于 LERT/BERT，统一表示空间便于冷启动。

七、点评与落地建议

  • 优点：全链路开源、一体化接口，模块可拆分；双 ASR 形态便于按性能/成本切换；VAD 数据是人标而非伪标，对复杂声场更稳。
  • 注意：8B LLM 版硬件开销较大，方言覆盖虽强但仍需结合业务语料验证；标点和 LID 在特殊领域可能需再微调。
  • 上线建议：根据延迟/算力选择 LLM 版或 AED 版，结合自有方言/垂直语料做轻量 SFT；保持 VAD/LID/标点与 ASR 的版本对齐，减少接口漂移。
