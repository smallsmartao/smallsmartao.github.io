Reducing the Offline-Streaming Gap for Unified ASR Transducer with Consistency Regularization

本文最后更新于 2026年4月22日 下午

论文信息

  • 标题: Reducing the Offline-Streaming Gap for Unified ASR Transducer with Consistency Regularization
  • 作者: Andrei Andrusenko, Vladimir Bataev, Lilit Grigoryan, Nune Tadevosyan, Vitaly Lavrukhin, Boris Ginsburg (NVIDIA)
  • 链接: arXiv:2604.19079

1. 问题背景：为什么需要统一离线/流式 ASR？

工业界部署 ASR 系统时，往往需要同时满足两种场景：高精度离线转写和低延迟流式识别。传统做法是分别训练和维护两套模型——一套离线模型享有完整上下文，精度高但延迟大；一套流式模型通过因果约束实现低延迟，但精度明显下降。

维护两套模型意味着双倍的训练、验证和部署成本。能否用一个模型同时胜任两种场景？这正是本文要解决的核心问题。

难点在于：Transducer (RNNT) 架构中，基于 Conformer 的编码器在离线模式下可利用全局注意力和标准卷积，而流式模式下必须限制注意力范围并对卷积做因果化处理。这种训练-推理的不一致性（train-inference mismatch）导致统一模型在低延迟流式场景下精度急剧退化。

2. 方法详解

本文提出的 Unified ASR 框架包含三个核心组件：Chunk-limited Attention with Right Context、Dynamic Chunk Convolution (DCConv) 和 Mode-Consistency Regularization for RNNT (MCR-RNNT)。

2.1 Chunk-limited Attention with Right Context

在流式训练中，多头注意力（MHA）受到分块掩码的约束，每个时间步只能看到三部分信息：

  • 左上下文 (L)：当前块之前的 $L$ 帧
  • 当前块 (C)：正在处理的 chunk
  • 右上下文 (R)：当前块边界之后的 $R$ 帧（即未来信息）

为了让单一模型支持多种延迟目标，训练时从预定义集合中随机采样不同的 $C$ 和 $R$ 值。离线模式对应 $C$ 和 $R$ 均为全长的特殊情况。这一设计使得模型在不同延迟约束下均有训练样本，避免了只在特定延迟点上表现良好的问题。

2.2 Dynamic Chunk Convolution (DCConv)

标准卷积在流式推理时会依赖尚不可用的未来帧；因果卷积虽然解决了这个问题，但丢失了有用的未来上下文，通常导致精度下降。

DCConv 的做法是让卷积操作感知当前的 chunk 配置。具体而言，在流式模式下，每个 Conformer block 的深度可分离卷积（depthwise convolution）之前，先将隐藏状态按当前 chunk size $C$ 进行 reshape，同时附带左右上下文各 $\frac{\text{kernel_size} - 1}{2}$ 帧。离线模式和流式模式共享相同的卷积参数，仅在输入组织方式上有区别。这种方式有效缩小了分块流式解码引入的 train-inference mismatch。

2.4 Mode-Consistency Regularization for RNNT (MCR-RNNT)

即使使用了上述 chunk-limited attention 和 DCConv，在极低延迟（<0.5s）下流式性能仍会急剧退化——因为同一组参数需要同时表征两种上下文条件截然不同的模式。

从 CR-CTC 到 MCR-RNNT 的演进：作者首先尝试将 CR-CTC（对 CTC 后验做离线/流式对称一致性正则）扩展到 hybrid CTC-RNNT 训练中，但发现这反而损害了流式 RNNT 精度。原因分析：CTC 损失鼓励帧同步的、局部自信的 token 预测，而低延迟流式 RNNT 需要编码器在有限未来上下文下产出更丰富的表示。CTC 一致性正则导致共享编码器偏向于离线更容易实现、但不适合流式 Transducer 解码的对齐方式。

3. 实验设置

3.1 模型架构与训练配置

  • 编码器：基于 FastConformer 的 RNNT 模型
  • L-size 模型：~128M 参数（FastConformer 编码器 123M + 单层 LSTM 预测网络 640 units）
  • XL-size 模型：~600M 参数
  • 输入特征：128 维 FBank，8 倍初始下采样
  • 分词器：BPE tokenizer，1024 tokens
  • 训练：100K steps，cosine annealing LR（max LR=1e-3，15K warmup）
  • 硬件：32 × NVIDIA A100 GPU，使用 dynamic bucketing
  • 框架：NeMo

3.2 数据

  • L-size 模型：~120,000 小时标注英语语音（normalized transcripts），来自公开 Granary 数据集
  • XL-size 模型：~240,000 小时（punctuation and capitalization，即 PC 数据）

3.3 评估

使用 Open ASR Leaderboard 的 8 个英语测试集（AMI, Earnings22, Gigaspeech, Librispeech, SPGI, TEDLIUM, VoxPopuli 等）的平均 WER。流式推理时，延迟定义为 chunk size + right context size。

关键观察：

  1. 离线 baseline 在离线模式下最优（6.47%），但流式延迟降至 1.12s 以下后 WER 急剧恶化，0.16s 时达到 94.05%——几乎不可用。

  3. Unified SM 优于 DM（在相同计算资源下），但 <0.56s 延迟后退化明显。
  4. MCR-RNNT 在离线和 ≥0.24s 延迟的流式场景下全面超越所有对比模型。仅在 0.16s 延迟点略逊于流式 baseline（10.51% vs 9.84%）。

消融结果表明：

  • 对称 KLD（双向 KL 散度）显著优于单向（无论是 offline→streaming 还是 streaming→offline）。单向 offline→streaming 在低延迟（0.32s）时 WER 高达 15.86%，说明仅用离线做 teacher 会把流式表示拉向不适合低延迟解码的方向。
  • λ=0.3 在离线和流式之间取得最佳平衡。λ 过大（0.5）反而损害两端性能。
  • α=0.5 是推荐的起点；调大 α 偏向离线性能，调小 α 偏向流式性能。

4.4 Right Context 与 Chunk Size 的权衡

在固定总延迟预算下（chunk + right context = 常数），增大 right context 比例可以显著降低 WER，尤其是在低延迟场景。但减小 chunk size 会增加解码步数，从而拖慢推理速度。这提示实际部署时需要在精度和推理效率之间进行权衡。

5. 总结与展望

MCR-RNNT 框架通过三个层面解决了统一离线/流式 ASR 的核心挑战：

  1. Chunk-limited Attention + Right Context：让 MHA 在流式模式下可控地利用未来信息
  2. DCConv：消除标准卷积在流式推理时的 train-inference mismatch
  3. MCR-RNNT：通过在 RNNT Joint 输出上施加对称 KL 散度正则，显式缩小离线与流式模式之间的表示差距

实验在 128M 和 600M 两个规模上验证了方法的有效性和可扩展性。600M 模型在离线模式下接近纯离线 SOTA，在 ≥0.24s 延迟下全面超越已有开源流式模型，成为当前最强的统一 RNNT 模型。

局限性与未来工作：当前推理时每个 chunk step 需要重新计算左上下文，缺少 cache-passing 机制，影响实际流式推理速度。作者计划在后续工作中实现高效的缓存传递解码。

开源地址：框架和英文模型 checkpoint 已在 NeMo 中开源。
