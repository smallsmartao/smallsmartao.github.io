Distilling Conversations: Abstract Compression of Conversational Audio Context for LLM-based ASR

本文最后更新于 2026年4月1日 上午

Distilling Conversations: Abstract Compression of Conversational Audio Context for LLM-based ASR

  • 论文链接：https://arxiv.org/abs/2603.26246

在多轮语音交互场景（如智能语音助手、客服通话、长会议记录）中，当前话语的准确转录和理解高度依赖于之前的历史对话上下文。历史对话不仅能引入新的实体（如人名、地名），还能确立特定说话人的发音习惯和话语的连贯性。

然而，传统的基于 LLM 的 ASR 系统通常将每一句话孤立处理。如果直接将前几轮对话的“音频 token 序列”一并送入多模态大模型，由于音频的高采样率特性，上下文长度会急剧膨胀。这会导致极其高昂的 Key-Value (KV) Cache 开销、严重增加推理延迟，并迅速耗尽内存。为了在保留“语音上下文”与“降低计算开销”之间取得平衡，本文提出了一种名为 抽象压缩（Abstract Compression） 的创新架构。

1. 痛点：为什么直接输入多轮音频行不通？

在基于 Text-LLM 的架构中引入多模态音频时，通常的做法是将连续的音频波形通过 Encoder（如 Whisper 编码器）映射为一系列离散的 Audio Tokens。

  • 序列过长：一段 10 秒的音频可能被编码为数百甚至上千个 token。如果是多轮对话，累计的上下文 token 数量会轻松达到数千。
  • 注意力机制的灾难：在 Transformer 架构中，计算复杂度与序列长度呈二次方增长（$O(N^2)$）。保留这些长音频 token 会导致 KV Cache 呈指数级占用显存，极大地降低了模型的吞吐量（Throughput）和实时性（Latency）。
  • 信息冗余：对于“历史轮次”而言，模型其实不需要知道每一个音素的确切声学细节，它只需要获取诸如“上一句提到了什么名字”、“说话人的情绪是什么”这类高维、抽象的上下文特征。

2. 核心方法：抽象压缩架构 (Abstract Compression)

为了解决这一问题，作者提出了 Abstract Compression 机制。其核心思想是：将历史音频压缩为极少量的隐式向量（Latent Tokens），同时保留历史对话的显式文本转录。

2.1 双模态历史上下文表示

在输入到大语言模型时，模型接收到的多轮上下文被分成了两部分：

  1. 显式文本（Explicit Transcript）：前几轮对话的文本被完整保留。因为文本 token 极其紧凑（几百个词只有几十个 token），它是提供词汇级别（尤其是专有名词）上下文最高效的方式。
  2. 压缩音频（Compressed Audio Latents）：前几轮的音频经过一个专门的 Distillation/Compression Module（提取/压缩模块），从数百个原始 token 被强制压缩为固定数量的（例如 4 个或 8 个）隐式 Token。这些压缩 Token 负责传递文本无法携带的信息，如语气、声学环境、说话人特征等。

2.2 压缩模块的具体设计与两阶段训练

为了让模型学会如何压缩并利用这些信息，论文采用了一种精心设计的两阶段训练策略：

  • 第一阶段：特征蒸馏与重构（Feature Distillation）
    在这个阶段，模型被要求通过压缩后的隐式 Token 去“重构”或“预测”原始的高维音频特征。这迫使压缩模块在极少的 token 瓶颈（Bottleneck）中，尽可能多地保留原始音频中的关键声学和语用信息。

  • 第二阶段：端到端 ASR 联合微调（End-to-End ASR Fine-tuning）
    在蒸馏预训练完成后，将压缩模块与主干 LLM 结合。在这一阶段，模型被给定“文本历史 + 压缩音频历史”，然后要求精确转录“当前轮次的完整高分辨率音频”。通过梯度反向传播，压缩模块进一步学会提取那些对下游 ASR 任务最有利的上下文特征。

3. 核心实验与详细结果分析

研究团队在多个包含了丰富实体和多轮依赖的数据集上进行了广泛评估。

3.1 压缩率与性能的权衡 (Compression Rates Trade-off)

实验的核心在于探索“压缩到多少个 token 最合适”。
图表显示了不同压缩率下的词错误率（WER）变化：

  • 如果完全不压缩（使用全部原始 Audio Tokens），模型性能最好，但推理成本极高。
  • 如果过度压缩（比如每轮只保留 1 个 token），模型会丢失过多的声学细节，导致在强依赖声学上下文的场景下性能下降。
  • 最佳平衡点：实验证明，将每轮音频压缩至 4 到 8 个隐式 token 时，模型不仅成功恢复了大部分由“全量音频上下文”带来的性能增益，而且使得上下文 token 的总数下降了数个数量级。

3.2 针对专有名词（Contextual Entities）的显著提升

论文的一个重要发现是，抽象压缩在处理**上下文实体（Contextual Entities）**时表现出了巨大的优越性。
在没有上下文基线模型中，ASR 经常将罕见的人名或地名识别为发音相近的常用词。而引入了“显式文本 + 压缩音频”的历史上下文后，模型能够跨轮次对齐发音和文本。经过多轮监督训练，模型在识别这些难点实体上的准确率得到了断崖式的提升。

4. 总结与局限性探讨

贡献总结：

  1. 明确了多轮音频大模型中 KV Cache 的性能瓶颈。
  2. 提出了一种新颖的 Abstract Compression 架构，将显式文本的紧凑性与隐式音频的高维特征完美结合。
  3. 证明了在大幅降低计算和内存成本的同时，依然能够实现超越单轮基线的 ASR 精度。

局限性与未来展望：
尽管这种两阶段训练方法非常有效，但其训练过程相对复杂，需要构建高质量的“历史音频-文本-当前音频”配对数据集。此外，当前研究主要集中在 ASR 任务上，未来该压缩模块是否能无缝泛化到全双工的语音对话生成（Speech-to-Speech Generation）任务中，仍有待进一步验证。
