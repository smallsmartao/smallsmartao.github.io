Distilling Conversations: Abstract Compression of Conversational Audio Context for LLM-based ASR

本文最后更新于 2026年4月8日 下午

Distilling Conversations: Abstract Compression of Conversational Audio Context for LLM-based ASR

  • 论文链接：https://arxiv.org/abs/2603.26246

在多轮语音交互场景（如智能语音助手、客服通话、长会议记录）中，当前话语的准确转录高度依赖于历史对话上下文。例如，历史对话可能已经提到了某个罕见的专有名词，或者确立了说话人的口音。

当前主流的多模态大模型（Audio-LLMs）通常通过一个 Audio Encoder 将音频映射到 LLM 的 token 空间。然而，由于音频序列通常非常长（例如 1 秒音频对应几十上百个 token），如果在多轮对话中直接将所有历史轮次的原始 Audio Tokens 送入 LLM，会导致极其高昂的 Key-Value (KV) Cache 开销，严重拖慢推理速度并造成 OOM（Out of Memory）。

为了在“利用语音上下文”与“降低计算开销”之间取得平衡，本文提出了一种名为 抽象压缩（Abstract Compression） 的方法，通过混合模态表示法，将极长的高维音频历史压缩为几个 Latent Tokens。

1. 核心痛点与输入输出定义

1.1 问题定义

假设在一个对话会话中，有 $N$ 个话语序列。对于第 $n$ 个话语（即当前需要识别的这句），模型可以访问前 $n-1$ 个历史轮次的对话内容。

  • 第 $i$ 个话语的原始音频特征表示为 $A_i$。
  • 第 $i$ 个话语的文本转录表示为 $W_i$。

1.2 抽象压缩（Abstract Compression）的目标

由于历史轮次的文本 $W_{1:n-1}$ 已经提供了极为紧凑且高效的词汇级信息（Lexical Context，这对解决专有名词极其重要），其实我们并不需要历史音频的每一帧细节。历史音频的真正价值在于提供韵律、情绪、发音特征和副语言信号。

因此，Abstract Compression 的核心就是通过一个可学习的压缩模块（Distillation Module） $f_{ heta}$，将长序列 $A_i$ 映射为一个极短的隐式特征序列 $C_i$（例如长度固定为 $K=4$ 或 $8$）：

2. 方法论详解：两阶段训练架构

如何训练这个压缩模块 $f_{ heta}$，使其在极低的 token 容量（Bottleneck）下保留对 ASR 最有用的信息？论文提出了一种两阶段（Two-Stage）的知识蒸馏与微调架构。

2.1 阶段一：特征层面的蒸馏（Feature Distillation）

在第一阶段，模型完全脱离下游的文本生成任务，专注于让压缩特征（Latent Tokens）尽可能多地重建全分辨率的音频特征。

具体机制如下：

  1. 全分辨率编码：将历史音频 $A_i$ 通过 Whisper 编码器，得到高分辨率的音频特征表示 $Z_i \in \mathbb{R}^{T imes D}$（其中 $T$ 是长序列帧数，$D$ 是特征维度）。
  2. 抽象压缩模块 $f_{ heta}$：这是一个基于 Q-Former（Query Transformer）或简单注意力池化（Attention Pooling）的模块。它引入了 $K$ 个固定数量的 Query Token（例如 $K=4$ 或 $8$）。这 $K$ 个 Query 通过 Cross-Attention 对长序列 $Z_i$ 进行查询和聚合，最终输出固定长度的压缩特征 $C_i \in \mathbb{R}^{K imes D}$。
  3. 重建与蒸馏损失：为了确保 $C_i$ 学到了有用的信息，模型使用一个浅层的 Decoder 网络，试图从 $C_i$ 重构出原始的 $Z_i$。这里的损失函数通常采用均方误差（MSE）或余弦相似度损失：这一步强迫那 $K$ 个可怜的 token 拼命“压缩”并“记住”整段音频中的全局声学风格、说话人声纹等高维特征。

2.2 阶段二：端到端的联合微调（End-to-End ASR Fine-tuning）

经过第一阶段后，压缩模块 $f_{ heta}$ 已经具备了很好的信息提炼能力。接下来进入真实的多轮 ASR 任务。

  1. 模型的主干是一个强大的 Text-LLM（如 Phi-3 或 LLaMA）。
  2. 输入拼装：对于前 $n-1$ 轮的每一轮，将显式文本 $W_i$ 的 token 和压缩后的音频 $C_i$ 交替拼装作为 Context。对于当前第 $n$ 轮，输入全分辨率的音频特征 $Z_n$。
    输入序列如同：<Transcript_1> <C_1> <Transcript_2> <C_2> ... <Transcript_{n-1}> <C_{n-1}> <Z_n>
  3. 联合训练：在这个阶段，LLM 被训练以自回归的方式输出当前轮次的文本 $W_n$。此时，压缩模块 $f_{ heta}$ 也会跟随 ASR 的损失（Cross-Entropy Loss）进行端到端的联合反向传播微调。
    这使得压缩模块从“尽量保存所有声音细节”转变为了“只提取对当前这句 ASR 识别有帮助的上下文特征”（例如发音习惯或语气线索）。

3. 实验结果与深度分析

3.1 压缩率与性能的权衡 (Compression Rates Trade-off)

为了量化这种架构的收益，作者对比了不同 $K$ 值（每轮保留的隐式 token 数量）对词错误率（WER）的影响。

上图清楚地展示了三条基准：

  1. 无上下文基线（No Context）：最差。
  2. 全分辨率上下文（Raw Context）：性能最好，但需要输入成千上万个 token，KV Cache 开销无法承受。
  3. 抽象压缩（Abstract Compression）：
    • 当 $K=1$ 时（极度压缩），模型丢失了过多的细节，性能下降明显。
    • 当 $K \in [4, 8]$ 时（最佳平衡），性能曲线趋于平缓，模型恢复了使用全分辨率音频时绝大部分的性能增益，同时上下文 token 的总数减少了两个数量级以上！

3.2 专有名词（Contextual Entities）的跨轮次对齐

这是该论文最为惊艳的发现之一。
在日常对话中，第一句可能提到“我叫张三（Zhang San）”，第三句再说“张三去吃饭了”时，ASR 常常由于发音模糊把第三句听成“张山（Zhang Shan）”。
通过 Abstract Compression，显式文本（第一句的转录）保留了“张三”这两个字的准确 Lexical Token；而隐式压缩特征 $C_1$ 则保留了说话人当时对“张三”这两个字的发音（Acoustic Signature）。
经过第二阶段的端到端微调，LLM 学会了在推理时跨越轮次去比对：“哦，当前这段音频里的发音，和第一句 $C_1$ 里提到的发音一模一样，所以我这里也应该输出文本里的‘张三’。”
这使得模型对罕见上下文实体的识别错误率实现了断崖式的降低。

4. 总结

《Distilling Conversations》不仅指出了一条降低多模态 LLM 长音频序列推理成本的明路，更通过“显式文本防遗忘、隐式音频防歧义”的双模态互补机制，揭示了 Audio-LLM 如何高效处理上下文的高级技巧。这种采用 Q-Former 风格架构进行跨模态特征蒸馏的两阶段训练法，在未来的全双工语音助手、长播客分析等真实工程落地中，具有极其重要的参考价值。
