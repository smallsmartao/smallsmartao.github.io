Distilling Conversations: Abstract Compression of Conversational Audio Context for LLM-based ASR

本文最后更新于 2026年4月1日 上午

Distilling Conversations: Abstract Compression of Conversational Audio Context for LLM-based ASR

  • 论文链接：https://arxiv.org/abs/2603.26246

标准的基于大语言模型（LLM）的语音识别系统通常独立处理每个语音片段，难以有效利用多轮对话的上下文信息。在语音助手、客服通话和会议记录等场景中，当前话语的准确理解往往高度依赖于之前的对话内容。历史对话不仅能引入专有名词，还能确立特定说话人的发音习惯以及提供话语的连贯性线索。

虽然多模态大语言模型能够通过将音频映射到文本生成模型的 token 空间来解决这一问题，但直接利用多模态对话上下文却面临巨大挑战。之前的对话语音通常由长序列的音频 token 组成，这会导致极高的 Key-Value (KV) 缓存开销、显著增加延迟并成为内存瓶颈。

1. 核心痛点与挑战

在多轮对话的 ASR 任务中，如果缺乏上下文，模型很容易在专有名词（如人名、地名或领域特定术语）上发生识别错误。而如果直接将前几轮对话的完整音频 token 序列送入模型，由于音频的高采样率，上下文的 token 长度会急剧膨胀。这不仅限制了模型能处理的上下文轮数，也使得推理成本难以承受。

2. 方法论：抽象压缩 (Abstract Compression)

为了降低原始音频上下文条件生成的计算成本，本文提出了一种称为 抽象压缩（Abstract Compression） 的方法。该方法将之前轮次的音频压缩成极少量的隐式 token（latent tokens），同时保留之前轮次的文本转录形式。

2.1 压缩机制设计

这一设计的出发点在于解决基于 LLM 的 ASR 中上下文 token 开销的主要来源：音频由长 token 序列表示，而对应的文本转录则紧凑得多。
通过抽象压缩，模型不再需要保留历史对话的所有原始音频细节，而是通过一个可学习的压缩模块（Distillation/Compression Module），将历史音频中的情感、声学特征和环境线索提炼成固定数量的向量。

2.2 混合上下文输入

在推理和训练阶段，模型接收到的多轮上下文是混合模态的：

  • 历史轮次：采用保留的文本转录 + 压缩后的音频隐式 token（极大地缩短了序列长度）。
  • 当前轮次：采用完整分辨率的音频 token，以保证对当前语音的高精度识别。

3. 实验结果与贡献

作者在多个数据集上验证了该方法的有效性，展现了在上下文长度与识别准确率之间的极佳平衡。

3.1 压缩率与性能的权衡

实验表明，将历史音频大幅压缩后（如每个轮次仅保留几个 token），虽然相比于使用完全未压缩的原始音频，在特定复杂场景下的极致性能会有少许损失，但整体上仍然能够恢复并保留大部分由音频上下文带来的性能增益。

3.2 对专有名词的识别提升

研究指出，利用多模态历史上下文（即使是压缩后的）后，模型对当前轮次中专有名词（Contextual Entities）的识别准确率得到了最大程度的提升，这得益于多轮监督训练下模型学会了跨轮次的信息对齐。

4. 总结与讨论

通过将显式文本与压缩的隐式音频特征相结合，Abstract Compression 提出了一种高效利用多模态对话上下文的新范式。这种两阶段训练策略和架构设计不仅大幅降低了多轮音频处理中的 KV Cache 开销和延迟，还为构建高效、连贯的长上下文语音大模型（Audio-LLM）铺平了道路，对实际工程落地具有极高的参考价值。
