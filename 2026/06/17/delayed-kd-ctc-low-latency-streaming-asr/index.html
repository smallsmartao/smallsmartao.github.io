Delayed-KD: Delayed Knowledge Distillation based CTC for Low-Latency Streaming ASR

本文最后更新于 2026年6月17日 下午

  • 机构: 西北工业大学 ASLP 实验室、华为云

1. 引言与研究动机

基于 CTC 的流式 ASR 在实际应用中受到广泛关注，但面临两个核心挑战：

  1. 小 chunk 下的精度退化：由于有限的上下文信息，当 chunk size 极小时，流式模型的识别准确率显著下降。
  2. Non-blank token 发射延迟：CTC spike 相对于非流式模型存在滞后，导致 token 输出延迟。

现有方法的局限性：

  • Fast-U2++ 采用混合 chunk 策略（下层小 chunk、上层大 chunk），部分缓解精度下降，但在极小 chunk 条件下仍然表现不佳。
  • CUSIDE-T 引入 SimuNet 模拟全局上下文，但最小延迟仍为 400 ms。
  • FastEmit、Peak-first CTC、Delay-Penalty 等方法通过损失函数鼓励提前发射 non-blank token，虽然减少了 CTC spike 滞后，但 token 发射延迟（由 chunk 尾部时间决定）仍未解决，且精度改善有限。
  • 传统知识蒸馏方法（如逐帧蒸馏）受限于流式 CTC 固有的 token 发射延迟，直接逐帧对齐效果不佳。基于强制对齐的蒸馏方法忽略了流式/非流式模型之间的信息差异。

本文提出 Delayed-KD，通过引入 时间对齐缓冲区（Temporal Alignment Buffer, TAB） 和极小 chunk size 进行训练，实现从非流式教师模型到流式学生模型的延迟知识蒸馏，在低延迟场景下显著提升识别精度。

2. 方法

2.1 模型架构

如图所示，Delayed-KD 的模型架构包含三个主要组成部分：

  1. 非流式教师模型的 CTC 分支：包含非流式编码器（Encoder）和 CTC 解码器，编码器可以获取全局上下文信息。训练过程中参数冻结。
  2. 流式学生模型的 CTC 分支：包含流式编码器和 CTC 解码器，编码器仅能获取左侧上下文。
  3. 流式学生模型的 Attention 分支：包含 Attention Decoder，用于建模 token 之间的依赖关系。

教师模型和学生模型的 CTC 分支采用相同结构：

  • 共享编码器：由多层 Conformer 层构成
  • CTC 解码器：由线性层 + log softmax 层组成

CTC 解码器的设计服务于双重目的：

  1. 训练时对 softmax 输出应用 CTC 损失
  2. 促进教师与学生模型之间帧级 CTC 后验概率的延迟知识蒸馏

Attention Decoder 采用标准 Transformer 解码器架构。

2.2 训练

2.2.1 延迟知识蒸馏（Delayed Knowledge Distillation）

核心思想：将音频的 fbank 特征分别送入非流式教师模型和流式学生模型的编码器，生成两个不同的帧级 CTC 后验概率分布。由于流式模型的 CTC spike 相对非流式模型存在延迟，直接逐帧蒸馏效果不佳。

Temporal Alignment Buffer (TAB) 的作用机制：

  • 在训练时采用极小的 chunk size（1 帧，即 40 ms）
  • TAB 维护相对于非流式教师模型的可控延迟范围
  • 在该延迟范围内，选择使 KL 散度损失最小的 chunk 进行蒸馏
  • 通过将教师模型的 CTC 输出与学生模型的延迟 CTC 输出（右移若干 chunk）对齐，有效缓解蒸馏过程中 non-blank token 的错配问题

3. 实验

3.1 数据集

  • AISHELL-1：178 小时中文普通话数据，测试集包含 7,176 条语音
  • WenetSpeech：10,000 小时多领域中文普通话数据，包含 Test Meeting 和 Test Net 两个测试集（共约 33,100 条语音）

3.2 实验设置

  • 基于 WeNet 工具包实现
  • 基线模型：标准 Conformer U2++
  • 教师模型参数在训练过程中冻结
  • 输入特征：80 维 fbank，帧移 10 ms，帧长 25 ms
  • 数据增强：SpecAugment + SpecSub
  • 建模单元：AISHELL-1 约 4,000 个汉字，WenetSpeech 约 5,500 个
  • Label smoothing 权重：0.01
  • 联合训练中 $\lambda = 0.3$
  • 优化器：Adam + Warmup 学习率调度
  • 初始学习率：0.001，梯度裁剪阈值 5.0
  • Warmup 阶段：前 25k 步
  • 总训练步数：AISHELL-1 为 200k，WenetSpeech 为 130k
  • 解码时模型平均：AISHELL-1 取 dev loss 最低的 top 20 模型，WenetSpeech 取 top 10

3.3 发射延迟度量

评估字符级识别延迟的方法：用模型输出时间戳减去对应 token 的 ground-truth 结束时间。

两个关键指标：

  • FTD (First Token Delay)：每条语音中第一个 token 的发射延迟
  • LTD (Last Token Delay)：每条语音中最后一个 token 的发射延迟

报告所有语音的 P50（第 50 百分位）和 P90（第 90 百分位），排除异常句子。Ground-truth 时间戳通过 Kaldi 工具包训练的 GMM/HMM 模型的强制对齐获取。

关键发现：

  1. Delayed-KD 的性能优越性：在 rescoring 解码模式下，Delayed-KD 以 40 ms 延迟达到 5.42% CER，甚至可与 U2++ 在 320 ms 延迟下的 5.44% 相媲美。在相同 40 ms 延迟下，相对 U2++ 实现 9.34% 的相对 CER 降低。

  2. 流式解码模式表现更突出：Delayed-KD 在流式解码模式下实现了 21.26% 的相对 CER 降低（相对于 U2++ 在 40 ms 延迟下），甚至超越了 U2++ 在 320 ms 延迟下的性能。

  3. 与其他先进模型的比较：

    • Rescoring 模式下，Delayed-KD (40 ms) 优于 CUSIDE-T (400 ms)
    • Streaming 模式下，Delayed-KD (40 ms) 超越 Fast-U2++ (160 ms)，接近 CUSIDE-T 的性能

  4. CTC Spike 分布对比：如 Figure 2 所示，Delayed-KD 的 CTC spike 明显早于 U2++，证明了其改进的对齐和降低的 token 发射延迟。

TAB 设置分析

  • TAB = 0（逐帧蒸馏）：token 发射延迟最低，但 CER 次优
  • TAB = 80 ms 产生最佳结果：rescoring CER 5.42%，streaming CER 6.11%
  • 相对于逐帧蒸馏，分别实现 6.07% 和 12.96% 的相对 CER 降低
  • 更大的 TAB 增加发射延迟，但 Delayed-KD 在保持精度优势的同时，延迟仍低于 U2++

3.5 WenetSpeech 实验结果

模型 Chunk Size 延迟 (ms) Test Meeting (Streaming/Rescoring) Test Net (Streaming/Rescoring)
U2++ 8 320 17.80 / 16.76 11.54 / 12.23
U2++ 1 40 25.32 / 23.52 16.51 / 19.06
Delayed-KD 1 40 17.53 / 16.96 11.37 / 12.75

关键发现：

  1. Delayed-KD 在 40 ms 延迟下达到与 U2++ 在 320 ms 延迟下相当的结果
  2. 在相同延迟条件下，Delayed-KD 显著优于 U2++
  3. 在 rescoring 模式下，40 ms 延迟的 Delayed-KD 相对于同延迟的 U2++ 在 Test Meeting 和 Test Net 上分别实现 27.9% 和 33.1% 的相对 CER 降低
  4. Delayed-KD 在流式模式下的改善尤为显著，优于 rescoring 模式的提升幅度
  5. 结果表明 Delayed-KD 在大规模数据集上保持了鲁棒性能

4. 总结

Delayed-KD 提出了一种新颖的延迟知识蒸馏方法，核心贡献包括：

  1. Temporal Alignment Buffer (TAB)：通过引入可控的延迟范围，有效对齐流式和非流式模型的 CTC 输出，克服了传统逐帧蒸馏的局限
  2. 极小 chunk size 训练：在 1 帧（40 ms）chunk size 下训练，实现极低延迟
  3. 精度-延迟的最优平衡：40 ms 延迟下达到与 320 ms 延迟基线相当的精度
  4. 细粒度延迟控制：通过调节 TAB 大小，可灵活控制 token 发射延迟与精度的权衡

该方法在 AISHELL-1 和 WenetSpeech 数据集上均展示了一致的优越性，为低延迟高精度流式 ASR 提供了有效的解决方案。
