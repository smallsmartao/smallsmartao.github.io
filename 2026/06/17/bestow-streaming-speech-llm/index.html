BESTOW: Efficient and Streamable Speech Language Model with the Best of Two Worlds in GPT and T5

本文最后更新于 2026年6月17日 下午

论文概览

本文来自 NVIDIA，发表于 arXiv 2024（2406.19954）。作者提出了 BESTOW（BEst of TwO Worlds）架构，将 GPT-style 和 T5-style SpeechLLM 的优势融合到一个统一模型中，同时实现了高效推理和流式多任务能力。这是首个开源的支持流式（Streaming）+ 多任务（Multitask，超越 ASR）的 SpeechLLM 方案。

作者: Zhehuai Chen, He Huang, Oleksii Hrinchuk, Krishna C. Puvvada, Nithin Rao Koluguri, Piotr Żelasko, Jagadeesh Balam, Boris Ginsburg

1. Introduction

1.1 背景与动机

大语言模型（LLM）的成功推动了多模态理解研究，尤其是将语音理解能力融入预训练 LLM（即 SpeechLLM）。当前主流框架是 Speech-LLaMA 系列：将语音 prompt 拼接到文本 prompt 前面作为 decoder-only LLM 的输入。该设计具备模块化优势，支持 LLM 知识向语音任务迁移，在 ASR 和 AST 上表现优异。

1.2 现有方法的缺陷

然而 Speech-LLaMA 式架构存在两个核心问题：

  1. 效率问题：Self-attention 对拼接后的长序列（语音嵌入远长于文本）的二次复杂度导致计算开销巨大。即使通过大幅下采样语音嵌入来缓解，也不可避免地造成信息损失。
  2. 流式不可行：整段语音嵌入作为 prompt 必须全部预置，无法支持流式 ASR、同声传译等应用。

1.3 本文贡献

  • 首个开源的同时支持流式 + 多任务（超越 ASR）的 SpeechLLM 方案
  • 基于 cross-attention 和 read-write policy 的新型骨干架构，统一离线/流式模式
  • 在 ASR、AST、SQA、DynamicSuperb 等大规模多任务基准上达到 SOTA
  • 端到端可优化，训练/推理成本更低，支持 LLM 知识迁移

2. Related Work

2.1 语音基础模型（Speech Foundational Model）

近期进展包括：

  • 大规模多语言自监督/半监督学习（XLSR、USM）
  • 大规模多任务监督训练（Whisper 系列、SeamlessM4T）
  • 更强大高效的语音编码器设计（Conformer 及变体）
  • 多语言多任务评测基准（XTREME、ML-SUPERB）

2.2 SpeechLLM 架构分类

根据语音嵌入类型可分为：

  1. 离散 token 方法（SpeechGPT、AudioPaLM）：将语音量化为离散 token 与文本共享词表。受限于语音量化模型质量。
  2. 连续特征方法：使用预训练语音编码器提取特征，投影到 LLM 词嵌入空间。本文属于此类。

在连续特征方法中，又可按架构分为：

  • GPT-style：直接拼接语音和文本 prompt 作为 decoder-only LLM 输入（Speech-LLaMA、SALMONN、QWEN-audio）
  • T5-style（Flamingo 系列）：在预训练 GPT-based LLM 的每一层/块中加入跨模态 cross-attention，文本作 query

2.3 流式语音模型

  • 流式 ASR：在 Transformer 上引入有限上下文或流式训练，通常基于 Transducer，难以利用预训练 LLM
  • 同声传译：研究固定和自适应 read-write policy（Wait-k、EMMA、ITST）

3. Why Streaming SpeechLLM is Hard

现有流式 SpeechLLM 方案（如 Speech RealLM、Tsunoo et al.）通过将 block-wise 语音特征与文本交错排列来更新 prompt 格式。这类方法存在以下局限：

  1. Prompt 格式不匹配：交错格式（注入 BLANK/WAIT token）与 LLM 文本预训练格式不同，阻碍 LLM 文本知识迁移。先前研究无法展示利用预训练 LLM 的额外收益，且能力局限于 ASR。
  2. 非端到端可优化：引入的对齐阶段（如 CTC 对齐）使得系统无法端到端训练，难以泛化到 AST、SQA 等多任务。
  3. 更高推理成本：源于新 prompt 格式中更长的文本预测长度或需要 beam search。

BESTOW 的解决方案保持 LLM prompt 格式不变，统一离线与流式学习框架，实现：LLM 知识迁移、多任务支持、端到端可优化、更低训练/推理成本。

4. BESTOW: A Streamable SpeechLLM

4.1 统一的离线-流式框架

核心思想：将流式 SpeechLLM 问题重新表述为同声传译中的 read-write policy 问题。在每个 LLM 步骤中，模型决定是等待更多语音输入特征（READ）还是预测目标词（WRITE）。

该方案保持 LLM prompt 格式不变，前提是将 READ 和 WRITE 操作从 LLM 中解耦，由独立的 cross-attention 特征提取器 建模（Section 4.2）。之后流式只需简单两步即可实现（Section 4.3）。

4.2 通过 Cross-Attention 引入语音模态

与现有方法的本质区别：不再简单拼接语音和文本 prompt，而是在 LLM 输入前注入可训练的 transformer-like self-attention + cross-attention 层，让文本 prompt attend 到语音 prompt 的不同区域，提取与当前 LLM 步骤最相关的特征。

具体设计：

  • Keys/Values：语音编码器输出的语音特征
  • Queries：输入文本（文本 prompt + 已预测 token）经 LLM 输入嵌入矩阵编码
  • Causal Self-Attention：在 LLM 输入嵌入和 cross-attention 之间注入因果自注意力层，使 query 能考虑当前步骤和历史上下文
  • Residual Connection：将文本 prompt 直接加到 cross-attention 输出上，确保模型可退化为原始文本 LLM（在非语音步骤学习忽略 cross-attention 输出）

最终设计本质上是 [Vaswani et al., 2017] 中的一个 cross-attention transformer 层，重复 $X$ 次。消融实验表明 $X=2$ 即可。

训练：标准 next-token-prediction loss。
推理：LLM 接受文本 prompt 逐步生成 token，唯一不同是每个预测 token 同时回馈到 LLM 输入和上方的 cross-attention 模块。

4.3 从离线到流式

有了 cross-attention 特征提取器后，每个 decoder 步骤所需的语音上下文长度独立于 LLM backbone，完全由 cross-attention 模块的 read-write policy 决定。流式化只需两步：

第一步：设计 Read-Write Policy

采用最经典的固定策略 Wait-k：

  • 确定固定 pre-decision ratio $L$，对应步长为 $L \times P \times 10\text{ms}$（$P$ 为语音编码器下采样率）
  • LLM 接收文本上下文 prompt（无 cross-attention），然后 cross-attend 前 $K \times L$ 个语音嵌入步来预测第一个 subword
  • 之后每收到 $L$ 个新语音嵌入即预测一个 subword

第二步：使语音编码器流式工作

两种方式：

  1. BESTOW-S-bidi：保持双向编码器，推理时每收到新语音块重新计算所有可用编码器状态。引入固定右上下文 13 帧来补偿训练/推理不匹配。
  2. BESTOW-S-unid：使用单向编码器重训模型。采用 cache-aware streaming model 更新 FastConformer pre-encoder 层，使用因果卷积，左右上下文窗口（帧）：$[[70,13],[70,6],[70,1],[70,0]]$，推理时可选。

训练策略：

  • 从离线 BESTOW 初始化 BESTOW-S，在相同数据上继续训练
  • 训练时随机采样 $K$ 范围，推理时可选择任意 $K$ 实现延迟-质量权衡

4.4 BESTOW vs GPT-style vs T5-style

与 GPT-style（Speech-LLaMA）的效率对比：

设 $L_t$ 为文本 token 长度，$L_a$ 为语音特征长度：

  • GPT-style 复杂度：$(L_t + L_a)^2 = L_t^2 + L_a^2 + 2L_aL_t$
  • BESTOW 复杂度：$L_tL_a + L_t^2$

由于通常 $L_a \gg L_t$，理论加速约 $L_a$ 倍——语音越长加速越显著。这在宽且深的 LLM 中尤为重要，因为语音编码器和 cross-attention 的计算可从 LLM forward/backward 中剥离。

与 T5-style（Flamingo、Whisper-LLaMA）的对比：

T5-style 在 LLM 每一层都加 cross-attention，引入大量参数。BESTOW 仅需 LLM 输入前的 2 层 cross-attention 即可达到 SOTA。模态特有设计仅在 LLM 输入侧，允许对 LLM 参数使用 LoRA 等参数高效微调。

5. Experiments

5.1 数据集与实验设置

训练数据：

  • 31K 小时公开语音数据 + 54K 小时内部数据（ASR/AST）
    • 英语 67.4K 小时、德语 6.1K 小时、西班牙语 6.6K 小时、法语 5.1K 小时
  • 2K 小时 MSMARCO 语音合成版（SQA）
  • DynamicSuperb 训练集

评估指标：

  • ASR：WER（LibriSpeech test-other、Gigaspeech、MCV-16.1、Open ASR Leaderboard）
  • AST：BLEU（CoVoST、FLEURS）
  • SQA：ROUGE-L
  • DynamicSuperb：Accuracy（6 类别：CNT, SPK, SEM, DEG, PRL, AUD）
  • 流式延迟：non-computation-aware LAAL

模型配置：

  • 框架：PyTorch + NeMo Toolkit
  • 训练：128× A100 (80G) GPUs，60k steps，一天完成
  • Batch duration：360 sec/GPU
  • 语音编码器：初始化自 Canary-1B
  • LLM：初始化自 TinyLlama-1.1B-chat
  • Cross-attention：2 层 Transformer 模块
  • 总参数量：约 1.8B（默认全参数训练）
  • LoRA：1024 维（消融实验中使用）
  • 优化器：Distributed Fused Adam + Cosine Annealing
  • 学习率：$1\times10^{-4}$，权重衰减 $1\times10^{-3}$，梯度裁剪 1.0

流式设置：

  • $L=4$，$P=8$，默认 $K=10$（ASR 使用 $K=6$）
  • 训练时 $K$ 从 3 到 12 随机采样
  • BESTOW-S-unid 先用 wav2vec2 在 librilight 上预训练 FastConformer cache-aware 编码器
  • 推理时固定右上下文 13 帧

  • 2 层即可达到与 8 层相同的最优性能（5.6 WER）

  • RNN 替代 self-attention 可有效恢复性能（5.7），类似 LAS 架构

5.4 流式延迟-质量权衡

通过在推理时变化 $K$ 值，可以灵活控制延迟-质量权衡。趋势与 ASR 和 AST 的 SOTA bespoke 系统一致。

6. Conclusions

BESTOW 提出了首个开源的同时支持流式和多任务（超越 ASR）的 SpeechLLM 方案。核心创新在于基于 cross-attention 和 read-write policy 的新型骨干架构，统一离线/流式模式，在多个大规模多任务语音-文本基准上达到 SOTA，同时降低训练和推理成本。该工作为下一代 SpeechLLM 的骨干设计提供了新方向。

个人思考

  1. 架构简洁性：仅 2 层 cross-attention 放在 LLM 输入前即可匹配甚至超越 Speech-LLaMA，同时解锁流式能力，设计非常优雅。
  2. Read-Write Policy 框架的通用性：将流式 SpeechLLM 统一到同声传译的 read-write policy 框架下，使得该领域的大量研究（Wait-k、EMMA 等）可直接复用。
  3. 效率优势在长语音场景更突出：$O(L_tL_a)$ vs $O((L_t+L_a)^2)$ 的差异随语音长度增加而放大，对长对话、播客、会议等场景尤为重要。
  4. 局限与未来方向：当前仅验证了固定 Wait-k 策略，自适应策略（EMMA）的集成是重要后续工作；双向/单向编码器的差距仍需弥合；computation-aware latency 优化尚未完成。
