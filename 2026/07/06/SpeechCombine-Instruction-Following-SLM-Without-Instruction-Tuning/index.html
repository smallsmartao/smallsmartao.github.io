SpeechCombine: Instruction-Following Speech Language Models without Instruction Tuning

本文最后更新于 2026年8月18日 中午

论文信息

  • 标题: Unlocking Speech–Text Compositional Powers: Instruction-Following Speech Language Models without Instruction Tuning
  • 作者: Congrui Du, Yang Zhang, Kaizhi Qian, Shiyu Chang
  • 机构: UC Santa Barbara, MIT-IBM Computing Research Lab (IBM Research)
  • 发表: ICML 2026
  • 链接: arXiv:2607.02214

一、为什么需要 SpeechCombine？——问题背景

1.1 语音大模型（SLM）训练的根本困境

当前语音大模型的训练范式直接沿袭文本 LLM 的路线：先大规模预训练，再指令微调（instruction tuning）。然而，语音模态存在一个致命瓶颈——序列膨胀。一个英文单词平均 3-4 个文本 token，对应的语音片段（约 1 秒）却需要 60-200 个语音 token，序列长度膨胀约 20 倍。这意味着在相同训练计算预算下，SLM 的有效数据量远低于文本 LLM。

更严重的问题是灾难性遗忘（catastrophic forgetting）。SLM 通常从文本 LLM 初始化，但后续在大量语音 token 上的训练会严重破坏原始文本能力。大量训练资源实际上被浪费在重新学习文本 LLM 已经掌握的知识上——而且是以更难学习的语音表征形式。

1.2 SLM 指令的三种类型

论文将 SLM 需要处理的指令归纳为三类：

类别 说明 输入 输出
文本导向指令 QA、推理、文章生成等文本 LLM 已有的能力 文本或语音 文本或语音
语音理解指令 查询语音中的副语言信息（情感、重音等） 必须含语音 文本或语音
语音生成指令 按约束生成语音（指定情感、重音词等） 文本或语音 必须含语音

现有方案（如 Freeze-Omni 冻结 LLM 仅训练适配器）只能覆盖第一类指令，无法处理后两类语音特有指令。这构成了一个内在矛盾：要保留文本 LLM 能力，就难以习得语音新技能；要学语音，就不可避免地破坏文本能力。

1.3 SpeechCombine 的核心思想

SpeechCombine 的回答简洁而优雅：不做指令微调，直接通过权重合并将文本 LLM 的指令跟随能力”移植”到语音模型上。

具体而言：

  1. 计算文本 LLM 的指令方向向量 $\Delta\theta_{\text{inst}} = \theta_{\text{instruct}} - \theta_{\text{base}}$
  2. 从基础模型出发，仅做一轮语音连续预训练得到 $\Delta\theta_{\text{speech}}$
  3. 最终模型：$\theta_{SC} = \theta_{\text{base}} + \Delta\theta_{\text{speech}} + \lambda \cdot \Delta\theta_{\text{inst}}$

这种做法的假设是：指令跟随能力编码为权重空间中的一个方向，该方向可以泛化到新模态。

二、方法详解

2.1 整体框架

如 Figure 2 所示，SpeechCombine 的推理流程为：

  1. 语音输入通过 Encoder（ASR + Prosody Tokenizer）转换为离散 token
  2. LLM 处理混合的文本/语音 token 序列
  3. LLM 输出的语音 token 通过 Decoder 还原为语音波形

本文仅训练 LLM 模块，Encoder 和 Decoder 使用开源预训练系统（基于 ProsodyLM）。

2.2 语音知识的定义与范围

论文将语音承载的信息分为三个层次：

  1. 内容（Content）：可转录为文本的部分
  2. 韵律（Prosody）：音高、语调、节奏、响度等
  3. 音色（Timbre）：说话人声音特征

本文聚焦前两个层次（内容 + 韵律），因为大多数语音相关指令都涉及韵律方面（如情感生成、重音检测等）。音色的扩展在框架内易于实现，留作未来工作。

2.3 预训练数据结构

预训练使用标准 next-token prediction 目标，关键设计在于数据结构。每个训练样本的格式为：

三个组成部分各有明确功能：

  • [speech]：语音 token 序列，让模型熟悉语音 token 的分布和结构
  • [cap]（caption）：自然语言描述语音的内容和韵律信息，让模型理解语音中的信息
  • [text]：语音对应的精确转录，作为文本能力迁移到语音的锚点

关键设计细节：

  1. [text] 必须与 [speech] 成对出现：这看似冗余，但消融实验证明它是指令跟随能力迁移的必要条件（去掉后 F1 从 60.84 降到 0.40）
  2. [cap] 的位置随机化：每个句子中，[cap] 以概率 $p_{\text{before}}$ 出现在 [speech] 之前（用于语音生成训练）或之后（用于语音理解训练）
  3. [cap] 的采样策略：从可用属性集中均匀采样一个属性；如果采到”text”则以 90% 概率丢弃；情感数据集保证采样情感属性

2.4 语音描述（Speech Caption）

Caption 描述语音中的内容和韵律信息，包含以下属性：

属性 提取方法 量化方式
平均音高等级 RMVPE 提取 F0 基于说话人和性别中位数划分 Low/Medium/High
平均语速 g2p_en 转音素计算每音素时间 基于中位数划分 Low/Medium/High
重音词 Whistress 模型提取 直接列出
情感唤醒度 whisper-large-v3-msp-podcast-emotion-dim 滑动窗口计算，划分 Low/Medium/High

音高分类的具体阈值：

  • Low：F0 < 0.75×说话人中位数 或 F0 < 0.85×性别中位数
  • High：F0 > 1.30×说话人中位数 或 F0 > 1.20×性别中位数
  • Medium：其他情况

采用 OR 融合策略：满足任一条件即判定。

2.5 韵律 Tokenization

论文采用 ProsodyLM（Qian et al., 2025）的韵律编码方案，仅编码韵律信息，因此比编码完整波形的方案产生更短的序列。

以 “How are you?” 为例，[speech] 格式如下：

每个词编码 5 个韵律属性：

  • Dur：词的持续时间（帧数）
  • f0_range：Log-F0 轮廓的 95% 与 5% 百分位差
  • f0_med：Log-F0 轮廓中位数
  • f0_slope：Log-F0 轮廓的最佳拟合直线斜率
  • energy：梅尔频谱图的 log-norm

所有属性量化为 512 级离散值，形成大小为 512 的韵律 token 词表。

2.7 推理格式与 Format Forcing

推理模板（基于 Qwen3-8B）：

模型从未在此格式上训练过，但能遵循它的原因是：$\Delta\theta_{\text{inst}}$ 已经认识大部分模板结构，[speech] 部分由 $\Delta\theta_{\text{speech}}$ 处理。

Format Forcing 机制：

  • 生成 [text] 时，mask 掉语音 token 词表，防止意外输出语音 token
  • 语音模式下，提升 <speech> 分隔符的生成概率，确保每段文本后产生语音段
  • 强制 <speech> 后立即输出 <spk_f0_med> token
  • 约束首个 token 为非语音 token

2.8 长思考（Long Thinking）

SpeechCombine 继承了 Qwen3 的 thinking 能力。实现细节：

  • 在 <think> 后追加 “Okay” 来增强长思考信号（否则模型可能不进入推理模式）
  • 思考过程中禁止生成韵律 token（静默思考）
  • 禁止 </think> 直到思考达到最小长度（160 token）

2.9 数据交错（Data Interleaving）

训练数据主要来自有声书（单一说话人、一致韵律），但推理场景是多轮对话。解决方案：将有声书切分为 5-7 个句子的小段，然后将不同有声书的片段拼接在一起，使模型感知说话人轮换。

三、实验配置

3.1 基础模型

  • Base model：Qwen3-8B-base
  • Instruct model：Qwen3-8B-instruct
  • LoRA 参数：rank=64, α=16

3.2 训练数据

预训练数据集共约 30k 小时：

  • Librilight（大规模有声书）
  • BEAT、CREMA-D、ESD、JL Corpus、EmoV-DB、Expresso、MEAD、TESS（情感/韵律语料）

使用 whisper-large-v3 提取文本转录，ProsodyLM 提取韵律 token。

3.3 基线对比

Group A（控制组，相同基础模型和数据量）：

  • ASR + TEXT LLM：Whisper 转文本 → Qwen3-8B-instruct（文本上界）
  • Continuous Pre-train：在 instruct 模型上继续预训练语音
  • Continuous Pre-train + SFT：在 base 模型上预训练 + 10k 小时指令数据微调

Group B（开放对比）：

  • GLM-4-Voice、Audio-Flamingo、Step-Audio2-Mini、Qwen-2.5-Omni、OSUM-EChat、Kimi-Audio、Fun-Audio-Chat、GPT-4o-Audio

4.4 消融实验

配置 OpenbookQA Acc.↑ Emph Det. F1↑ GenEmo Score↑
Original 86.59 60.84 45.42
No Thinking 64.83 53.14 36.37
No [cap] 84.83 0.39 27.18
No [text] 83.95 0.40 35.69
No Δθ_inst 71.68 40.38 15.34

核心结论：

  1. 去掉 [cap]：语音理解/生成能力几乎完全丧失（F1: 60.84→0.39），因为 caption 是模型学习语音信息语义的唯一途径
  2. 去掉 [text]：同样导致灾难性下降（F1: 60.84→0.40），证明文本锚点对能力迁移至关重要
  3. 去掉 Δθ_inst：文本能力下降，语音能力也下降，说明 in-context learning 无法完全替代指令方向
  4. 去掉 Long Thinking：所有任务一致性下降，确认长思考对未见任务有显著增益

4.5 λ 的影响

λ 控制指令方向的强度：

  • λ 增大 → 文本任务性能下降（对原始权重扰动增大），语音任务性能提升
  • 存在一个宽泛的 sweet spot（约 0.75-0.90）能在所有任务间取得平衡
  • λ=0.85 为最终选择

五、讨论与总结

5.1 核心贡献

  1. 提出 SpeechCombine：首个不经过指令微调即可跟随指令的语音大模型
  2. 验证权重合并假设：指令跟随能力编码为权重方向，可跨模态迁移
  3. 极简训练流程：仅需一轮 30k 小时预训练（无 SFT），在三类指令任务上全面达到 SOTA 水平
  4. 训练数据结构设计：[cap]/[text]/[speech] 三段式结构的必要性通过消融充分验证

5.2 局限性

  • 依赖外部 ASR 系统（whisper-large-v3）进行语音转录
  • 仅覆盖内容和韵律两个层次，未处理音色
  • Thinking 阶段的稳定性问题（无 format forcing 时易退化为无意义韵律 token）
  • 情感理解任务（UnderEmo）相对较弱，需要特定提示激活韵律推理

5.3 启示

SpeechCombine 揭示了一个深刻洞察：大模型的能力可以分解为独立的方向向量，这些方向在权重空间中具有跨模态的泛化性。这为构建多模态模型提供了一条全新路径——不再需要海量多模态指令数据，只需学会新模态的”语法”，然后直接移植已有能力。

这一发现对整个领域的训练范式提出了挑战：也许我们一直在用错误的方式训练多模态模型。
