Prompting Whisper for Joint Speech Transcription and Diarization

本文最后更新于 2026年5月12日 上午

论文速览

项目 内容
标题 Prompting Whisper for Joint Speech Transcription and Diarization
作者 Mariia Zamyrova, Henk van den Heuvel (Radboud University Nijmegen)
会议 Joint Workshop on HSCMA and CHiME 2026
链接 arXiv:2605.05231
状态 In-progress research

1. 问题背景与动机

在医疗场景中（MediSpeech 项目），需要一个能够实时对荷兰语医患对话进行转录 + 说话人分离（diarization）的系统。传统做法是将 ASR 和说话人分离作为两个独立的流水线串联——先做 ASR 得到文本，再用一个独立的说话人分离模块（如 pyannote）标注”谁在说话”。这种两阶段架构存在明显的延迟和错误累积问题。

Whisper 凭借其强大的多语言 ASR 能力成为首选，但它原生不支持说话人分离。现有的将 diarization 嵌入 Whisper 的方案存在两类局限：

  1. 计算开销大：部分方法（如 Target-Speaker ASR）需要为每个说话人单独处理音频，说话人越多，计算量线性增长。
  2. 长音频 speaker ID 不连续：基于 Serialized Output Training (SOT) 的方法在处理长音频分块（chunk）推理时，无法保证不同 chunk 之间 speaker ID 的一致性——chunk A 里的 Speaker 1 和 chunk B 里的 Speaker 1 可能根本不是同一个人。

本文提出了一个直觉性很强的思路：利用 Whisper 自身的 prompt 机制注入说话人标签，让模型在生成转录文本的同时插入 [S1]、[S2] 等标签，从而实现端到端的联合转录与分离。通过将历史 chunk 的带标签文本作为 context prompt 传递给后续 chunk，还能解决长音频中 speaker ID 不连续的问题。

2. 数据

2.1 Corpus Gesproken Nederlands (CGN) comp-A

实验使用了 CGN 数据集的 comp-A 部分，包含 925 段自发面对面对话录音（荷兰语），涵盖 231 位母语说话人。主要统计特征：

说话人数 训练集 验证集 测试集 测试子集
2 503 53 121 14
3 106 29 65 4
4 35 10 - -
5 3 - - -
总时长（小时） 99.5 12.5 27.0 2.8
平均时长（分钟） 6.9 6.6 7.3 8.5

数据集按 7:1:2 划分训练/验证/测试，测试集中的说话人与训练集和验证集无重叠。

值得注意的细节：

  • 重叠语音（overlapping speech）占每段音频时长的 5-10%，大多数重叠持续不到 1 秒，但也存在超过 3 秒的长重叠段。
  • 59.3% 的音频包含男女混合说话人。
  • 转录为正字法转录（orthographic transcription），保留了填充词、自我修正和截断词等语音特征。

2.2 数据预处理

为微调 Whisper，训练集和验证集中的 utterance 被合并为不超过 30 秒的 chunk，并进行以下处理：

  1. 过滤：移除包含不可辨识语音标注（”xxx”）或笑声标注（”ggg”）的 utterance。
  2. Speaker 标签注入：按说话人在音频中出现的顺序，将 CGN 的 speaker ID 映射为 [S1]、[S2] 等标签，在每个 utterance 开头和说话人切换处插入标签。
  3. 文本适配：对非句首或无标点结尾的 utterance，用 … 填充以模拟 Whisper 的标注风格；使用正则表达式进行首字母大写处理；移除元数据标注（如 *a 截断词标记）。
  4. 长度限制：prompt 和训练标签各限 224 token。

3. 方法

3.1 Prompt 设计：Task Prompt + Context Prompt

本文的核心设计在于 prompt 的构造方式。在 Whisper 的 prompt 机制中，prompt 文本会被放置在 decoder 输入的起始位置，用于引导模型的生成行为。

两部分 prompt 结构：

  • Task Prompt（任务提示）：固定的说话人标签热词 [S1] [S2] [S3] [S4] [S5]。无论音频中实际有几个说话人，始终提供全部 5 个标签，让模型自行推断需要使用哪些标签——这使模型不依赖于事先知道说话人数量。
  • Context Prompt（上下文提示）：前一个或多个 chunk 的带标签转录文本，例如：[S1] [S2] [S3] [S4] [S5] [S1] Uhm moeten langs uhm de Gamma gaan denk ik voor uh uh om die…。当 context 超过 224 token 限制时，从左侧截断（即保留最近的上下文）。

关键训练策略：

  • 每个音频文件的第一个 utterance 仅接收 task prompt（此时无历史上下文）。
  • 后续每个 utterance 同时接收 task prompt 和累积的 context prompt。
  • 强制 S1 起始：随机选择 20% 的 utterance，仅提供 task prompt（模拟”新音频开始”场景）。如果该 utterance 的参考文本不是以 [S1] 开头，则重新编号说话人标签，确保首个说话人始终为 [S1]。

3.2 微调策略

微调目标模块： 作者假设 decoder 的 cross-attention 模块对说话人标签的预测影响最大，因为它是文本信息与编码音频特征交互的核心节点。因此仅微调每个 decoder 层的 cross-attention 及其后的两个线性层。

LoRA 配置：

  • 使用 Low-Rank Adaptation (LoRA)，rank=16，alpha=16
  • 基座模型：Whisper large-v2
  • 训练：NVIDIA RTX A4000 单卡，约 3 个 epoch（2430 steps），batch size=4，gradient accumulation=4
  • 优化器：默认 AdamW，learning rate = $1 \times 10^{-5}$

一个重要的训练决策——不 mask prompt token： 标准做法通常会 mask 掉 prompt token，只计算生成部分的 loss。但本文故意不 mask，假设这样可以让 Whisper 学到 prompt 上下文与输出之间更强的语义关联。后续实验结果表明，这个决策可能正是模型更依赖文本上下文进行说话人标注的原因之一。

3.3 推理流程

推理时使用与训练相同的 prompt 方案，但 context prompt 来自模型自身的预测（而非参考文本）。这意味着任何预测错误都会通过 prompt 传递到后续 chunk——这是一个关键的潜在风险点。

推理使用量化版 Faster Whisper 实现。

4. 实验设置

4.1 评估指标

  • WER（Word Error Rate）：标准词错误率，衡量整体转录质量。
  • cpWER（Constrained Minimum-Permutation WER）：在说话人之间找到最优对齐后计算的词错误率，专门为多说话人场景设计。使用 MeetEval 库计算。
  • DER（Diarization Error Rate）：使用 pyannote-metrics 计算，collar 设为 250ms 以容忍时间戳偏差。

文本归一化包括：小写化、去标点、数字转写形式。

4.2 对比配置

配置 描述
(a) 基线未调优 Whisper large-v2
(b) 未调优 + 手工设计的 prompt（包含荷兰语对话示例，含说话人标签）
(c) 未调优 + 使用训练时相同的 prompt 方案
(d) 本文提出的 prompt-tuned 模型

5. 结果与分析

5.1 转录质量（WER）

配置 min WER ↓ 中位数 WER ↓ 75th 百分位 WER ↓
(a) 基线 21.2% 36.7% 40.7%
(b) 手工 prompt 21.2% 37.2% 41.5%
(c) 未调优 + 训练 prompt 20.2% 85.6% 94.5%
(d) Prompt-tuned 6.9% 31.7% 37.7%

关键发现：

  1. 微调显著提升了逐字转录能力：配置 (d) 的 WER 在所有分位上均优于基线 (a)，最小 WER 从 21.2% 降至 6.9%。
  2. 填充词识别率大幅提升：top 7 高频填充词（如 “uh”、”oh”、”m”）的识别命中率从 7% 跃升至 63%。这对医疗场景尤为重要——更好的逐字转录意味着对未见过的医学术语可能有更强的鲁棒性。
  3. 未调优模型无法适应训练 prompt 方案：配置 (c) 的 WER 急剧恶化（中位数 85.6%），说明直接使用 [S1] 格式的简化标签会严重干扰未经适配的 Whisper。但经过微调后 (d) 完全适应了该方案，表明 Whisper 可以通过 LoRA 低成本地适配任意 prompt 格式。

5.2 说话人标注质量

OOV 标签大幅减少： 未调优模型会生成大量超出词表的说话人标签，如 [Speaker 2 laughs] 或直接使用人名 [Judith]，OOV 标签超过 10 个（占所有标签的 2%）。微调后，OOV 标签降至仅 2 个（[Rudy] 和 [J]），仅占 0.02%。

5.3 联合评估（cpWER 与 DER）

核心数据：

  • 2 说话人音频：平均 cpWER = 55%，平均 DER = 46%
  • 3 说话人音频：平均 cpWER = 84.4%，平均 DER = 60.9%
  • cpWER 与 DER 之间存在强相关（$r = 0.76$）
  • WER 与 DER 之间存在中等相关（$r = 0.43$），说明降低 WER 有望间接降低 DER

5.4 错误传播与长音频退化

由于推理时 context prompt 来自模型自身的预测，任何说话人标注错误都会沿 chunk 链向下传播。从图 2 可以清晰看到：模型的中位 DER 在前 30 秒之后翻倍。这是当前方案最大的瓶颈。

5.5 3+ 说话人退化分析

3 说话人音频的性能显著劣于 2 说话人，原因有二：

  1. 训练数据不均衡：训练集中 3 说话人音频仅 106 个，4 说话人仅 35 个，5 说话人仅 3 个。
  2. 上下文稀释：第三个说话人通常出现时间占比很低（约 20%），其带标签文本容易被其他主导说话人的文本”挤出” 224 token 的 context prompt 窗口，导致后续 chunk 完全丢失对第三说话人的记忆。

5.6 重叠语音的时间戳问题

Whisper 基于 cross-attention score 估计的时间戳在重叠语音段上表现糟糕：

  • 短重叠段：重叠部分的词被错误地标注为顺序出现（sequential timestamping）
  • 长重叠段：Faster Whisper 的对齐器将整个重叠段中所有词分配相同的时间戳

这直接导致 DER 计算中的大量错误。

5.7 VAD 的作用

作者对比了有/无 VAD（Voice Activity Detection）的 DER，假设说话间的静音段可能有助于检测说话人切换。但双侧 Wilcoxon 检验结果 p=0.75，无显著差异。这进一步说明模型更多依赖文本上下文而非音频信号来判断说话人标签——训练时不 mask prompt token 的策略可能强化了这一行为。

6. 总结与展望

本文展示了一种优雅且低成本的思路：通过 Whisper 的 prompt 机制实现联合转录与说话人分离。主要贡献和局限：

✅ 贡献：

  • 利用 LoRA 微调 Whisper 的 cross-attention 模块，适配带说话人标签的 prompt 方案
  • 通过 context prompt 传递历史转录文本，实现长音频跨 chunk 的 speaker ID 一致性
  • 显著提升了逐字转录质量（WER 中位数 36.7% → 31.7%），填充词识别率从 7% 提升至 63%
  • OOV 说话人标签从 2% 降至 0.02%

⚠️ 局限：

  • DER 仍然偏高（2 说话人 46%，3 说话人 60.9%），距离实用仍有差距
  • 错误通过 prompt 链传播，长音频性能退化明显
  • 重叠语音的时间戳估计不准确
  • 3+ 说话人场景因训练数据不足和 context 窗口限制表现较差

未来方向：

  • 引入音频级别的 context（如 encoder prompting）以增强说话人区分鲁棒性
  • 改进重叠语音的时间戳对齐
  • 标准化文本拼写以降低正字法转录带来的 WER
