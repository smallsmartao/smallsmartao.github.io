StepAudio 2.5 Technical Report

核心问题：统一模型 vs 专用系统的性能鸿沟

语音系统正经历架构收敛——ASR、TTS、实时对话三条技术路线汇聚到同一个终点：将语音视为大语言模型框架内的另一种序列类型。然而，现有的统一音频-语言基座模型（如 Step-Audio 2、Qwen3-Omni）往往在某一两个方向表现不错，却在另一个方向落后于专用系统。

根本原因在于三个任务的优化目标天然冲突：

  • ASR 追求精准高效的长音频转录
  • TTS 追求可控、自然、富有表现力的语音合成
  • 实时对话 在低延迟约束下还需保持人设一致性和副语言响应能力

StepAudio 2.5 的核心论点是：一旦文本和音频共享了多模态表示空间，任务特化就不再是架构问题，而是”操作模式”的差异——即数据构造、优化目标和解码约束的组合。

统一基座架构

共享骨干

架构采用标准的 audio-encoder → adapter → LLM-decoder 模式：

  • 音频编码器（冻结）：将波形特征转为紧凑声学嵌入
  • 适配器：将声学嵌入映射到 LLM 的隐空间
  • 解码器：从文本 LLM 初始化的 MoE 大模型，在统一序列空间中同时处理文本 token 和音频 token

设计是有意非对称的：编码器负责稳定的声学抽象，解码器承载语义、上下文管理、指令遵循和生成。这种非对称性使得下游任务可以共享大部分模型参数。

任务特化即方向性推理

三种推理方向共享同一个多模态先验：

  • ASR：音频嵌入条件化解码器生成转录 token（输出空间窄、确定性高）
  • TTS：文本+控制指令条件化解码器生成音频 token（输出空间丰富，核心挑战是自然表达）
  • Realtime：在严格延迟约束下耦合音频理解和响应生成

核心洞察：基座模型不需要分离的”理解”和”生成”概念——只需要一个高质量的多模态先验加上将监督信号路由到不同输出空间的机制。

共享数据引擎与基座预训练

数据生产流水线

自动化流水线联合支撑语音理解、TTS 和语音对话：

  1. 声音事件检测（SED）+ 语音活动检测（VAD）过滤低质量段
  2. 相邻 VAD 段合并、重新切分为语义完整的基础样本
  3. 音频级标注：质量评分、合成语音检测、说话人计数
  4. 文本级标注：双 ASR 模型转录 + 语言识别，WER/编辑距离/语速交叉验证
  5. 按语言、时长、语义质量、音频质量分级

渐进式基座训练

从文本 MoE LLM 初始化，持续预训练 2.2T tokens：

阶段 数据量 序列长度 关键操作
对齐阶段 3B tokens ASR - 冻结编码器+LLM，仅训适配器
多模态 warmup 128B tokens 16K 适配器/embedding/output 高学习率，MoE router 低学习率
多模态主训练 800B 文本 + 800B 语音 16K 层学习率统一，MoE 辅助损失逐步退火
冷却阶段 600B 高质量数据 32K 引入 Audio Caption 和 Instruct TTS

语音数据覆盖：ASR、TTS、语音翻译、文本-语音交错续写、语音对话等多种输入输出配置。模型学到的不仅是文本和音频的原始关联，而是二者之间的操作接口。

ASR 分支：可验证多 Token 解码

MTP-5 架构

在标准 encoder-adapter-decoder 基础上增加 MTP-5 头：在解码位置 $t$，主分支预测下一个 token $x_{t+1}$，第 $h$ 个 MTP 分支预测 $x_{t+1+h}$（$h \in {1,…,5}$），一次前向产生 6-token 提议。

验证机制：提议仅作为已验证前缀被接受——一旦某个未来 token 与正常解码路径不一致，后续提议被拒绝，从已接受前缀继续自回归解码。MTP 严格作为加速原语，不影响最终转录质量。

每个 MTP block 接收前一分支的隐状态和移位 token embedding，归一化、拼接、投影回解码器隐维度，经 Transformer block 处理。所有分支共享 embedding 层和词表输出头。

训练流程

ASR SFT：32K token 序列预算，SpecAugment 数据增强，冻结编码器，优化适配器和解码器 10K 步，峰值学习率 $2 \times 10^{-5}$。

MTP 训练（两阶段）：

  1. 冻结分支对齐：5 个 MTP block 从最后一层解码器初始化 Transformer 层，仅优化 MTP block，学习率 $2 \times 10^{-4}$
  2. 联合校准：解冻适配器和解码器，低学习率 $2 \times 10^{-5}$ 联合优化

关键洞察：接地生成任务（grounded generation）比自由文本生成更适合投机解码加速，因为外部模态降低了语义分支的不确定性。

TTS 分支：纯 LLM 骨干的可控合成

架构特点

与 ASR/Realtime 不同，TTS 分支完全去掉了编码器-适配器模块，纯靠 LLM 骨干建模。音频 token 被当作一种新”语言”，语音合成被重新定义为纯 next-token prediction 任务。核心挑战变为学习文本和音频表示空间之间的有效对齐。

训练流程

SFT（两阶段）

  1. 全局指令控制：大规模零样本语音克隆训练，学习粗粒度控制（音色、风格、整体韵律）
  2. 全局+行内联合控制：使用带全局和行内指令标注的高质量数据，实现句内级别精细控制

强化学习（RLHF）

训练生成式奖励模型（GRM）$r_\phi$。对每个 prompt $x$，给定高质量参考响应 $y^$，策略模型 $\pi_\theta$ 生成候选 $y$，GRM 评估 $y$ 相对于 $y^$ 的配对偏好得分：

其中 $s(\cdot)$ 为奖励塑形变换。这使模型能处理复杂、抽象、高上下文依赖的指令，同时提升自然度和表现力。

SFT 数据构建

两类数据源：

  1. 模型合成数据（全局指令控制）：使用 Step-Audio-EditX 模型生成大规模多样风格/情感变化的语音数据
  2. 录制语音数据（全局+行内控制）：遵循 Emotional-Context-Speech 标注流水线
    • Whisper-Large-v3 转录 → Montreal Forced Aligner 获取词级时间戳 → 切分为句级样本
    • 提取并离散化韵律特征：F0、语速、停顿统计、频谱质心、RMS 能量、MFCC 方差、HNR
    • LLM 标注生成两种输出：(a) 全局控制描述（整体风格/韵律/情感）；(b) 行内表达描述（局部指令标记）
    • ASR 交叉验证，丢弃转录不匹配的段

评测

采用 Arena 式配对评估，与 MiniMax-2.8-HD、ElevenLabs-v3、Gemini-3.1-Flash-TTS 对比，使用 774 条 prompts。

StepAudio 2.5 TTS 总体胜率 67.6%，在所有配对比较中均取得一致优势。

Realtime 分支：低延迟人设一致对话

核心挑战

  • 对话连贯性：跨多轮维持话题上下文和风格一致性
  • 人设一致性：面对多样甚至对抗性输入仍保持特定人格特征
  • 副语言敏感性：理解并恰当回应犹豫、笑声、叹息、节奏变化等非语言线索
  • 奖励稀疏性：对话属性（自然度、情感适配）缺乏单一真值目标

训练流程

1. 音频中心中训练

继承自基座模型，赋予模型稳健的音频感知和长链推理能力。

2. 渐进式 SFT（三维度递进）

  • 对话对齐：使用指令丰富的对话数据校准多轮交互，处理口语不流畅、中途打断，偏好口语化表达
  • 人设与风格控制：从 10,000+ 原生人设出发，通过属性正交分裂（性格、口头禅、情感边界、交互原型）扩展为百万级人设矩阵，配对百万级真实场景对话
  • 副语言敏感性：使用带氛围描述符和线索标签（犹豫、轻笑、叹息、呼吸、节奏变化、降调）的真实对话训练

动态排练机制：交互数据与通用指令/推理任务按验证指标动态交错，防止灾难性遗忘。

3. RLHF（生成式奖励模型）

PPO + KL 正则化。生成式奖励模型基于显式交互评分维度（rubrics）评估候选响应：

  • 多轮对话数据鼓励跨轮一致性
  • 单轮 prompts 提供更长推理和偏好表达空间
  • 配对偏好比较作为主奖励信号
  • Rubric 得分补充指令敏感维度（如跨轮连贯、忠实用户内容）

数据

三类互补数据流：

  1. 对话骨干：自然口语多轮对话，偏好轮间连续性、省略/不流畅表达，弱化书面风格
  2. 人设条件化对话：10,000 原生人设 → 属性正交分裂 → 百万级人设矩阵 × 百万级真实场景
  3. 副语言线索对话：带氛围描述符和线索标签的对话

全部通过统一流水线检查人设一致性、交叉验证标注、去重。

总结

StepAudio 2.5 证明了一个关键路线：统一音频-语言基座已经可以在 ASR、TTS、实时对话三个方向同时超越专用系统。技术杠杆不在架构创新，而在 post-training 的系统工程——以 RLHF 为核心分化机制，配合任务特化的解码策略（MTP 加速 ASR、纯 NTP 做 TTS、生成式奖励模型驱动实时对话），将同一个共享骨干塑造为三种截然不同的操作模式。

对从业者的启示：

  1. 接地生成任务天然适合投机解码——外部模态降低语义不确定性
  2. RLHF 不只是对齐工具，更是任务分化工具——相同底座通过不同偏好信号分化出不同能力
  3. 数据工程的分阶段设计（对齐→warmup→主训练→冷却）比简单堆量更有效
