Streaming SpeechLLMs: From BESTOW's Fixed Wait-k to MoCha-ASR's Adaptive Latency Optimization

本文最后更新于 2026年10月14日 凌晨

把 decoder-only 大语言模型接入语音识别并不困难：用语音编码器产生连续特征，将其映射为 LLM 可以读取的表示，再让 LLM 自回归生成转写即可。真正困难的是流式化。标准 decoder-only SpeechLLM 通常要求完整语音位于文本之前；而流式系统必须在音频仍持续到达时决定两个问题：当前信息是否足以输出下一个 token，以及输出后应当读取多少新语音。

本文联合解读两项沿着同一问题连续推进的工作：

  • BESTOW: Efficient and Streamable Speech Language Model with the Best of Two Worlds in GPT and T5（NVIDIA，arXiv:2406.19954，2024）：将语音—文本融合从 LLM 主干中解耦为输入侧 cross-attention，并以固定 wait-$k$ 策略实现统一的离线/流式、多任务 SpeechLLM。
  • Streaming Speech Recognition with Decoder-Only Large Language Models and Latency Optimization（中国科学技术大学、科大讯飞、陕西师范大学，arXiv:2601.22779，2026；下文简称 MoCha-ASR）：用基于 MoChA 的策略网络学习 token 级语音边界，以自适应 READ/WRITE 替代固定 wait-$k$，并通过最小延迟训练直接压缩输出滞后。

两篇论文并不是两个互不相关的结构。BESTOW 首先证明：只要把“读多少语音”从 LLM 中分离出来，decoder-only LLM 就可以流式工作；MoCha-ASR 随后追问：既然 READ/WRITE 已经是独立决策，为什么仍由人工固定，而不能由模型根据每个 token 的声学证据自适应决定？

论文地址：BESTOW；MoCha-ASR

1. 统一问题：decoder-only SpeechLLM 为什么难以流式化

1.1 离线 SpeechLLM 的因果顺序与在线输入冲突

设语音编码器将输入 $X$ 转换为连续表示 $h_{1:N}$，目标文本为 $Y=(y_1,\ldots,y_L)$。典型 GPT-style SpeechLLM 把全部语音表示置于文本 token 之前：

\[[h_1,\ldots,h_N,y_1,\ldots,y_{L-1}],\]

并建模

\[P(Y\mid X)=\prod_{i=2}^{L}P(y_i\mid h_{1:N},y_{1:i-1};\theta_{\mathrm{LLM}}).\]

这种排列适合离线识别，但在 $y_2$ 生成之前便要求 $h_{1:N}$ 全部存在。若简单把不断到达的语音块插入已生成文本之间，输入格式便从 LLM 预训练时的连续文本序列变成“语音块—文本—语音块—文本”，甚至还要引入 WAIT、BLANK 等控制 token。结果是：

  1. 离线与流式 prompt 格式不一致，削弱预训练 LLM 的知识迁移；
  2. 每次追加语音都可能改变长前缀，KV cache 难以直接复用；
  3. 固定音频块忽略不同 token 所需声学上下文的差异；
  4. 如果依赖外部 CTC 或混合系统预先对齐，训练链路不再完全由目标任务端到端决定。

1.2 流式 SpeechLLM 本质上是 READ/WRITE 策略

在任一输出步骤 $i$，系统只有两类操作：

  • READ：暂不输出，继续接收语音；
  • WRITE：利用当前已读语音与历史文本生成 $y_i$。

因此，关键变量不是“是否使用 LLM”，而是每个 token 的读取边界 $t_i$：

\[0=t_1\le t_2\le\cdots\le t_L\le N.\]

一旦 $t_i$ 确定，流式识别可写为

\[P(Y\mid X)=\prod_{i=2}^{L}P\!\left(y_i\mid h_{1:t_i},y_{1:i-1}\right).\]

BESTOW 与 MoCha-ASR 的分歧正发生在这里：BESTOW 用人工定义的固定速率产生 $t_i$；MoCha-ASR 用单独的单调注意力策略网络学习 $t_i$。

2. BESTOW：先把语音读取从 LLM 主干中解耦

2.1 为什么 GPT-style 与 T5-style 都不理想

BESTOW 将已有 SpeechLLM 分为两类。

GPT-style / Speech-LLaMA-style 把语音 prompt 与文本 prompt 直接拼接，再送入 decoder-only LLM。设文本长度为 $L_t$、语音特征长度为 $L_a$，LLM self-attention 的复杂度为

\[O\!\left((L_t+L_a)^2\right) =O\!\left(L_t^2+L_a^2+2L_tL_a\right).\]

由于 $L_a\gg L_t$，主要成本来自每一层 LLM 对长语音序列反复进行 self-attention。大幅下采样虽可减轻成本，却可能损失语音细节。

T5-style / Flamingo-style 在 LLM 的多个层中加入 speech cross-attention。语音信息可以深入访问每层隐状态，但附加参数与计算随 LLM 深度增长，也更难保持主干完全模块化。

BESTOW 的目标是保留两者优势：像 GPT-style 一样不改造每个 LLM block，又像 T5-style 一样通过 cross-attention 访问语音。

2.2 输入侧 cross-attention：文本作为 Query，语音作为 Key/Value

BESTOW 不把语音序列送入 LLM self-attention，而是在 LLM 输入之前放置一个小型 Transformer-like 特征提取器：

  1. 语音编码器输出 $A=(a_1,\ldots,a_{L_a})$，作为 cross-attention 的 Key 与 Value；
  2. 文本 prompt 与历史输出 token 经 LLM 原始 embedding 得到 $E=(e_1,\ldots,e_{L_t})$；
  3. 因果 self-attention 先让当前文本 query 汇总历史文本；
  4. cross-attention 再以该文本状态为 Query，从语音特征中提取当前步骤相关的信息；
  5. cross-attention 输出与原始文本 embedding 残差相加，再送入未改变的 decoder-only LLM。

可概括为

\[Q=\operatorname{CausalSelfAttn}(E),\]\[C=\operatorname{CrossAttn}(Q,A,A),\]\[Z=E+C,\]

其中 $Z$ 是 LLM 真正接收的输入表示。残差路径使模型在不需要语音时可以忽略 $C$，退化为原始文本 LLM；语音相关模块则集中在输入侧，便于冻结 LLM 或使用 LoRA。

论文最终使用两层“causal self-attention + cross-attention”。这里的 self-attention 不是多余组件：它让当前 query 包含历史 token，否则 cross-attention 只能按孤立 token 查询语音。

2.2.1 复杂度为何下降

BESTOW 的主要注意力成本变为

\[O(L_t^2+L_tL_a),\]

消除了发生在深层 LLM 中的 $L_a^2$ 项。论文将其描述为在 $L_a\gg L_t$ 时理论收益随语音长度增长。严格地说，实际端到端加速还受语音编码器、cross-attention、KV cache 与硬件利用率影响，不能直接把复杂度比值等同于墙钟加速；实验测得的收益是训练速度从 0.50 提高到 0.59–0.60 step/s，而不是数量级提升。

2.3 从离线到流式：固定 wait-$k$ 策略

有了独立 cross-attention 后，LLM 每一步能看到多少语音不再由 LLM 输入长度决定，而由 cross-attention 的可见范围决定。BESTOW 采用固定策略：

  • $P$：语音编码器下采样率；
  • $L$：每次决策新增的编码器步数；
  • 单次 READ 对应 $L\times P\times10\text{ ms}$；
  • $K$：首次 WRITE 前等待的决策块数。

模型先读取 $K L$ 个语音 embedding，再生成第一个 subword；此后每新增 $L$ 个 embedding 生成一个 subword。若第 $i$ 个输出从 1 开始计，则其可见语音长度近似为

\[g(i)=\min\bigl(KL+(i-1)L,\,L_a\bigr).\]

这是一条固定斜率的读取轨迹。它的优点是简单、稳定、无需 token 级对齐；缺点是所有 token 按相同节奏前进，无法根据音节时长、停顿、语言顺序差异或语义歧义调整边界。

训练时 $K$ 从一定范围随机采样，使同一模型在推理时可以改变 $K$，以延迟换质量。论文默认 $L=4$、$P=8$；ASR 使用 $K=6$，其余任务使用 $K=10$，训练时在 $[3,12]$ 采样 $K$。

2.4 两种流式语音编码器

仅限制 cross-attention 可见范围还不够；若语音编码器本身读取未来帧，系统仍不是真正的低延迟模型。BESTOW 给出两条路径。

2.4.1 BESTOW-S-bidi

保留双向编码器，每到一个新语音块便重新计算当前所有可用状态，并在推理时保留固定 13 帧右上下文以缓解训练/推理失配。其识别与翻译质量更高，但重复计算未计入论文主要 LAAL 指标，因此“算法滞后较低”不等于“计算感知延迟同样低”。

2.4.2 BESTOW-S-unid

将 FastConformer 改为 cache-aware 单向流式编码器，因果卷积可选择上下文配置

\[[[70,13],[70,6],[70,1],[70,0]].\]

该版本可以缓存历史状态，在线计算更符合真实部署，但整体质量低于双向重算版本。论文先在 LibriLight 上用 wav2vec 2.0 目标预训练 cache-aware 编码器，再从离线 BESTOW 初始化流式模型并继续训练。

3. BESTOW 实验：效率、流式能力与多任务规模

3.1 数据、模型与优化

训练数据由 31K 小时公开语音、54K 小时内部 ASR/AST 数据以及约 2K 小时合成 MSMARCO SpeechQA 和 DynamicSuperb 数据组成，总计约 87K 小时。四种主要语言的 ASR/AST 数据分别为英语 67.4K、德语 6.1K、西班牙语 6.6K、法语 5.1K 小时。

模型配置为：

  • 语音编码器：Canary-1B 初始化；
  • LLM：TinyLlama-1.1B-chat；
  • 融合模块：2 层 cross-attention Transformer；
  • 总参数量：约 1.8B，默认全参数训练；
  • 训练：128 张 A100 80GB、60K step、约一天；每卡 batch duration 360 秒；
  • 优化：Distributed Fused Adam，学习率 $10^{-4}$，权重衰减 $10^{-3}$，梯度裁剪 1.0。

论文同时评估 ASR、语音翻译（AST）、SpeechQA（SQA）和未见过的 DynamicSuperb 任务；流式延迟使用 non-computation-aware LAAL。这一限定非常重要：它衡量输出相对输入的算法滞后，不包含双向重算与硬件执行时间。

3.5 延迟—质量曲线

通过推理时改变 $K$，BESTOW 可以沿固定读取轨迹平移首个输出时刻，形成连续的延迟—质量折中。它解决了“同一模型如何切换延迟档位”，但没有解决“同一句话中不同 token 应等待多久”。这正是 MoCha-ASR 的起点。

4. MoCha-ASR：从固定节奏转向 token 级自适应边界

4.1 非流式基线：连续语音 soft prompt

MoCha-ASR 首先建立标准非流式模型：Conformer 将 $X$ 编码为声学表示，前馈 adaptor 将其投影到 LLM 词嵌入空间，形成 $h_{1:N}$；decoder-only LLM 再按

\[P(Y\mid X)=\prod_{i=2}^{L}P(y_i\mid h_{1:N},y_{1:i-1};\theta_{\mathrm{LLM}})\]

生成文本。$y_1$ 和 $y_L$ 分别为 BOS 与 EOS。训练只在文本位置计算交叉熵，语音 prompt 位置被 mask；LLM 通过 LoRA 适配。

4.2 流式声学编码：只有历史上下文的 context-sensitive chunking

输入语音被切成固定 chunk，每个 chunk 附加历史上下文，不使用未来上下文。训练时各 chunk 可并行送入 Conformer；随后丢弃上下文帧对应输出，把有效区域重新拼接为 utterance-level 表示。实验设置为：

  • chunk：0.4 秒；
  • 左上下文：1.6 秒；
  • 未来上下文：0；
  • 因此算法上的新增编码等待由当前 0.4 秒 chunk 决定，而不会额外偷看未来帧。

这一步只保证声学编码可在线执行，尚未决定何时让 LLM输出。

4.3 MoChA 策略网络：学习每个 token 的读取终点

策略网络由轻量 decoder 与 Monotonic Chunkwise Attention（MoChA）构成。输出步骤 $i$ 从上次边界 $t_{i-1}$ 开始顺序扫描编码帧，对每个位置 $j$ 计算选择概率

\[p_{i,j}=\sigma\!\left(e_{i,j}\right),\]

其中 $e_{i,j}$ 由 decoder 状态与第 $j$ 帧声学表示共同决定。当 $p_{i,j}$ 超过阈值时，触发 WRITE，并令

\[t_i=j.\]

普通 hard monotonic attention 只选单帧；MoChA 在该硬边界附近再执行局部 soft chunkwise attention，使策略 decoder 可以汇聚一个小窗口，而非把 token 判断压在单帧上。最终得到与 $[y_2,\ldots,y_L]$ 同步的边界序列 $[t_1,\ldots,t_L]$，其中 $t_1=0$。

直观上，token $y_i$ 只在收到新语音段

\[h_{t_{i-1}+1:t_i}\]

后生成。不同 token 的段长可以不同：短音节、清晰词可较早触发；歧义或长音节可以继续 READ。

4.4 把语音段与文本历史交错输入 LLM

根据策略网络边界，训练序列被重排为

\[H_y= [h_{t_1+1:t_2},y_1, h_{t_2+1:t_3},y_2, \ldots, h_{t_{L-1}+1:t_L},y_{L-1}].\]

于是 LLM 的条件概率为

\[P(Y\mid X)=\prod_{i=2}^{L} P\!\left( y_i\mid h_{t_1+1:t_2},y_1,\ldots, h_{t_{i-1}+1:t_i},y_{i-1}; \theta_{\mathrm{LLM}} \right).\]

$L_{\mathrm{LLM}}$ 只在每个语音段最后一个位置计算，用于预测紧随其后的 token。这样既保留 decoder-only LLM 的因果计算，又让每次追加的声学信息恰好位于需要它的文本 token 之前。

这里与 BESTOW 有结构性差异：BESTOW 保持纯文本 prompt 格式，由 cross-attention mask 控制可见语音；MoCha-ASR 显式构造“新语音段—历史 token”的交错序列。前者更利于统一多任务 prompt，后者更直接地把自适应边界落实为 decoder-only 输入。

4.5 三部分训练目标

4.5.1 LLM token 损失

\[L_{\mathrm{LLM}} =-\sum_{i=2}^{L}\log P(y_i\mid H_{y,<i}).\]

它联合更新语音编码器、adaptor、策略网络所影响的边界以及 LLM LoRA 参数。

4.5.2 策略 decoder 损失

MoChA 内部的小 decoder 使用与 LLM 相同的词表，并以交叉熵 $L_{\mathrm{MoChA}}$ 学习目标 token。它的输出仅用于训练策略网络；推理时真正的文字输出仍来自 LLM，因此不会额外融合两个 decoder 的分数。

4.5.3 最小延迟训练（minLT）

仅依赖识别交叉熵时，策略只要在足够晚的位置触发也能得到正确 token，缺乏主动提前的压力。作者用 HMM 混合 ASR 系统生成 token 边界 $b_i$，并对 MoChA 的边缘对齐概率 $\alpha_{i,j}$ 施加

\[L_{\mathrm{minLT}} =\frac{1}{L}\sum_{i=2}^{L}\sum_{j=1}^{N} \left|j\alpha_{i,j}-b_i\right|.\]

总目标为

\[L_{\mathrm{total}} =L_{\mathrm{LLM}}+L_{\mathrm{MoChA}}+\lambda L_{\mathrm{minLT}},\]

实验中 $\lambda=0.1$。这里保留的是论文正式版本印出的双重求和形式 $\sum_j|j\alpha_{i,j}-b_i|$；常见的“期望边界误差”写法则会把绝对值放在 $\sum_jj\alpha_{i,j}$ 之后。论文文字称其为 expected latency objective，但没有解释这两种形式的差别，复现时不能在不说明的情况下互换。

这形成一个需要准确表述的边界：主识别路径与边界策略可以联合训练，但 minLT 的监督仍来自外部 HMM 强制对齐。 因而 MoCha-ASR 避免了推理期级联对齐，也允许联合优化；它并非在所有训练信号上都摆脱外部对齐器。

4.6 流式与非流式联合训练

两种模式共享语音编码器、adaptor、LLM 及其 LoRA 参数，只在 forward 路径上不同。每个 batch 随机选择流式或非流式模式：

  • 非流式路径使用完整 $h_{1:N}$；
  • 流式路径使用 MoChA 产生的分段交错序列。

这不是两个模型之间的知识蒸馏，而是参数完全共享的多路径训练。目标是用一套权重同时支持两种运行模式，减少训练和维护成本。

4.7 在线推理循环

推理时重复以下过程：

  1. context-sensitive chunk encoder 接收新语音并产生增量表示；
  2. 策略网络从上个边界继续扫描；
  3. 未触发则继续 READ；
  4. 触发后，将缓冲的新语音段与上一 token 输入 LLM；
  5. LLM 生成下一 token；
  6. 该 token 同时反馈给 LLM 历史与 MoChA decoder；
  7. 直到 LLM 输出 EOS。

因此策略 decoder 决定“何时写”，LLM 决定“写什么”。模块职责是明确分离的。

5. MoCha-ASR 实验：识别率与 token 级延迟

5.1 数据与模型配置

论文使用三个普通话数据集：

  • AISHELL-1：165 小时，训练/开发/测试约 120K/14K/7K 条；
  • AISHELL-2：1000 小时，开发 2500 条、测试 5000 条；
  • 内部多领域 MD：约 1 小时，仅测试，覆盖金融、教育、影视等领域。

模型为 12 层 Conformer（8 头、hidden 512、FFN 2048），adaptor hidden 1024、GELU；LLM 为 Qwen2.5-1.5B（28 层、12 头、hidden 1536），保留原 tokenizer 与词表。LoRA 注入 attention 的 Q/K/V/O 投影，rank 32，$\alpha=64$。优化器为 AdamW，三角循环学习率在 0 与 $1.5\times10^{-4}$ 之间变化，每 25K step 一个周期，总计 100K step；测试 beam size 为 10。

5.3 minLT 将平均 token 延迟从 640 ms 降到 240 ms

论文使用强制对齐边界衡量首 token、中间 token、末 token 和全序列平均延迟。每帧为 40 ms。

方法 CER↓ First（帧） Mid（帧） Last（帧） Avg（帧）
Baseline-stream 6.1 19 15 7 15
MoCha-ASR，无 minLT 5.4 18 15 9 16
MoCha-ASR + minLT 5.5 10 5 2 6

换算为时间：

  • 平均：$16\times40=640$ ms → $6\times40=240$ ms，下降 62.5%；
  • 首 token：720 ms → 400 ms；
  • 中间 token：600 ms → 200 ms；
  • 末 token：360 ms → 80 ms；
  • CER 只从 5.4% 增至 5.5%。

这组结果还揭示了一个反直觉现象：没有 minLT 时，MoCha-ASR 虽然比 encoder–decoder 流式基线更准，却并不更快，平均延迟甚至从 15 帧升到 16 帧。可学习边界本身不会自动产生低延迟；必须在目标函数中显式赋予“尽早输出”价值。

5.4 联合训练、LoRA 与预训练初始化消融

设置 非流式 CER↓ 流式 CER↓
完整 MoCha-ASR 5.0 5.5
不联合训练 5.1 5.6

联合训练只带来 0.1 CER，但其意义在工程统一，而不是显著精度增益。冻结 LLM 而不使用 LoRA 造成 0.2–0.4 CER 损失；随机初始化 LLM 则造成 1.5–1.7 CER 损失，说明提升并非只来自一个拥有 1.5B 参数的随机 decoder，预训练语言知识确实参与了识别。

二者的演进关系可以概括为三步：

  1. 结构解耦：BESTOW 把语音访问放到 LLM 外部的小型 cross-attention 中，证明 LLM 不必直接吞下整段语音序列；
  2. 策略显式化：一旦语音访问独立，流式就可以被写成 READ/WRITE；BESTOW 用固定 wait-$k$ 建立可运行基线；
  3. 策略学习化：MoCha-ASR 用单调策略网络取代固定节奏，并加入边界监督，让准确率与延迟进入同一个优化目标。

但这不是简单的“新论文全面替代旧论文”。MoCha-ASR 在自适应延迟上更进一步，却没有复现 BESTOW 的多任务覆盖、输入侧复杂度优势和纯文本 prompt 兼容性；BESTOW 的固定策略不够灵活，却无需 HMM token 对齐，也更容易扩展到 AST、SQA 等不存在单调逐词对齐的任务。

7. 尚未解决的问题

7.1 两篇论文使用不同延迟定义

BESTOW 报告 non-computation-aware LAAL，描述输出相对输入的平均滞后；MoCha-ASR 报告输出 token 相对强制对齐边界晚了多少帧。它们不能直接用“3 秒对 240 毫秒”比较：一个是序列级 lagging，另一个是 token 边界偏移，参考原点与聚合方式不同。

更完整的流式评测至少应同时报告：

  • 首 token 延迟（TTFT）；
  • token 平均与尾部延迟；
  • computation-aware LAAL；
  • 实时因子（RTF）；
  • 峰值显存和缓存规模；
  • 不同设备与 batch size 下的墙钟延迟。

7.2 自适应策略仍依赖外部边界

MoCha-ASR 的识别主路径不需要推理期强制对齐，但最有效的 minLT 来自 HMM 边界。若目标语言缺乏可靠混合系统，或任务是语音翻译、问答等非单调映射，$b_i$ 并不容易定义。未来需要无监督、弱监督或风险最小化式延迟目标。

7.3 固定策略更通用，自适应策略更精细

BESTOW 的 wait-$k$ 不理解内容，但可以直接用于 ASR、AST 与 SQA；MoChA 假设输入与输出大体单调，非常适合 ASR，却难以直接处理需要重排序的翻译或必须听完整问题的 SQA。一个自然方向是：在 BESTOW 的高效 cross-attention 骨干上，引入可针对任务切换的策略——ASR 用单调边界，AST 用可延迟重排的策略，SQA 用语义完备度判断。

7.4 双向重算与单向缓存之间仍有质量差距

BESTOW-S-bidi 质量优于单向版，但 computation-aware 成本更高；MoCha-ASR 避免未来上下文，却使用 0.4 秒 chunk 和 1.6 秒历史窗口。真正部署时还要考察 chunk 调度、encoder cache、LLM KV cache、beam search 以及网络抖动的共同影响。

7.5 关键复现参数仍不完整

MoCha-ASR 没有报告 MoChA 触发阈值、soft chunk window、策略 decoder 的层数与维度，也未说明长时间不触发时的 fallback/endpointer；这些参数都会直接改变 CER 与延迟。BESTOW 则没有完整给出输入侧 Transformer 的 attention head、归一化顺序等实现细节。两篇论文都公布了主结构和主要训练设置，但还不足以仅凭正文无歧义复现全部结果。

8. 结论

BESTOW 与 MoCha-ASR 共同说明，流式 decoder-only SpeechLLM 的核心不是把音频切成块，而是把语音读取权从 LLM 的静态前缀中释放出来。

BESTOW 完成第一步：以输入侧 cross-attention 隔离语音与 LLM 主干，将复杂度从包含 $L_a^2$ 的长序列 self-attention 降为 $L_tL_a+L_t^2$，并用 wait-$k$ 在统一骨干上支持离线、流式和多任务。MoCha-ASR 完成第二步：用 MoChA 策略网络学习每个 token 的读取边界，再以 minLT 把平均 token 延迟从 640 ms 压到 240 ms，同时只增加 0.1 CER。

从研究路径看，下一代系统最值得组合的不是两篇论文的表面模块，而是各自最强的约束：BESTOW 的高效、prompt 兼容、多任务 cross-attention骨干，加上 MoCha-ASR 的内容自适应策略与显式延迟优化。只有同时建模“读什么”“读到何时”和“计算是否来得及”，流式 SpeechLLM 才会从可演示的算法变成可部署的实时系统。
